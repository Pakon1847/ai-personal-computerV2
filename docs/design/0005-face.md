- **สถานะ:** อนุมัติ 2026-09-24 (Pakon) · กำลังสร้าง · Pakon ส่งข้อกำหนดระบบสแกนใบหน้า 2026-09-24 แล้วให้ผู้ช่วยตัดสินว่าอะไรควร/ไม่ควร
- **เสร็จแล้ว:** แกน (config, quality gate, align, จับคู่ 1:N) · โหลดโมเดล + sha256 · pipeline สแกน/ลงทะเบียน/log · evaluate.py · ผลชั้นที่ 1 บน LFW: EER 0.36% ([ผล](../benchmarks/2026-09-24-face-lfw/README.md)) · MiniFASNet ผ่าน OpenCV ได้ (ไม่ต้องใช้ onnxruntime)
- **ยังเหลือ:** ทดสอบบน Pi 4 (เวลา/RAM) · ต่อกล้องจริง + วงกล้องในหน้า Login · ที่เก็บแม่แบบ · ประเมินชั้นที่ 2 กับคนจริง (ต้องมีหนังสือยินยอม) · APCER
- **ข้อกำหนดที่อ้าง:** BRIEF 5.1 ข้อ 5–9, หัวข้อใบหน้า (แม่แบบ, 1:N + margin, PAD สองระดับ, ไลเซนส์) · ตารางเกณฑ์ใบหน้าใน BRIEF · ROADMAP 0.8 · ADR-002 (RGB/NIR) · ADR-003/004 (ที่เก็บ) · ADR-008 (IPC) · ADR-014 (ใช้ในงานศึกษา) · THREAT_MODEL

## 1. ปัญหาที่แก้ และใครใช้

วงกล้องในหน้า Login ตอนนี้บอก "ระบบจดจำใบหน้ายังไม่พร้อม" · ผู้ใช้ทุกคนที่ลงทะเบียนใบหน้าจะใช้ระบุบัญชีที่หน้า Login
โดยไม่ต้องพิมพ์ชื่อ (รหัสผ่านยังเป็นกุญแจ) · และเล่มปริญญานิพนธ์ต้องการตัวเลข FAR/FRR/EER/เวลา ที่วัดได้จริง

## 3. ทางเลือก

| ทางเลือก | ข้อดี | ข้อเสีย |
|---|---|---|
| ก. SCRFD/RetinaFace + ArcFace (InsightFace) ผ่าน onnxruntime + FastAPI + SQLite/Fernet (ตามข้อกำหนดที่ส่งมา) | แม่นยำสูงบนชุดข้อมูลมาตรฐาน | โมเดล InsightFace "non-commercial research purposes only" · ArcFace ResNet หนักสำหรับ Pi (ยังไม่ได้วัด) · FastAPI เปิดพอร์ต + RAM เพิ่ม (ขัด BRIEF 5.2) · กุญแจ Fernet อยู่ข้างข้อมูล = ป้องกันน้อย |
| **ข. YuNet + SFace + MiniFASNet ผ่าน OpenCV (เลือก)** | ตรงกับที่ BRIEF เลือกไว้แล้ว · ไลเซนส์ MIT/Apache-2.0 · ทำมาสำหรับอุปกรณ์เล็ก · dependency เดียว · YuNet ให้ 5 จุดสำหรับ align ในตัว | แม่นยำน้อยกว่า ArcFace ขนาดใหญ่ (ต้องวัดกับข้อมูลของเรา) · MiniFASNet บนกล้อง RGB กันได้แค่การโจมตีง่าย |
| ค. ใช้ InsightFace เฉพาะตอนประเมินเพื่อเทียบ | ได้ตัวเลขเทียบในเล่ม | ใช้เวลาเพิ่ม · ทำภายหลังถ้ามีเวลา (ข้อ 10) |

**ส่วนของข้อกำหนดที่ส่งมาที่ไม่ทำ และเหตุผล**
- อัปเดตแม่แบบอัตโนมัติเมื่อ similarity สูง → ขัด BRIEF 5.1 ข้อ 6 และเปิดทางค่อย ๆ ป้อนหน้าคนอื่น (template poisoning) · ทำแทนได้เฉพาะ "ปรับแม่แบบในเซสชันที่ยืนยันรหัสผ่านแล้ว" (ข้อ 10)
- FastAPI + หน้าเว็บ → ใช้หน้าจอ QML ที่มี (วงกล้องใน Login, หน้าตั้งค่า) คุยผ่าน Unix socket (ADR-008)
- SQLite + Fernet → ที่เก็บตาม ADR-003/004 · ระหว่างรอใช้ไฟล์ของผู้ใช้แบบเดียวกับนัดหมาย (atomic + .bak)
- เป้า < 300 ms ต่อการสแกน → ใช้เกณฑ์ BRIEF (ทั้งกระบวนการ median ≤ 1.5 วิ, p95 ≤ 3 วิ) · log เวลาต่อขั้นตามข้อกำหนดเดิม

## 4. ความสัมพันธ์กับชิ้นส่วนอื่น

- **พึ่ง:** OpenCV (`opencv-python-headless`, มีบน Pi ผ่าน pip) · ไฟล์โมเดล 3 ตัว (ดาวน์โหลด + ตรวจ sha256) · กล้อง (มีกล้อง USB บน Pi 4 แล้ว)
- **มีคนพึ่ง:** หน้า Login (ระบุบัญชี 1:N) · ปิดบัง/ล็อก (ตรวจ 1:1 กับเจ้าของ, เฟส 2) · การสมัคร (ขั้นลงทะเบียนใบหน้า) · Privacy Center (ลบแม่แบบ)
- **ชั้น:** แกนเป็น Python ล้วนใน `aipc.vision` (ย้ายไป `visiond` ชั้น 2 ได้โดยไม่เขียนใหม่ · DESIGN.md หัวข้อ 2) · ตอนนี้รันในโปรเซสเดียวกับหน้าจอสำหรับทดลอง

```
กล้อง → [quality gate] → YuNet (กล่อง + 5 จุด) → align 112×112 → MiniFASNet (PAD)
      → SFace (embedding, L2-normalize) → เก็บ 3–5 เฟรมดีสุด → เฉลี่ย → จับคู่ 1:N (threshold + margin)
      → ผล: บัญชี / ไม่รู้จัก / เหตุผลที่ไม่ผ่าน   (log: เวลาแต่ละขั้น, ผล, คะแนน · ไม่มีภาพ)
```

## 5. ข้อมูล

| ข้อมูล | เก็บ? | ที่ไหน |
|---|---|---|
| ภาพจากกล้อง | ❌ หน่วยความจำเท่านั้น | — |
| แม่แบบใบหน้า (embedding เฉลี่ย + จำนวนเฟรม + วันที่) | ✅ | ระหว่างรอ ADR-004: ไฟล์ของผู้ใช้ (atomic + .bak) · ปลายทาง: ตาม BRIEF (กุญแจบัญชี / กุญแจระบบสำหรับ 1:N ที่หน้า Login) |
| log การสแกน | ✅ เวลา, ผล, คะแนน, เหตุผล, เวลาต่อขั้น | ไม่มีภาพ ไม่มี embedding |
| ภาพทดสอบสำหรับประเมิน | ✅ แยกนอกเครื่องใช้งาน | มีหนังสือยินยอม + วันลบ (BRIEF) |

ลบ: "ลบใบหน้า" = ลบแม่แบบ + ใช้ใบหน้าไม่ได้ทันที · เทสต์ว่าไม่เหลือในไฟล์

## 6. รอยต่อ

- `quality.check(face, frame) -> Quality(ok, reasons[])` · เหตุผล: `too_small` (< 112 px) · `blurry` (Laplacian variance) · `too_dark` / `too_bright` · `turned` (yaw/pitch > 25° ประมาณจาก 5 จุด)
- `align(frame, landmarks) -> 112×112`
- `Liveness.score(aligned) -> float` · ต่ำกว่า threshold = ปฏิเสธทันที
- `Embedder.embed(aligned) -> vec (L2 = 1)`
- `select_best(frames, k=3..5)` · `average(vecs)`
- `match(vec, templates, threshold, margin) -> Match(account | None, score, second, reason)`
- `enroll(frames, poses=("ตรง", "ซ้าย", "ขวา")) -> Template | Rejected(reasons)`
- ค่าทั้งหมด (threshold, margin, blur, สว่าง, มุม, จำนวนเฟรม) อยู่ในไฟล์ config ที่อ่านครั้งเดียว
- `python -m aipc.vision.evaluate <โฟลเดอร์> ` → FAR, FRR, EER, threshold ที่ FAR = 0.1%, ROC (PNG + CSV ค่าดิบ)

## 7. กรณีที่ต้องคิดไว้ก่อน

- หลายหน้าในภาพ → ใช้หน้าใหญ่สุด · ถ้าหน้าที่สองใหญ่ใกล้กัน → ไม่ตัดสิน บอก "มีหลายคนในภาพ"
- คนที่หน้าคล้ายกัน → margin กับอันดับสองไม่ถึง → "ไม่แน่ใจ" ให้พิมพ์ชื่อ
- ไม่มีกล้อง/กล้องถูกบัง → สถานะเดิมของหน้า Login ("ไม่พบกล้อง · ใช้รหัสผ่านได้เลย")
- โมเดลหาย/ไฟล์เสีย (sha256 ไม่ตรง) → ใบหน้าใช้ไม่ได้ บอกตรง ๆ ไม่ล่มทั้งหน้า Login
- PAD ของ MiniFASNet: ต้องแปลงเป็น ONNX ให้ OpenCV DNN อ่านได้ → **ยังไม่รู้** ว่าอ่านได้ตรงไหม · ถ้าไม่ได้ ใช้ onnxruntime เฉพาะตัวนี้
- ค่า threshold เริ่มต้นของ SFace (cosine 0.363) ใช้เป็นจุดเริ่มเท่านั้น ต้อง calibrate จาก evaluate.py

## 8. ต้นทุนบน Pi

- RAM: งบใน BRIEF 0.1–0.3 GB · ขนาดจริง **ยังไม่รู้** → วัดบน Pi 4 แล้วยืนยัน Pi 5
- CPU: ประมวลผลเฉพาะตอนหน้า Login เปิดกล้อง/ลงทะเบียน · ไม่วิ่งตลอด
- เวลา: **ยังไม่รู้** · log ต่อขั้นทุกครั้ง · ตัวเลขลงเล่มจาก Pi 5

## 9. การทดสอบ และเกณฑ์ผ่าน (ประกาศก่อนสร้าง)

**Unit test (วินโดวส์ + Pi):** quality gate ทุกเหตุผล (ภาพสังเคราะห์) · มุมจาก 5 จุด · align ขนาด/ตำแหน่งตา · L2-normalize · เฉลี่ยหลายเฟรม · match: ตรง/ไม่ตรง/margin ไม่ถึง/ไม่มีแม่แบบ · enroll ปฏิเสธภาพคุณภาพต่ำ · log ไม่มีภาพ/embedding · ลบแม่แบบแล้วไม่เหลือ

**ประเมินส่วนจับคู่ (ชุดภาพสาธารณะ เช่น LFW — ใช้ในงานศึกษา ตรวจเงื่อนไขก่อนใช้):** รายงาน FAR, FRR, EER, threshold ที่ FAR = 0.1%, ROC · ไม่ตั้งเกณฑ์ผ่าน (เป็นการวัด) แต่ต้องรันซ้ำได้และมีค่าดิบ

**ทั้งระบบกับคนจริง (ตามตาราง BRIEF):** เวลาระบุบัญชี median ≤ 1.5 วิ, p95 ≤ 3 วิ (≥ 50 ครั้ง × ≥ 5 คน, **Pi 5**) · APCER แยกประเภท (รูปพิมพ์/รูปบนจอ/วิดีโอบนจอ) ≥ 60 ครั้งต่อประเภท · Pi 4 วัดได้ แต่กำกับ "(Pi 4)"

## 10. ไม่ทำในรอบนี้

- เทียบกับ InsightFace (ทางเลือก ค.)
