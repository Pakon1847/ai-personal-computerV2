# การ์ดออกแบบ 0055: จอล็อกรุ่น 2 — นาฬิกากลางจอ · ปลดด้วยใบหน้า · คุมเพลง

- **สถานะ:** **อนุมัติแล้ว 2026-10-23 (Pakon "อนุมัติตามที่แนะนำ")** · แตะ PAM (กฎเหล็กข้อ 3) + เพิ่ม dependency (กฎข้อ 5) อนุมัติในข้อความเดียวกัน
- **ข้อกำหนดที่อ้าง:** การ์ด 0020 (ล็อกเมื่อไม่ใช้) · 0051 (ล็อกอย่างเดียว · จอล็อกรุ่น 1 · ตัวตรวจด้วยกล้องผ่าน visiond) · 0015 (เข้าเครื่องด้วยใบหน้า · liveness) · H1 H3 H5 H7
- **ที่มา:** Pakon 2026-10-23 ดูจอล็อกรุ่น 1: "อยากได้เวลาอยู่ตรงกลาง มีการตรวจจับหน้าจะได้ไม่ต้องใส่รหัส และเพิ่มอะไรอีก" → ภาพร่างรุ่น 2 → อนุมัติตามที่แนะนำ

## 1. ปัญหาที่แก้ และใครใช้

ผู้ใช้ทุกคนที่ถูกล็อกจอ: ต้องการดูเวลา · ปลดล็อกโดยไม่ต้องพิมพ์รหัส (มองกล้อง) · คุมเพลงที่เล่นค้างโดยไม่ต้องปลดล็อก ·
swaylock ทำนาฬิกาเดินและปลดด้วยใบหน้าไม่ได้ (ภาพนิ่ง + รหัสผ่านอย่างเดียว)

## 2. หลักการที่ใช้ตัดสิน

| หลักการ | ใช้ยังไง |
|---|---|
| H1 | ใช้ตัวล็อกที่ปลอดภัยแบบเดียวกับเดิม (ext-session-lock: ตัวล็อกตาย = จอยังล็อก) · ไม่ทำจอล็อกด้วย QML ของเราเอง |
| H3 | จอล็อกไม่แสดงนัด/ข้อความ/ชื่อเพลงละเอียด (ใครเดินผ่านก็เห็น) · แสดงแค่ เวลา วันที่ ชื่อบัญชี สถานะใบหน้า ปุ่มคุมเพลง |

## 3. ออกแบบ

- **ตัวล็อก:** `gtklock` 4.0.0 (คลัง Debian 13 ของ Raspberry Pi OS) + `gtklock-userinfo-module` (รูป/ชื่อ) + `gtklock-playerctl-module` + `playerctl` (คุมเพลงผ่าน MPRIS) ·
  หน้าตาด้วยไฟล์ CSS ของเรา (ธีมดำ · ตามภาพร่าง) · ไม่มี gtklock = swaylock รุ่น 1 (การ์ด 0051)
- **ปลดด้วยใบหน้า:** `/etc/pam.d/gtklock`: ลองใบหน้าก่อน (`pam_exec` + `expose_authtok`) → ไม่ผ่าน = รหัสผ่านตามเดิม (`@include common-auth`)
  - ตัวช่วย `aipc-face-unlock` (รันเป็นผู้ใช้คนนั้น ไม่ใช่ root): ช่องรหัสว่าง = ขอ visiond สแกน · พิมพ์รหัสมา = ออกทันที (ไปทางรหัสผ่าน ไม่เสียเวลา)
  - visiond คำขอใหม่ `unlock {username}` เจ้าของบัญชีเท่านั้น · สแกนเทียบเฉพาะแม่แบบของบัญชีนั้น · มี liveness · ผิดหลายครั้ง = ต้องใช้รหัสผ่าน
- **ไม่ใส่:** นัดถัดไป (H3) · ปุ่มปิดเครื่องบนจอล็อก (ไม่มีในแพ็กเกจ)

## 4. ต้นทุน

ดิสก์: gtklock ~99 KB + โมดูล + playerctl (ใช้ GTK3 ที่มีอยู่) · RAM ตอนล็อก: ยังไม่รู้ → วัดบน Pi · ปลดด้วยหน้า: กล้องเปิดเฉพาะตอนกด Enter ช่องว่าง (~2–8 วิ) ·
ไลเซนส์: gtklock GPL-3.0 · playerctl LGPL-3.0 — ใช้เป็นโปรแกรมแยก ไม่ได้ลิงก์กับโค้ดเรา · ตรวจไฟล์ copyright ก่อนติดตั้งแล้วบันทึก ADR-014

## 6. จุดย้อนกลับ

ลบ `/etc/pam.d/gtklock` + `apt remove gtklock` → แอปกลับไปใช้ swaylock รุ่น 1 เอง (ตรวจว่ามี gtklock ก่อนใช้) · ไม่แตะ PAM ของ login/greetd/swaylock

## 7. รอบ 2: ไม่มีกรอบ · ปลดเองเมื่อเห็นหน้า (Pakon 2026-10-23 "สแกนหน้าแล้วก็เข้าไปเลยไม่ต้องมีกรอบอะไรเลย" · เลือก "ทำ 1 และ 2 ทาง ก")

- **ไม่มีกรอบ:** gtklock `-S -H -T 20` = เริ่มด้วยนาฬิกา + วันที่ + คำใบ้ 1 บรรทัด · กดปุ่มใดก็ได้ = กล่องรหัสขึ้น · ไม่แตะ 20 วิ = ซ่อนอีก
- **ปลดเอง (ตั้งค่า "ปลดจอล็อกเองเมื่อเห็นหน้าฉัน" · ค่าเริ่มต้นปิด เพราะกล้องเปิดตลอดตอนล็อก · H3):**
  โมดูล gtklock `aipc-autounlock.so` (C · `src/aipc/ui/lock/aipc-autounlock.c`) เปิดตัวเฝ้า `aipc-face-watch` →
  visiond คำขอ `watch` (เจ้าของเท่านั้น · ได้แค่จำนวนหน้า/ใช่เจ้าของไหม ทุก 2 วิ) → เห็นเจ้าของ = โมดูล "กด Enter" ช่องรหัสที่ว่าง →
  PAM ทางเดิมของรอบ 1 (visiond `unlock` สแกนซ้ำพร้อมตรวจรูปปลอม) ตัดสิน · **โมดูลไม่ได้ตัดสินเอง** (H7) · ช่องมีตัวอักษร = ไม่กด
  ไม่ผ่าน = เฝ้าใหม่ รอ 5 → 10 → … ≤ 60 วิ · ระหว่างล็อก presence ปล่อยกล้อง (visiond ใช้กล้องทีละงาน)
- **ไม่ใช้ libgtk-3-dev:** ตรวจบน Pi แล้วจะพาแพ็กเกจใหม่ 79 ตัว + อัปเกรด 8 ตัว → ประกาศเฉพาะฟังก์ชัน GTK 3/GLib ที่ใช้เอง แล้วลิงก์กับไลบรารีที่มีในเครื่อง (ต้องมีแค่ gcc)
- ทางที่ลองแล้วไม่ได้: ส่งปุ่ม Enter ด้วย `wtype` → gtklock ไม่รับ (ext-session-lock ไม่รับปุ่มจากโปรแกรมอื่น)
