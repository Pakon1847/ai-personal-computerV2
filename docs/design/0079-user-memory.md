# การ์ดออกแบบ 0079: ความจำของผู้ใช้ เก็บได้จนกว่าดิสก์จะเหลือน้อย

- **สถานะ:** **อนุมัติแล้ว (2026-11-07, Pakon "อนุมัติ")**
- **ข้อกำหนดที่อ้าง:** คำแนะนำอาจารย์และกรรมการข้อ 7 · BRIEF 5.2 (หลายผู้ใช้และความเป็นส่วนตัว) · 5.8 · H1 H3 H4

## 1. ปัญหาที่แก้

ตอนนี้ AI ในเครื่องจำได้แค่บทสนทนาที่เปิดอยู่ (context 4,096 token ≈ ข้อความ 3,000 token) · ข้ามแชทแล้วลืม · กรรมการอยากให้จำผู้ใช้ได้ไม่จำกัด เก็บจนดิสก์เต็ม

## 2. ข้อเท็จจริงที่ต้องบอกตรง ๆ

"จำไม่จำกัด" ทำได้ในแง่**เก็บ** (ดิสก์) แต่ AI **อ่านได้ทีละนิด** (context จำกัด) → ต้อง "ค้นแล้วหยิบเฉพาะที่เกี่ยว" (แบบเดียวกับการ์ด 0018 ค้นสกิล) · เขียนในเล่มแบบนี้ ไม่อ้างว่า AI จำทุกอย่างได้พร้อมกัน

## 3. ออกแบบ (ร่าง)

1. **เก็บ:** SQLite ใน home ของผู้ใช้ (`~/.local/share/aipc/memory.db` · 0600) · ตาราง `facts(id, text, source_chat, created, last_used, pinned)` + FTS5 (ค้นข้อความ · มีใน Python มาตรฐาน · ไม่เพิ่ม dependency)
2. **จดอะไร:** เฉพาะที่ผู้ใช้สั่ง ("จำไว้ว่า…") **หรือ** ที่ AI เสนอแล้วผู้ใช้กดยอม (H3 · ไม่แอบจด) · ไม่จดรหัสผ่าน/เลขบัตร (ใช้ตัวตรวจข้อความของการ์ด 0074)
3. **ใช้:** ก่อนตอบ ค้น FTS5 ด้วยข้อความล่าสุด → หยิบ ≤ 5 ข้อ (≤ 300 token) ใส่ท้าย system prompt (ส่วนต้นคงที่ แคชยังใช้ได้)
4. **ไม่จำกัดจำนวน:** ไม่ตั้งเพดานจำนวนข้อ · ดิสก์ว่างของเครื่อง < 2 GB → หยุดจดใหม่ + แจ้งผู้ใช้ (ไม่ลบเอง · H2) · มีหน้าจัดการ: ดู · ค้น · ลบ · ปักหมุด · ส่งออก
5. **หลายผู้ใช้:** แยกไฟล์ต่อบัญชี (home 0700 เดิม) · ลบบัญชี = ลบไฟล์นี้ด้วย
6. **ทางเลือกที่ไม่เลือก:** ฐานข้อมูลเวกเตอร์ + โมเดล embedding (RAM เพิ่ม ~100–500 MB · ต้องเพิ่ม dependency · อธิบายยากกว่า) → เก็บไว้เป็นงานต่อยอดถ้า FTS5 ค้นไม่เจอบ่อย

## 4. ต้นทุน

RAM ~0 (SQLite) · ค้น < 10 ms ที่ 100,000 ข้อ (**ยังไม่ได้วัด** · ต้องวัดบน Pi) · ดิสก์ ~200 B/ข้อ · prompt +≤ 300 token ต่อข้อความที่มีความจำเกี่ยวข้อง
