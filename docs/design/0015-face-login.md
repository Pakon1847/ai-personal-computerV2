# การ์ดออกแบบ 0015: ลงทะเบียนใบหน้าตอนสมัคร + สแกนหน้าที่หน้า Login (1:N ผ่าน `visiond`)

- **สถานะ:** **อนุมัติแล้ว 2026-09-30** (Pakon ตอบหัวข้อ 10: ข้อ 1 = สแกนแล้วเข้าได้เลย · ข้อ 2 = ก. เจ้าของบัญชีเลือกเปิดเอง) ·
  ออกแบบส่วนเข้าระบบด้วยใบหน้าอย่างเดียวในหัวข้อ 12 · หัวข้อ 1–9 เขียนก่อนตัดสิน (แบบ "เลือกบัญชี + รหัสผ่าน") ให้อ่านคู่กับหัวข้อ 12
- **ข้อกำหนดที่อ้าง:** BRIEF 5.1 ข้อ 5–9 และ "ใบหน้า = ความสะดวก ไม่ใช่กุญแจ" · BRIEF หัวข้อแม่แบบใบหน้า (1:N ต้องอ่านได้ก่อน
  มีใครเข้าระบบ) · การ์ด 0005 (แกนใบหน้า) · การ์ด 0006 (ใบหน้าของฉันในหน้าตั้งค่า · ทางเลือก ก. ที่เลื่อนมา) ·
  การ์ด 0012 (ตัวช่วย root `aipc-accounts`) · THREAT_MODEL ("การยืนยันด้วยใบหน้าไม่เทียบเท่ารหัสผ่าน")
- **ขอบเขตรอบ 3 เคยตัดออก** (ARCHITECTURE: "สแกนหน้าที่หน้า Login ไม่มีในรุ่นนี้") · การ์ดนี้เปิดกลับตามที่ Pakon ขอ ·
  ต้องเสร็จก่อนวันล็อกงาน 9 ต.ค.

## 1. ปัญหาที่แก้ และใครใช้

ตอนนี้หน้า Login ต้องพิมพ์ชื่อผู้ใช้ + รหัสผ่าน · วงกล้องบอกแค่ "ระบบจดจำใบหน้ายังไม่พร้อม" ·
เป้าหมาย: เดินมาหน้าเครื่อง → กล้องรู้ว่าเป็นใคร → ขึ้นชื่อและรูปของบัญชีนั้น + ปุ่ม "ไม่ใช่ฉัน" → พิมพ์แค่รหัสผ่าน (BRIEF ข้อ 7)

## 2. หลักการที่ใช้ตัดสิน

| หลักการ | ใช้ยังไง |
|---|---|
| ใบหน้า = ความสะดวก ไม่ใช่กุญแจ | ใบหน้าแค่ **เลือกบัญชี** · การเริ่มเซสชันยังใช้รหัสผ่านผ่าน greetd/PAM เหมือนเดิม (เว้นแต่ตัดสินข้อ 10.1 เป็นแบบ ข.) |
| แยกสิทธิ์ | หน้า Login รันเป็น `_greetd` ซึ่ง **อ่านแม่แบบใบหน้าไม่ได้** · แม่แบบอยู่กับบริการ `visiond` เท่านั้น หน้า Login ได้แค่ "ชื่อบัญชี" กลับมา |
| ยินยอมชัดแจ้ง | บัญชีที่ลงทะเบียนใบหน้าในเซสชัน (การ์ด 0006) **ไม่ถูกใช้ที่หน้า Login อัตโนมัติ** · ต้องเปิด "ให้หน้า Login จำหน้าฉัน" เองและใส่รหัสผ่านยืนยัน |
| ลงทะเบียนให้คนอื่นไม่ได้ | ตัวช่วย root ตรวจรหัสผ่านของบัญชีนั้นก่อนเพิ่มแม่แบบเสมอ (BRIEF ข้อ 6) |
| บอกตามจริง | ไม่มีกล้อง / ไม่มีใครลงทะเบียน / ไม่แน่ใจ = บอกตรง ๆ แล้วให้พิมพ์ชื่อได้เลย · ไม่เดาบัญชีเมื่อคะแนนอันดับ 1 กับ 2 ใกล้กัน (margin) |

## 3. ความสัมพันธ์กับชิ้นส่วนอื่น

```
หน้า Login (_greetd) ──Unix socket /run/aipc-vision/visiond.sock (กลุ่ม aipc-face)──► aipc-visiond (ผู้ใช้ _aipcvision · กลุ่ม video)
      │  identify → {"state": "found", "user": "namfon", "name": "น้ำฝน"}           │ กล้อง + quality + PAD + SFace + 1:N (โค้ด aipc.vision เดิม)
      │                                                                              │ แม่แบบ /var/lib/aipc-vision/face-login/ (0700 · อ่านได้แค่ _aipcvision)
หน้าตั้งค่า "ใบหน้าของฉัน" (ผู้ใช้เอง) ── sudo -n aipc-accounts {"op":"face-login-add", รหัสผ่าน, vector} ──► ตรวจ PAM → เขียนแม่แบบ
```

- **พึ่ง:** `aipc.vision` ทั้งชุด (มีแล้ว · Pi 4: ต่อเฟรม median 88 ms · สแกนคนจริง 11/11) · `aipc-accounts` + PAM ctypes (มีแล้ว) · LoginScreen วงกล้อง 5 สถานะ (มีแล้ว)
- **ใหม่:** `aipc.vision.service` (บริการ) · `aipc.vision.client` (ฝั่งหน้า Login) · op ใหม่ 2 ตัวในตัวช่วย root · สวิตช์ในหน้าตั้งค่า · `install-visiond.sh`

## 4. ข้อมูล

| ข้อมูล | เก็บที่ | ใครอ่านได้ |
|---|---|---|
| แม่แบบสำหรับหน้า Login (embedding เฉลี่ย + ชื่อบัญชี + วันที่ + sha256 ของโมเดล) | `/var/lib/aipc-vision/face-login/<user>.json` (0600) | `_aipcvision` เท่านั้น |
| แม่แบบในเซสชันเดิม (การ์ด 0006) | home ของผู้ใช้ | เจ้าของ (ไม่เปลี่ยน) |
| log | journal: เวลา · ผล found/unknown/no-face · **ไม่มีภาพ ไม่มีเวกเตอร์ ไม่มีคะแนน** | root |

- ลบ: ปิดสวิตช์ / ลบใบหน้าในหน้าตั้งค่า / ลบบัญชี → ลบไฟล์ใน `/var/lib/aipc-vision/face-login` ด้วย
- **ยังไม่เข้ารหัสด้วยกุญแจระบบ (OTP)** ตาม BRIEF · กันได้แค่ผู้ใช้อื่นในเครื่อง ไม่กันการถอด microSD → เขียนเป็นความเสี่ยงที่ยอมรับใน THREAT_MODEL (ถ้าอนุมัติ)

## 5. รอยต่อ (interface)

- socket ส่ง JSON บรรทัดเดียว: `{"op":"identify","timeout_s":8}` → สถานะทีละบรรทัด `scanning` / `no-face` / `low-quality {hint}` /
  `found {user,name}` / `unknown` / `no-camera` / `busy` · `{"op":"stop"}` ปิดกล้องทันที
- `aipc-accounts`: `face-login-add {username, password, vector[128], frames}` · `face-login-remove {username, password}` ·
  ลบบัญชีเรียก remove ให้เอง
- หน้า Login: `login.scanState` ใช้ค่าเดิม + `login.scannedUser` · กด "ไม่ใช่ฉัน" = ล้าง แล้วพิมพ์ชื่อเอง

## 6. กรณีที่ต้องคิดไว้ก่อน

- ไม่มีใครเปิดสวิตช์ → visiond ไม่เปิดกล้องเลย · วงกล้องบอก "ยังไม่มีบัญชีที่ใช้ใบหน้า"
- คะแนนผ่าน threshold แต่ margin กับอันดับ 2 ไม่พอ → `unknown` (ไม่เดา)
- ล้มเหลวติดกัน 5 ครั้ง → หยุดสแกนจนกว่าจะ login ด้วยรหัสผ่านสำเร็จ (BRIEF)
- รูปถ่าย/จอ → PAD MiniFASNet (มีแล้ว) · ถือว่า "กันการโจมตีแบบง่าย" เท่านั้น และใบหน้าไม่ได้เปิดเซสชันเอง
- login สำเร็จ → visiond ปล่อยกล้องก่อนเซสชันเริ่ม (หน้าตั้งค่าในเซสชันใช้กล้องเองได้)
- visiond ล่ม/โมเดลหาย → หน้า Login ใช้รหัสผ่านได้ปกติ · ไม่ล่มทั้งหน้า
- ถอดกล้องกลางสแกน → `no-camera` ภายใน 3 วิ (เกณฑ์เดิม)

## 7. ต้นทุนบน Pi 5

- RAM: ราว 220 MB **เฉพาะตอนหน้า Login สแกน** (Pi 4 วัดได้ 217 MB) · ปิดเองเมื่อไม่มีใครใช้ 60 วิ
- CPU: ~88 ms/เฟรม (Pi 4) · Pi 5 น่าจะเร็วกว่า · ต้องวัดใหม่ (Pi 4 ≠ ระดับ 4)
- **ความร้อน:** Pi 5 เครื่องนี้ขึ้นไป 84°C ตอนรัน AI แม้พัดลมเต็มรอบ (2026-09-30) · ต้องแก้เรื่องระบายความร้อนก่อนวัด

## 8. การทดสอบ และเกณฑ์ผ่าน (ประกาศก่อนสร้าง)

| ทดสอบ | เกณฑ์ |
|---|---|
| เทสต์อัตโนมัติ: visiond กับกล้อง/โมเดลปลอม · client · op ใหม่ของตัวช่วย root (รหัสผิด = ไม่เขียน) | ผ่านทั้งหมด |
| `_greetd` อ่าน `/var/lib/aipc-vision/face-login` | อ่านไม่ได้ (Permission denied) |
| เพิ่มใบหน้าให้บัญชีอื่นโดยไม่รู้รหัส (ทุกทางที่ UI/socket/sudo เปิด) | ทำไม่ได้ |
| เวลาระบุบัญชี (กล้องพร้อม → ชื่อขึ้น) บน Pi 5 | มัธยฐาน ≤ 1.5 วิ · p95 ≤ 3 วิ (BRIEF) · อย่างน้อย 20 ครั้ง × คนที่มี (ชุดเต็ม ≥ 5 คนทำภายหลัง) |

| ไม่มีกล้อง / visiond ปิด | login ด้วยรหัสผ่านได้ปกติ |

## 9. ไม่ทำในรอบนี้

- เข้ารหัสแม่แบบด้วยกุญแจระบบ (OTP) · โหมดใช้ร่วมกัน/Guest · ปลดปิดบัง/ล็อกด้วยใบหน้า (BRIEF 5.2) · APCER ตามมาตรฐาน ≥ 60 ครั้งต่อประเภท

## 10. คำถามที่ Pakon ตัดสินแล้ว (2026-09-30)

1. **สแกนแล้วเข้าระบบได้เลย** (แบบ ข. = "โหมดสะดวก" ของ BRIEF) · ผู้ช่วยแจ้งความเสี่ยงแล้ว: ความปลอดภัยต่ำกว่ารหัสผ่าน
   (กันรูปปลอมได้แค่แบบง่าย · ยังไม่มีตัวเลข) และงานเพิ่ม (ต่อ PAM)
2. **ก. เจ้าของบัญชีเลือกเปิดเอง** · ปิดเป็นค่าเริ่มต้น · เปิดตอนสมัคร (ขั้นใบหน้า) หรือในหน้าตั้งค่า · เปิดต้องยืนยันรหัสผ่าน

## 11. เพิ่มหลังร่าง: ลงทะเบียนใบหน้าในหน้าสมัคร (Pakon 2026-09-30 เช้า)

Pakon: "ในหน้าสมัครยังต้องเพิ่มลงทะเบียนสแกนหน้าเข้าไปด้วย" · ตรง BRIEF 5.1 ข้อ 4–6
(ตั้งรหัสผ่าน → PIN กู้คืน → ลงทะเบียนใบหน้าถ้าเลือก · ข้ามได้)

- **ลำดับหน้าสมัคร:** ขั้นเดิม 3 ขั้น → **ขั้นที่ 4 (ไม่บังคับ): "ให้หน้า Login จำหน้าคุณไหม"** → ขอความยินยอม (ข้อมูลชีวภาพ ·
  พ.ร.บ.คุ้มครองข้อมูลส่วนบุคคล มาตรา 26 · ข้อความเดียวกับการ์ด 0006) → สแกน 3 ท่า → เสร็จ · กด "ข้าม" ได้ทุกเมื่อ
- **ใครถือกล้อง:** `visiond` (ไม่ใช่หน้า Login ของ `_greetd`) · หน้าสมัครส่ง `{"op":"enroll","username","password"}` ทาง socket →
  visiond สแกน 3 ท่า (quality gate + PAD เดิม) → ส่งเวกเตอร์ต่อให้ `aipc-accounts face-login-add` ซึ่ง **ตรวจรหัสผ่านด้วย PAM ก่อนเขียน**
  → เวกเตอร์ไม่ผ่านมือหน้า Login เลย
- **ลงทะเบียนไม่ผ่าน (BRIEF ข้อ 6):** ลองใหม่ได้ในขั้นตอนสมัครเดิม (ยังไม่รีบูต ไม่หมดเวลา 10 นาที) · หลังจากนั้นต้องทำในหน้าตั้งค่า
  "ใบหน้าของฉัน" หลัง login ด้วยรหัสผ่าน · บัญชีสร้างเสร็จแล้วตั้งแต่ขั้น 3 ใบหน้าล้ม = บัญชียังใช้รหัสผ่านได้ปกติ
- **ห้ามลงทะเบียนให้บัญชีอื่น:** รหัสผ่านต้องตรงกับบัญชีที่เพิ่งสร้าง (ตัวช่วย root ตรวจ) · ใช้ช่องนี้กับบัญชีที่มีอยู่แล้วไม่ได้
- **แม่แบบที่ได้:** ใช้ทั้งหน้า Login (1:N) และคัดลอกเข้า home ของผู้ใช้ตอน login ครั้งแรก ให้หน้าตั้งค่าเห็นและลบได้ที่เดียว
- **ทดสอบเพิ่ม:** สมัคร → ลงทะเบียน → ออก → หน้า Login ขึ้นชื่อ · ข้ามขั้นใบหน้า = ไม่มีไฟล์ใน `/var/lib/aipc-vision/face-login` ·
  ถอดกล้องระหว่างลงทะเบียน = บอก "กล้องหลุด" บัญชียังสร้างอยู่ · ส่งรหัสผิดทาง socket = ไม่เขียนอะไร

## 12. เข้าระบบด้วยใบหน้าอย่างเดียว (ตามที่ Pakon ตัดสิน)

```
หน้า Login ── identify ──► visiond ── พบ "namfon" (ผ่าน threshold + margin + PAD) ──► ออกตั๋ว 1 ใบ (ผูกกับ namfon · อายุ 30 วิ · ใช้ได้ครั้งเดียว)
    │ create_session("namfon") ผ่าน greetd
    ▼
PAM /etc/pam.d/greetd:  auth [success=done default=ignore] pam_exec.so quiet /usr/local/sbin/aipc-face-pass   ← บรรทัดแรก
                        @include login (รหัสผ่านเดิม)
aipc-face-pass (root · อ่าน PAM_USER) ── socket เฉพาะ root ──► visiond: "ใช้ตั๋วของ namfon" → มี = สำเร็จ (เข้าเลย) · ไม่มี = ไปถามรหัสผ่านตามเดิม
```

- **เฉพาะ `/etc/pam.d/greetd`** · sudo, SSH, หน้าจอล็อก และตัวช่วยบัญชียังใช้รหัสผ่านเสมอ (เทสต์ตรวจไฟล์ PAM ทุกตัว)
- **ตั๋ว:** สุ่ม 32 ไบต์ · อยู่ในหน่วยความจำของ visiond เท่านั้น · ผูกชื่อบัญชี · 30 วิ · ใช้แล้วลบ · socket ของตั๋วตรวจ `SO_PEERCRED` = uid 0
  (หน้า Login ขอออกตั๋วไม่ได้ ขอได้แค่ identify · ตั๋วเกิดจาก visiond เองเมื่อสแกนผ่านเท่านั้น)
- **เจ้าของเลือกเปิด (ข้อ 2):** แม่แบบของบัญชีที่ไม่ได้เปิด ไม่อยู่ในรายการที่หน้า Login ใช้เลย · เปิด/ปิด = `aipc-accounts face-login-add/remove`
  (ตรวจรหัสผ่านด้วย PAM ก่อน)
- **ตัวลดความเสี่ยง (BRIEF 5.1 ข้อ 9):** สแกนไม่ผ่าน 5 ครั้งติด → ต้องใช้รหัสผ่านจนกว่าจะเข้าด้วยรหัสผ่านสำเร็จ 1 ครั้ง · PAD ทุกครั้ง ·
  งานสำคัญ (เปลี่ยนรหัส ติดตั้งสกิล ลบข้อมูล sudo) ใช้รหัสผ่านเสมอ · หน้าจอบอกว่า "เข้าด้วยใบหน้า" ทุกครั้ง + ปุ่ม "ไม่ใช่ฉัน"
- **ยังไม่มีการเข้ารหัส home ด้วยรหัสผ่าน (fscrypt ยังไม่ได้ทำ)** จึงเข้าด้วยใบหน้าได้โดยไม่ต้องปลดกุญแจ · ถ้าทำ fscrypt ภายหลังต้องออกแบบใหม่
  (BRIEF: ห่อกุญแจบัญชีด้วยกุญแจเครื่อง)
- **THREAT_MODEL เพิ่มความเสี่ยงที่ยอมรับ:** รูปถ่าย/จอที่ PAD ไม่จับ → เข้าบัญชีที่เปิดโหมดนี้ได้ · แฝด/คนหน้าคล้าย · ถอด microSD อ่านแม่แบบได้
