# การ์ดออกแบบ 0063: เลือก Wi-Fi จากแถบด้านบน

- **สถานะ:** อนุมัติแล้ว (2026-10-24, Pakon "อนุมัติ 0062, 0063") · ใครเปลี่ยนได้: Pakon ไม่ได้ระบุ → ผู้ช่วยใช้แบบการ์ด 0052 = ผู้ใช้ที่นั่งที่จอ (active local session) · แจ้ง Pakon แล้ว
- **ที่มา:** Pakon "แถบข้างบนทำให้สามารถเลือก wifi ที่จะเชื่อมได้ด้วย"

## 1. ปัญหา

เปลี่ยน Wi-Fi ต้องใช้ terminal (ไม่มีแถบงานของ Pi ในเซสชันของเรา) · แถบบนมีแค่สถานะเน็ต

## 2. หลัก

| หลักการ | ใช้ยังไง |
|---|---|
| H1 | รหัส Wi-Fi ส่งให้ NetworkManager ทาง D-Bus/ไฟล์ชั่วคราวสิทธิ์ 600 · **ไม่ใส่ใน argv** (คนอื่นเห็นใน ps) · ไม่ log ไม่เก็บในแอป |
| H7 | สิทธิ์ตัดสินโดย NetworkManager + polkit · หน้าจอแค่ส่งคำขอ |
| H5 | เชื่อมไม่ได้ (รหัสผิด/สัญญาณหาย) = บอกตามจริง · เครื่องกลับไปใช้เครือข่ายเดิมเอง |

## 3. ออกแบบ

- กดป้ายเครือข่ายบนแถบบน → หน้าต่างเล็ก: รายชื่อ Wi-Fi (ชื่อ · แรงสัญญาณเป็นขีด · มีรหัสไหม · อันที่ต่ออยู่) · ปุ่มค้นหาใหม่
- กดชื่อ → ช่องรหัส (ซ่อนตัวอักษร · กดตาเพื่อดู) → เชื่อมต่อ · Wi-Fi ที่เคยต่อ = ต่อเลยไม่ถามรหัส · ลืมเครือข่ายได้
- ใช้ `nmcli` (มีบน Pi แล้ว · NetworkManager ทำงานอยู่)

## 4. ต้องตรวจก่อนสร้าง (ขั้น 0)

ตรวจแล้ว (2026-10-24 · ผ่าน `sudo -u pakon` นอกเซสชันจอ): `network-control` · `wifi.scan` · `settings.modify.own` = **auth** (ต้องยืนยันตัวตน) ·
ต้องตรวจซ้ำ **ในเซสชันที่จอจริง** (ผู้ใช้ active · polkit อาจให้ yes) · ถ้ายังเป็น auth → ต้องเพิ่มกฎ polkit (`/etc/polkit-1/rules.d` · แบบการ์ด 0052) = **ถามก่อนแก้ /etc** ·
ต้องตัดสิน: ผู้ใช้ทุกคนเปลี่ยน Wi-Fi ของเครื่องได้ หรือเฉพาะบางบัญชี (เครื่องใช้ร่วมกันหลายคน · เปลี่ยนแล้วกระทบทุกคน)

## 5–7. ข้อมูล · รอยต่อ · ต้นทุน

ไม่เก็บรหัสในแอป (NetworkManager เก็บเองตามปกติ) · `NetworkController.scan()` / `connect(ssid, password)` / `forget(ssid)` · CPU/RAM ~0 · ประมาณ 1 วัน

## 8. เกณฑ์ผ่าน

| # | เกณฑ์ |
|---|---|
| W1 | เห็นรายชื่อ Wi-Fi ≤ 5 วิหลังกด (Pi 5) |
| W2 | ต่อ Wi-Fi มีรหัส: รหัสถูก = ต่อได้ 3/3 · รหัสผิด = บอก "รหัสไม่ถูก" ไม่ค้าง 3/3 · เน็ตเดิมกลับมาเอง |
| W3 | เทสต์: รหัสไม่อยู่ใน argv/log · ช่องรหัสซ่อนตัวอักษร |
| W4 | เทสต์ทั้งชุดผ่าน · ไม่มีคำเตือน QML |

## 9. ไม่ทำในรอบนี้

Wi-Fi แบบองค์กร (WPA-Enterprise) · ปล่อยฮอตสปอต · ตั้ง IP เอง

## 10. ผลขั้น 0 (2026-10-24 · Pi 5 · อ่านอย่างเดียว)

นโยบาย NetworkManager (`/usr/share/polkit-1/actions/…NetworkManager.policy`) ของผู้ใช้ที่นั่งหน้าจอ (active):
`wifi.scan` = yes · `network-control` = yes · `settings.modify.own` = yes · **`settings.modify.system` = auth_admin_keep** ·
กฎของ Raspberry Pi OS (`/usr/share/polkit-1/rules.d/org.freedesktop.NetworkManager.rules`): modify.system = yes ถ้าอยู่กลุ่ม **netdev** หรือ sudo ·
pakon ไม่อยู่ netdev (มีแค่ aipc2030)

ทางเลือก:
- **ก (แนะนำ):** ใส่บัญชีที่ให้เปลี่ยน Wi-Fi ได้เข้ากลุ่ม netdev (ทางเดียวกับที่ Raspberry Pi OS ออกแบบไว้ · ไม่ต้องเขียนกฎ polkit เอง) · แก้ /etc/group = ถาม Pakon ก่อน ·
  บัญชีใหม่ตอนสมัคร: เพิ่ม netdev ในกลุ่มของตัวช่วยสมัคร (ถ้า Pakon เลือก "ทุกบัญชี")
- ข: Wi-Fi เป็นของผู้ใช้คนนั้น (connection.permissions) = ไม่ต้องแก้ระบบ แต่ใช้ได้เฉพาะตอนคนนั้นเข้าระบบอยู่ · หน้า Login/คนอื่นไม่มีเน็ตนั้น

ยังไม่รู้ (ต้องลองบน Pi ก่อนเขียนโค้ดส่วนเชื่อมต่อ): ส่งรหัสด้วย `passwd-file` (ไฟล์ 600 ลบทันที) แล้ว NetworkManager จำรหัสไว้ให้ครั้งหน้าหรือไม่ ·
การลองเปลี่ยน Wi-Fi บน Pi อาจตัด SSH ที่ใช้ฮอตสปอตอยู่ → ต้องลองตอน Pakon อยู่ที่จอ และมี Wi-Fi อีกเครือข่ายให้ลอง

## 11. ตัดสินใจ (2026-10-24 · Pakon "0063 ทาง ก ทุกบัญชี")
