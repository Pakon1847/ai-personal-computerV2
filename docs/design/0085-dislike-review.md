# การ์ดออกแบบ 0085: ปุ่มชอบ/ไม่ชอบ → Claude ตรวจและแก้สกิลเอง

- **สถานะ:** อนุมัติ (Pakon 2026-11-20 "อนุมัติตามที่แนะนำ" · ทั้ง 6 เรื่องในหัวข้อ 10 ตามคำแนะนำ) · แผนย่อย `docs/plans/2026-11-20-0085-dislike-review.md`
- **ที่มา:** อาจารย์ที่ปรึกษา (Pakon สรุปมาให้ 2026-11-20): AI ในเครื่องทำงานเสร็จ → ปุ่ม like/dislike สักพักแล้วหาย · like / ไม่กด = ไม่มีอะไร · dislike = Claude ตรวจผลของ AI ในเครื่องกับสกิล แล้วแก้หรือเพิ่มสกิล · สกิลที่ Claude แก้/เพิ่ม **ใช้ได้ทันทีโดยไม่ต้องรอผู้ใช้อนุมัติ**
- **ข้อกำหนดที่อ้าง:** BRIEF หัวข้อสกิล · SKILLS.md (ชั้นที่ 2 ผู้ใช้บอกว่าผิด · ชั้นที่ 3 ผิดซ้ำปิดเอง) · การ์ด 0017 0030 (Claude สร้างสกิล) · 0074 (กันสกิลแย่งคำสั่ง) · 0078 (ปุ่ม "ตรงใจ"/"ไม่ถูก") · 0083 (วงจรเรียนรู้สกิล) · 0084 (ใช้ลิมิตบัญชี Claude)

## 1. ปัญหาที่แก้ และใครใช้

ผู้ใช้ทุกคนที่เปิด Claude ไว้: เมื่อ AI ในเครื่องทำงานไม่ดี ตอนนี้แก้ได้เฉพาะสกิลที่ Claude สร้าง และต้องพิมพ์อธิบายว่าผิดตรงไหน ·
การ์ดนี้ทำให้ **กดปุ่มเดียว** แล้ว Claude ดูว่าพลาดเพราะอะไร และแก้สกิล สร้างสกิลใหม่ หรือบอกว่าไม่ต้องแก้ · ครั้งหน้า AI ในเครื่องทำเองได้ (local-first)

## 2. หลักการที่ใช้ตัดสิน

| หลักการ | ใช้ยังไง |
|---|---|
| H1 ข้อมูลปลอดภัย | สกิลที่ Claude ส่งมา = ผ่านด่านตรวจเดียวกับตอนสร้าง (`userskills.gate` · ตัวตรวจ manifest · ทดลองเส้นทาง · ไม่แย่งประโยคของสกิลอื่น) ก่อนใช้ทุกครั้ง |

| H3 ความเป็นส่วนตัว | ส่งเฉพาะรอบที่กด "ไม่ชอบ" · ปุ่มบอกชัดว่าจะส่งให้ Claude · จดลงสมุดบัญชีคลาวด์ทุกครั้ง · ปิด Claude = ไม่ส่ง |

| H6 โค้ดตัดสิน | Claude **เสนอ** ไฟล์สกิล · โค้ดตัดสินว่าติดตั้งได้ไหม · ส่วนหัวสิทธิ์ของสกิลเดิมยึดค่าเดิม (`forge.pin_header`) |

## 3. ความสัมพันธ์กับชิ้นส่วนอื่น

- **พึ่ง (มีแล้ว):** `forge.forge(..., revise=...)` · `userskills.gate/install` + รุ่น/ย้อนรุ่น · `SkillsController._start_forge/_on_forged` · สมุดบัญชีคลาวด์ (`cloud/ledger.py`) · ข้อความโควตาเต็ม (การ์ด 0084) · ปุ่ม "ตรงใจ" ใน `SkillCard.qml` (0078)
- **ต้องแก้ตาม:** สมุดบัญชีชนิดใหม่ `review` ต้องเพิ่มใน `ledger.KINDS` และ `CLAUDE_KINDS` ของการ์ด 0084 (นับ "วันนี้ถาม Claude ไป N ครั้ง")
- **เปลี่ยน:** ปุ่มใต้ผลย้ายจาก "เฉพาะสกิลผู้ใช้" → ทุกผลของ AI ในเครื่อง · "ไม่ถูก" แบบพิมพ์เอง (0078) ยังอยู่เป็นทางเลือกในหน้า Skill
- **ชั้นของระบบ:** หน้าจอ (QML: ปุ่ม) → `SkillsController` / `ChatController` (backend ตัดสิน) → `forge` (Claude) → ด่านตรวจ → โฟลเดอร์สกิลของผู้ใช้

## 4. ข้อมูล

- **ส่งให้ Claude (เมื่อกด "ไม่ชอบ" เท่านั้น):** คำสั่งของผู้ใช้ · คำตอบ/ผลของเครื่อง (ตัดที่ ~1,500 ตัวอักษร) · ทางที่ระบบเลือก (เช่น `chat` `skill:<id>` `rule:<ชนิด>`) · ไฟล์ .md ของสกิลที่ใช้ (ถ้าเป็นสกิลผู้ใช้) · รายชื่อ+คำอธิบายสกิลที่มี (แบบเดียวกับที่ forge ส่งอยู่แล้ว)
- **ไม่ส่ง:** ไฟล์แนบ · อีเมล/ปฏิทิน/ความจำผู้ใช้ทั้งก้อน · ประวัติแชทรอบอื่น · ถ้ารอบนั้นใช้ข้อมูลส่วนตัว (ไฟล์ · Gmail · ปฏิทิน · ความจำ) → ถามยืนยันอีกครั้งก่อนส่ง (หัวข้อ 10)
- **เก็บในเครื่อง:** นับ ชอบ/ไม่ชอบ ต่อสกิล (ใช้ตัวนับเดิมของ 0078 `likes`/`downs`) · ผลการตรวจของ Claude 1 บรรทัดในประวัติรุ่นของสกิล · สมุดบัญชีคลาวด์ชนิดใหม่ `review`
- **ไฟดับกลางคัน:** ยังไม่ติดตั้ง = ไม่มีอะไรเปลี่ยน (ติดตั้งแบบเขียนไฟล์ชั่วคราวแล้วเปลี่ยนชื่อ ของเดิม 0078)

## 5. รอยต่อ

- QML: `skills.rateResult(turnId: str, liked: bool) -> QVariantMap` (การ์ดผล: กำลังให้ Claude ตรวจ / ต้องเปิด Claude ก่อน)
- backend: เก็บ `turn` ล่าสุด N รอบ (คำสั่ง · ผล · route · skill id · ใช้ข้อมูลส่วนตัวไหม) ในหน่วยความจำ ไม่เขียนดิสก์
- `forge.review(turn, skills, ...) -> Proposal` · ผล 3 แบบ: `revise` (id เดิม) · `create` (สกิลใหม่) · `none` (บอกเหตุผล ไม่ติดตั้ง) · ใช้ด่านและการติดตั้งเดียวกับ `_on_forged`

## 6. กรณีที่ต้องคิดไว้ก่อน

- ปิด Claude / ไม่มี Claude / โควตาเต็ม → บอกตามจริง ไม่ส่ง (0084)
- กดไม่ชอบรัว ๆ → 1 รอบตอบ = ตรวจได้ 1 ครั้ง · กำลังตรวจอยู่ = ปุ่มอื่นรอ (`_forging` เดิม)
- Claude ส่งสกิลที่แย่งคำสั่งเดิม / ขอสิทธิ์เพิ่ม / ไม่ผ่านตัวตรวจ → ไม่ติดตั้ง + บอกเหตุผล
- สกิลในตัวพลาด → Claude **ไม่แก้สกิลในตัว** สร้างสกิลผู้ใช้แทนได้ (หัวข้อ 10)
- สกิลใหม่สั่งเครื่อง → การ์ดยืนยันตอนจะทำจริงยังอยู่ (หัวข้อ 10)
- ออกจากระบบระหว่าง Claude ตรวจ → ผลทิ้ง ไม่ติดตั้งข้ามบัญชี · หลายผู้ใช้ = สกิลของใครของมัน
- คำตอบเดิมมีคำสั่งแฝง ("ลบไฟล์ทั้งหมด") → เป็นข้อมูลให้ Claude อ่าน ไม่ใช่คำสั่ง (H8)

## 7. ต้นทุนบน Pi 5

RAM/CPU: ปุ่ม + ตัวนับ ≈ 0 · ไม่เรียก AI ในเครื่องเพิ่ม · Claude: **1 ครั้งต่อการกด "ไม่ชอบ"** (ใช้โควตา Pro ของผู้ใช้ · เวลาเท่าการสร้างสกิล ~1–3 นาที ยังไม่ได้วัดสำหรับโหมดตรวจ) · ดิสก์: รุ่นสกิลละไม่กี่ KB
