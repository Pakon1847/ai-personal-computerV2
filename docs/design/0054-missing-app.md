# การ์ดออกแบบ 0054: เปิดแอปที่ไม่มีในเครื่อง → ถามติดตั้ง / ถามเปิดผ่านเบราว์เซอร์

- **สถานะ:** ร่าง (2026-10-22) · รอ Pakon อนุมัติ · **ส่วนติดตั้งจริงแตะสิทธิ์ root + apt → ต้องอนุมัติแยก (กฎเหล็กข้อ 1, 3)**
- **ข้อกำหนดที่อ้าง:** `skills/apps.py` · `skills/actions.py:280` ("ไม่พบแอปนี้ในเครื่อง") · `actions.SITES` · การ์ด 0031 (เว็บแอป) · `accounts/helper.py` · H1 H2 H7 H8
- **ที่มา:** รายการของ Pakon 2026-10-22 ข้อ 2 · ทางที่เลือก: ถามเปิดผ่านเว็บ **และ** ถ้าผู้ใช้บอกให้ติดตั้ง ต้องติดตั้งจริง

## 1. ปัญหาที่แก้ และใครใช้

ผู้ใช้สั่ง "เปิด X" แล้วเครื่องไม่มี X → ตอนนี้ตอบแค่ "ไม่พบแอปนี้" แล้วจบ · ต้องการให้ถามต่อ: ติดตั้งไหม → ถ้าไม่ → มีเว็บไหม เปิดผ่านเบราว์เซอร์ไหม ·
**ถามแบบนี้ทุกครั้ง** รวมถึงหลังออกจากระบบแล้วเข้ามาใหม่ (ไม่จำว่าเคยตอบ "ไม่")

## 2. หลักการที่ใช้ตัดสิน

| หลักการ | ใช้ยังไง |
|---|---|
| H7 backend ตัดสินสิทธิ์ | ติดตั้งได้เฉพาะแอปใน **รายการที่ผู้ดูแลอนุญาต** (`/etc/aipc/apps-allowed.json`: ชื่อที่พูด → ชื่อแพ็กเกจ apt + ลิงก์เว็บ) · ตัวช่วย root ตรวจชื่อแพ็กเกจกับรายการนี้เอง ไม่เชื่อข้อความจากหน้าจอ |
| H8 ข้อมูลไม่ใช่คำสั่ง | ชื่อแพ็กเกจไม่มาจาก LLM / เว็บ / ไฟล์สกิล · มาจากรายการผู้ดูแลเท่านั้น |
| H1 | ติดตั้งด้วย `apt-get install --no-install-recommends -y <pkg>` แพ็กเกจเดียว ห้าม remove/upgrade · ดิสก์เหลือ < 2 GB = ไม่ติดตั้ง |
| H2 | ระหว่างติดตั้งแสดงความคืบหน้า · ล้มเหลว = บอกสาเหตุจริง (ไม่มีเน็ต / ดิสก์เต็ม / แพ็กเกจไม่พบ) |
| เครื่องหลายคน | ติดตั้งแล้ว**ทุกผู้ใช้ได้แอปด้วย** → เฉพาะผู้ใช้ที่เป็น**ผู้ดูแล**สั่งติดตั้งได้ ต้องใส่รหัสผ่านของผู้ดูแลยืนยัน · ผู้ใช้ทั่วไป = "ต้องให้ผู้ดูแลติดตั้ง" แล้วไปถามเรื่องเว็บต่อ |

## 3. ขั้นตอน (ทุกครั้ง ไม่จำคำตอบ)

```
"เปิด X" → มีในเครื่อง? ─ใช่→ เปิด
             └ไม่ → X อยู่ในรายการอนุญาต?
                    ├ใช่ → "ไม่มีแอป X ในเครื่อง ติดตั้งไหม?" ─ใช่→ (ผู้ดูแล + รหัส) → ติดตั้ง → เปิด
                    │                                        └ไม่→ ข้อถัดไป
                    └ไม่ → ข้อถัดไป
             X มีเว็บ? ─ใช่→ "จะเปิดผ่านเบราว์เซอร์ไหม?" ─ใช่→ เปิดในเบราว์เซอร์ของผู้ช่วย · ไม่→ ไม่ทำอะไร
                       └ไม่→ "ไม่พบแอปนี้ในเครื่อง" (เหมือนเดิม)
```

- ตอบด้วยเสียงได้ ("ใช่" / "ไม่" / "เปิดเว็บ") ใช้ตัวยืนยันเดียวกับการ์ด 0045 ("หมายถึง … ใช่ไหม")
- รายการเริ่มต้น (เสนอ · ผู้ดูแลแก้ได้): LibreOffice (writer/calc) · GIMP · VLC · Thonny · Inkscape · แอปที่มีเว็บ: Spotify · Discord · Zoom · Microsoft Teams · Canva (ไม่มีแพ็กเกจ apt → ถามเว็บอย่างเดียว)
- ไลเซนส์ของแอปในรายการ: ตรวจตาม ADR-014 ก่อนใส่รายการ

## 4. ออกแบบส่วนติดตั้ง

- ตัวช่วยสิทธิ์เดิม (`accounts/helper.py` รันผ่าน sudoers ที่มีอยู่) เพิ่ม `{"op":"install_app","app":"<key>","admin":…,"admin_password":…}` ·
  ตรวจรหัสผู้ดูแลด้วย PAM (ทางเดียวกับสร้างบัญชี) → หา `<key>` ในรายการ → `apt-get install` → ส่งความคืบหน้าทีละบรรทัด
- ทางเลือกที่ไม่เอา: ให้ผู้ใช้สั่ง `sudo apt` ตรง ✗ (H7) · Flatpak ✗ (ไม่ได้ติดตั้งไว้ · กิน RAM/ดิสก์เพิ่ม · ต้องถามก่อนเพิ่ม dependency)
- ⚠️ **กรรมการถามแน่:** "ให้ผู้ใช้สั่งติดตั้งโปรแกรมด้วยสิทธิ์ root ปลอดภัยไหม" → คำตอบ: ติดตั้งได้แค่รายการที่ผู้ดูแลกำหนด · ต้องรหัสผู้ดูแล · ตัดสินที่ backend · ไม่มีชื่อแพ็กเกจจาก AI

## 5. ต้นทุน

RAM ≈ 0 ตอนไม่ได้ติดตั้ง · ระหว่างติดตั้ง apt ใช้ CPU/ดิสก์ (LibreOffice ~300–400 MB ดิสก์ · ยังไม่ได้วัดบน Pi) · LLM 0 · เวลาทำ ~2–3 วัน (ส่วนถามเว็บ ~0.5 วัน)
