# การ์ดออกแบบ 0009 (ย้อนหลัง): สกิล 5 ถามเครื่องว่าเป็นอะไร

- **สถานะ:** การ์ดย้อนหลัง · โค้ดสร้าง 2026-09-23 ก่อนมีกติกา "การ์ดก่อนโค้ด" · เขียน 2026-09-24 · **รอ Pakon ทบทวน + อนุมัติแผนวัดผลข้อ 8**
- **ข้อกำหนดที่อ้าง:** SKILLS.md สกิล 5 · BRIEF 5.7 (หน้าสุขภาพเครื่อง) · ROADMAP 0.3 (`aipc.doctor`) · DESIGN.md H5 H6 H1

## 1. ปัญหาที่แก้ และใครใช้

ผู้ใช้ที่ไม่รู้เรื่องเทคนิคถาม "ทำไมเครื่องช้า" แล้วได้คำตอบเป็นภาษาคนพร้อมวิธีแก้ · บน Pi ปัญหาที่พบบ่อยคือไฟตก ร้อน RAM เต็ม พื้นที่เต็ม

## 2. หลักการที่ใช้ตัดสิน

| หลักการ | ใช้ยังไง |
|---|---|
| **H6** | โค้ดอ่านค่าและตัดสินว่ามีปัญหาอะไร (`skills/machine.py`) · LLM (เมื่อมี) เรียบเรียงประโยคเท่านั้น ห้ามเพิ่มข้อเท็จจริง |
| **H5** ความจริง | อ่านค่าไม่ได้ = บอกว่า "ไม่รู้" (รายการ `unknown`) ห้ามเดา · อ่านไม่ได้เกือบหมด = บอกว่า "น่าจะไม่ได้รันบน Pi" |
| **H1** | วิธีแก้ที่แตะไฟล์บูตเป็นคำแนะนำเท่านั้น ไม่มีปุ่มทำให้อัตโนมัติ |
| หนึ่งแหล่งความจริง | ใช้ `aipc.doctor` ตัวเดียวกับหน้าสุขภาพเครื่อง · คำตอบในแชทกับหน้าสุขภาพเครื่องจึงไม่ขัดกัน |

## 3. ทางเลือก

| ทางเลือก | ข้อดี | ข้อเสีย |
|---|---|---|
| **ก. โค้ดตัดสิน + ประโยคที่เขียนไว้ (เลือก, ตอนนี้)** | ถูกแน่นอน ใช้ได้ทันทีไม่ต้องรอ LLM | ประโยคแข็ง ไม่ปรับตามคำถาม |
| ข. ส่งค่าดิบให้ LLM ตอบเอง | ประโยคเป็นธรรมชาติ | LLM เล็กบน Pi อาจแต่งค่าที่ไม่มีจริง (hallucination) · ช้า |
| ค. ก. แล้วให้ LLM เรียบเรียงผลของ ก. (เป้าหมาย) | ได้ทั้งความถูกและความลื่น | ต้องมี LLM (ADR-007) + ตัวตรวจว่า LLM ไม่เพิ่มตัวเลขใหม่ |
