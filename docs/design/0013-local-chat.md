## 1. ปัญหาที่แก้ และใครใช้

ช่องแชทรับข้อความได้ แต่ **ไม่มีโมเดลตอบ** — ส่วน "AI" ของ AI Personal Computer ยังไม่มีเลย
ผู้ใช้: ทุกคนที่เข้าเครื่อง · ใช้ถามคำถามทั่วไป เขียน สรุป แปล (สกิล 1) แบบไม่ต้องใช้เน็ต

## 2. หลักการที่ใช้ตัดสิน

| หลักการ | ใช้ยังไงในฟีเจอร์นี้ |
|---|---|
| **H3/H4** ส่วนตัว + local | llama-server รันเป็นโปรเซสของผู้ใช้คนนั้น · คุยผ่าน Unix socket ใน `$XDG_RUNTIME_DIR` (0700) · ไม่มีพอร์ตเครือข่าย ไม่มี Cloud |
| **H5** ความจริง | ป้ายสถานะโมเดลจากค่าจริง: พร้อม / กำลังโหลด / ไม่พร้อม (พร้อมเหตุผล) · ตอบไม่จบเพราะ AI หยุดทำงาน = บอกตรง ๆ ไม่ทำเป็นว่าจบ |
| **H6** งานต้องถูกแน่นอนใช้โค้ด | ตัวคัดสกิลทำงานก่อนเสมอ (สั่งเครื่อง นัดหมาย ถามเครื่อง) · LLM รับเฉพาะที่ไม่ตรงสกิลใด + สกิลแปล |
| **H8** ข้อมูลไม่ใช่คำสั่ง | คำตอบของ LLM เป็นข้อความเท่านั้น · รุ่นนี้ LLM สั่ง Action ไม่ได้เลย |
| **H1** ข้อมูลปลอดภัย | ประวัติแชทเขียนแบบ atomic (ตัวเขียนเดียวกับนัดหมาย) · บันทึกไม่ได้ = บอก ไม่หายเงียบ |
| ทนทาน | llama-server เป็น user service ของ systemd (`Restart=on-failure`, `MemoryMax`) · AI พัง หน้าจอยังอยู่ |

## 3. ความสัมพันธ์กับชิ้นส่วนอื่น

- **พึ่ง:** llama.cpp `llama-server` (build บน Pi · runbook ตั้ง Pi 5) · ไฟล์โมเดลจาก ADR-007 (ระหว่างรอผลใช้ตัวที่วัดได้เร็วสุดไปก่อน — เปลี่ยนแค่ไฟล์) ·
  ตัวคัดสกิล (มีแล้ว) · เซสชัน V2 (การ์ด 0004) สำหรับเปิด/ปิด service
- **มีคนพึ่ง:** ข้ออ้างที่ 1 ของเล่ม · สกิล 1 แปล · ตัวเลข ADR-007 ในบทที่ 4
- **ชั้น:** หน้าจอ (QML) → `ChatController` (Python, เธรดแยก) → HTTP ผ่าน Unix socket → `llama-server` (โปรเซสของผู้ใช้)

```text
aipc-session (เริ่มเซสชัน)
  └ systemctl --user start aipc-llm      → llama-server -m /opt/aipc-models/<โมเดล>.gguf
                                            --host $XDG_RUNTIME_DIR/aipc/llm.sock -c 4096 -t <3|4>
                                            --no-webui --no-slots   (Restart=on-failure · MemoryMax)
หน้าจอ: ข้อความ → ตัวคัดสกิล → ไม่ตรงสกิล/สกิลแปล → ChatController (เธรดแยก)
         → POST /v1/chat/completions (stream) → token ทีละคำขึ้นจอ · ปุ่มหยุด/Esc = ปิดการเชื่อมต่อ
ออกจากระบบ → KillUserProcesses → llama-server ของคนนั้นหยุด (คนถัดไปใช้ต่อไม่ได้ ไม่มี cache ค้าง)
```

## 4. ข้อมูล

| ข้อมูล | เก็บที่ | เขียนแบบ |
|---|---|---|
| ประวัติแชท (1 ไฟล์ต่อบทสนทนา) | `~/.local/share/aipc/chats/<id>.json` (home 0700) | atomic ทุกครั้งที่ AI ตอบจบ |
| แชทชั่วคราว | หน่วยความจำเท่านั้น | ไม่เขียนดิสก์ |
| ไฟล์โมเดล | `/opt/aipc-models/` (root, อ่านได้ทุกคน · ใช้ร่วมกัน) | ติดตั้งครั้งเดียว ตรวจ sha256 |
| การตั้งค่าโมเดล | `/etc/aipc/llm.conf` (ไฟล์โมเดล, threads, context) | ผู้ดูแลแก้ |

- ไฟดับกลางคำตอบ: บทสนทนาเก็บถึงคำตอบล่าสุดที่จบแล้ว · คำตอบที่ยังไม่จบหาย (บอกในเล่ม)
- ลบ: ปุ่ม "ลบประวัติแชททั้งหมด" ในหน้าตั้งค่า · ลบทีละบทสนทนาในรายการประวัติ

## 5. รอยต่อ (interface)

- `aipc.chat.client`: `stream(messages, on_token, stop: threading.Event) -> Reply(text, finished, reason, timings)` ·
  `health() -> "ready" | "loading" | "down"` · ใช้ `http.client` บน `AF_UNIX` (standard library)
- `aipc.chat.store`: `ChatStore.list() / load(id) / save(conv) / delete(id) / delete_all()`
- `aipc.ui.backend.ChatController` (QML): `send(text)`, `stop()`, `newChat(temporary)`, `openChat(id)` ·
  Property `messages`, `status`, `statusText`, `busy`, `history` · Signal token/finished
- ตัดบริบทให้พอดี context 4096: เก็บ system prompt + ข้อความล่าสุดที่รวมแล้วไม่เกินงบ (ตัดข้อความเก่าสุดออกก่อน · บอกผู้ใช้เมื่อมีการตัด)
- `scripts/pi/session/aipc-llm.service` (user unit) · `scripts/pi/install-llm.sh` (dry-run ก่อน: วางไฟล์โมเดล + ตรวจ sha256 + llm.conf + unit)

## 6. กรณีที่ต้องคิดไว้ก่อน

- **ยังไม่มีโมเดล / service ไม่ทำงาน** → ป้าย "AI ไม่พร้อม: <เหตุผล>" · ข้อความทั่วไปบอกว่าตอบไม่ได้ (เหมือนตอนนี้) · สกิลแบบกฎยังใช้ได้
- **กำลังโหลดโมเดล** (`/health` ตอบ 503) → "กำลังโหลดโมเดล…" · ส่งได้เมื่อพร้อม
- **AI พังกลางคำตอบ** → เก็บส่วนที่ได้ พร้อมป้าย "ตอบไม่จบ: AI หยุดทำงาน" · systemd เปิดใหม่เอง (T7)
- **กดหยุด/Esc** → ปิดการเชื่อมต่อ llama-server หยุดสร้างเอง · เก็บส่วนที่ได้พร้อมป้าย "หยุดแล้ว"
- **บริบทยาวเกิน** → ตัดข้อความเก่า และบอกผู้ใช้
- **RAM ไม่พอ** → `MemoryMax` กันไม่ให้ดึงทั้งเครื่องล่ม · หน้าจอบอกว่า AI หยุดเพราะหน่วยความจำ
- **หลายผู้ใช้** → socket อยู่ในโฟลเดอร์ของแต่ละคน ผู้ใช้อื่นต่อไม่ได้ (T12) · ออกจากระบบแล้ว service หยุด
- **ออฟไลน์** → ไม่ต่างจากออนไลน์ (T5) · ไม่มีการเชื่อมต่อขาออก (T6)
- **บันทึกประวัติไม่ได้** → บอกใต้ช่องแชท · บทสนทนายังอยู่ในหน่วยความจำ

## 7. ต้นทุนบน Pi 5

RAM 1–3.5 GB ขณะโหลดโมเดล (ตาม ADR-007 · ต้องวัด) · CPU 3–4 คอร์ขณะตอบ · ดิสก์: โมเดล 2.5–3.1 GB ใช้ร่วมทุกบัญชี + ประวัติแชทไม่กี่ KB ต่อบทสนทนา ·
เรียก LLM 1 ครั้งต่อข้อความ · โหลดโมเดลตอนเข้าใช้ครั้งแรกของเซสชัน (ต้องวัดเวลาโหลดจาก microSD)

## 8. การทดสอบ และเกณฑ์ผ่าน (ประกาศก่อนสร้าง)

**เทสต์อัตโนมัติ** (server ปลอมผ่าน socket · ไม่ต้องมีโมเดล):
token ขึ้นทีละคำ · หยุดกลางคำตอบ · server ตายกลางคำตอบ · กำลังโหลด (503) · ไม่มี server · ตัดบริบทเมื่อยาวเกิน ·
แชทชั่วคราวไม่เขียนดิสก์ · บันทึก atomic · ลบทั้งหมดแล้วไม่เหลือไฟล์ · Enter/Shift+Enter/IME/Esc · QML ไม่มี warning ทุกสถานะ

**บน Pi 5 (ระดับ 4 · โมเดลตาม ADR-007):**

| เกณฑ์ | ผ่านเมื่อ |
|---|---|
| เวลาถึงคำแรก (prompt 200 token, โมเดลโหลดแล้ว) | ตาม ADR-007 ข้อ 2 (≤ 10 วิ ชั้น 4B) |
| ความเร็วตอบในหน้าจอจริง | ≥ 4 tok/s (ADR-007 ข้อ 3) · หน้าจอยังตอบสนองระหว่าง AI ตอบ |
| ออฟไลน์ / ไม่รั่ว | T5 และ T6 ผ่าน |
| AI พัง | T7: `kill -9` ระหว่างตอบ → กลับมาใช้ได้เอง ≤ 60 วิ |
| ข้ามบัญชี | T12: ผู้ใช้อื่นต่อ socket ไม่ได้ · ออกจากระบบแล้วไม่เหลือ llama-server |
| ตอบต่อเนื่อง 10 นาที | ไม่ throttle · ไม่ล่ม |

## 9. ไม่ทำในรอบนี้

Cloud · ไฟล์แนบ/RAG/OCR · สรุปบทสนทนาเก่า · ลบประวัติอัตโนมัติหลัง N วัน · สลับหลายโมเดล · ให้ LLM เลือกสกิลหรือสั่ง Action · เสียง
