# การ์ดออกแบบ 0023: ขอให้เขียน/แนะนำ/คิด = ทำให้เลย ไม่ถามกลับ

- **สถานะ:** ร่าง · ประกาศเกณฑ์และชุดทดสอบก่อนวัด (2026-10-12 กลางวัน · ผู้ช่วย)
- **ที่มา:** Pakon สั่ง 2026-10-12 "ก่อนถึง 1 ทุ่มคุณก็ทดสอบแล้วแก้งานให้มันดีขึ้นด้วยนะ" · หลังหยุดเพิ่มฟีเจอร์ = แก้พฤติกรรม ไม่ใช่ฟีเจอร์ใหม่
- **ข้อกำหนดที่อ้าง:** BRIEF หัวข้อ 9 (H9 ประกาศเกณฑ์ก่อนวัด · ชุดอิสระ) · การ์ด 0022 (วิธีเดียวกัน)

## 1. ปัญหาที่แก้ และใครใช้

สำรวจบน Pi 5 2026-10-12 ([ผล](../benchmarks/2026-10-12-pi-smoke/README.md)): ขอให้ AI ในเครื่องเขียน/แนะนำ/คิดอะไรที่ทำได้เลย
แต่มันถามกลับแทน 5 ครั้งจาก ~110 ประโยค: "แนะนำเมนูอาหารเย็นง่ายๆ" · "ช่วยคิดชื่อร้านกาแฟให้หน่อย 5 ชื่อ" · "ช่วยเขียนอีเมลขอบคุณลูกค้า" ·
"ช่วยจัดตารางวันหนึ่งให้หน่อย" · "เขียนกลอนสั้นๆ เรื่องฝน 2 บรรทัด" → ผู้ใช้ต้องพิมพ์อีกรอบและรอ AI อีก 10–60 วิ ·
กรรมการลองพิมพ์แบบนี้ในวันสอบได้ง่าย

## 2. สิ่งที่จะเปลี่ยน

เพิ่มประโยคเดียวท้าย `catalog.RULES` (system prompt ของแชท · ตัวเดียวกับที่ชุดสอบและการ์ด 0022 ใช้) · ไม่แก้โค้ดส่วนอื่น ·
ประโยคตั้งต้น (ปรับได้ด้วยชุดพัฒนา D3 ไม่เกิน 3 แบบ):
"ถ้าผู้ใช้ขอให้เขียน แต่ง แนะนำ คิด หรือวางแผนอะไรให้ ให้ทำเลยด้วยตัวเลือกที่เหมาะกับคนทั่วไป ไม่ต้องถามรายละเอียดก่อน
แล้วค่อยบอกสั้น ๆ ว่าปรับได้ · ถามกลับเฉพาะเมื่อขาดสิ่งที่ต้องใช้จริง เช่น ขอให้สรุปหรือแปลแต่ไม่ได้ให้ข้อความมา"

ความเสี่ยง: prompt เปลี่ยน → ผลชุดสอบ 100 ข้อ และการส่งต่อ Claude (การ์ด 0022) อาจเปลี่ยน → วัดซ้ำทั้งสองอย่าง (ข้อ 8)

prompt ยาวขึ้น ~60 token (อ่านครั้งเดียวต่อวัน · แคช) · ไม่เรียก LLM เพิ่ม

## 8. การทดสอบ และเกณฑ์ผ่าน (ประกาศก่อนวัด · H9)

**ชุดข้อมูล** (ผู้ช่วยเขียนทั้งสองชุด = จุดอ่อน: ไม่อิสระเต็มที่ · เขียนในข้อจำกัด):
- D3 `tests/data/askback_d3.json` — ชุดพัฒนา 16 O + 4 N · ใช้เลือกประโยค · ห้ามรายงานเป็นผล
- H4 `tests/data/askback_h4.json` — ชุดทดสอบ 20 O + 6 N · คนละหัวข้อกับ D3 · commit ก่อนรัน D3 · รันครั้งเดียวต่อแบบ
- O = ทำได้เลย ไม่ควรถามกลับ · N = ขาดข้อความ/ไฟล์ที่ต้องใช้จริง ควรถามกลับ

**วิธีวัด:** `aipc.spikes.askback_eval` ขับแอปตัวจริงบน Pi 5 (Gemma 4 E2B · llama-server ตัววัด ค่าเดียวกับแอป) · Claude ปลอม ·
ตัดสินอัตโนมัติ: O ผ่าน = มีงานที่ขอจริง (บรรทัดที่ไม่ใช่คำถาม ≥ min_lines หรือ ตัวอักษร ≥ min_chars ตามที่เขียนไว้ในชุด) ·
N ผ่าน = ถามหาสิ่งที่ขาด (มี ? หรือ กรุณา/รบกวน/โปรด + พูดถึงข้อความ/ไฟล์/โค้ด…) และยาวไม่เกิน 400 ตัวอักษร ·
แต่ละแบบ (prompt เดิม / ใหม่) รันชุดละครั้ง ในวันเดียวกัน

| # | เกณฑ์ | ผ่านเมื่อ |
|---|---|---|
| 1 | H4 กลุ่ม O (ทำให้เลย) | แบบใหม่ ≥ 15/20 **และ** มากกว่าแบบเดิม ≥ 5 ข้อ |
| 2 | H4 กลุ่ม N (ถามเมื่อขาดจริง) | แบบใหม่ ≥ 5/6 |
| 3 | ชุดสอบ 100 ข้อ (`aipc.spikes.exam` ในเครื่องล้วน) | แบบใหม่ผ่านเกณฑ์เดิมของชุดสอบ (บอกตรง ≥ 90% · สกิลถูก ≥ 80% · แต่ง ≤ 5%) **และ** ข้อที่ตอบถูก (must_any) ไม่น้อยกว่าแบบเดิมที่รันวันเดียวกันเกิน 2 ข้อ |
| 4 | การส่งต่อ Claude: H3 ของการ์ด 0022 (24 ข้อ · Claude ปลอม) | แบบใหม่ ข้อมูลล่าสุดส่งต่อ ≥ 11/12 · ความรู้ส่งผิด ≤ 1/12 (เกณฑ์เดิมของ H3) |

**ไม่ผ่านข้อใดข้อหนึ่ง = ไม่ใส่ในแอป** · บันทึกผลทุกครั้ง รวมรอบที่ใช้ไม่ได้ ·
ผ่านทุกข้อ = ใส่ใน `catalog.RULES` + เทสต์ที่ล็อกประโยค + ติดตั้งบน Pi + เขียนในเล่มว่า prompt เปลี่ยนหลังวัดชุดสอบรอบแรก (ตัวเลขชุดสอบที่ใช้ในเล่มต้องเป็นรอบที่ตรงกับ prompt ที่ส่ง)

## 9. เปลี่ยนจากที่ประกาศ (บันทึกก่อนรัน H4)
