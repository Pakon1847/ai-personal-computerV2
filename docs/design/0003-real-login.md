# การ์ดออกแบบ 0003: หน้า Login ของ V2 เป็นหน้า login จริงของเครื่อง

- **สถานะ:** รออนุมัติ
- **ข้อกำหนดที่อ้าง:** BRIEF 5.1 (Login) · DESIGN.md H1 H2 H3 H5 H7 · การ์ด 0002 (หน้าตา Login) · runbook [pi4-switch-to-v2](../runbooks/pi4-switch-to-v2.md)

## 1. ปัญหาที่แก้ และใครใช้

ผู้ใช้สั่ง (2026-09-23) ให้เอาหน้า login ของระบบเก่าออก แล้วใช้หน้า Login ที่ออกแบบใน V2
ตอนนี้ Login ของ V2 **ไม่ตรวจรหัสผ่านเลย** (นอกโหมดพัฒนาปฏิเสธทุกครั้ง) จึงใช้เข้าเครื่องจริงไม่ได้
ผู้ใช้คือทุกคนที่เปิดเครื่อง Pi

## 2. หลักการที่ใช้ตัดสิน

| หลักการ | ใช้ยังไง |
|---|---|
| H7 backend ตัดสิน / H1 ความปลอดภัย | **โค้ดเราไม่ตรวจรหัสผ่านเอง** · greetd ส่งให้ PAM ของ OS ตรวจ (ชุดเดียวกับ login ปกติ) · หน้าจอแค่ส่งข้อความไป-กลับ |
| H3 ความเป็นส่วนตัว | ไม่เก็บ ไม่ log รหัสผ่าน · ล้างช่องรหัสผ่านทันทีหลังส่ง · ข้อความผิดพลาดไม่บอกว่า "ไม่มีผู้ใช้นี้" หรือ "รหัสผิด" แยกกัน |
| H5 ความจริง | ใบหน้ายังไม่มีระบบจริง → วงกล้องบอก "ยังไม่พร้อม" และไม่มีทางลัดเข้าด้วยใบหน้า · แถบ "โหมดพัฒนา" ไม่แสดงในโหมดจริง |
| H2 ไม่ทิ้งงานเงียบ ๆ | ถ้าหน้า Login ของเราพัง ต้องยังมีทางเข้า: คอนโซลตัวหนังสือ (Ctrl+Alt+F2) + SSH · ตรวจทั้งสองทางก่อนสลับ |
| ไม่ทำให้เครื่องพัง (กติกาผู้ใช้) | สลับด้วยการแก้ไฟล์ config ไฟล์เดียวที่สำรองไว้ · มีสคริปต์ย้อนกลับ · dry-run ก่อนเสมอ · ไม่ถอนแพ็กเกจ ไม่แตะไฟล์บูต |

## 3. ทางเลือก

| ทางเลือก | ข้อดี | ข้อเสีย |
|---|---|---|
| **ก. greetd + หน้า Login QML ของเราเป็น greeter (เลือก)** | greetd มีบน Pi แล้ว (ระบบเก่าใช้อยู่) · โปรโตคอลง่าย (JSON ผ่าน socket) · PAM ทำงานตรวจทั้งหมด | ต้องติดตั้งแอปไว้ที่ที่ผู้ใช้ `_greetd` อ่านได้ (ไม่ใช่ใน home) |
| ข. lightdm + greeter ของเรา | lightdm เป็นค่าเริ่มต้นของ Raspberry Pi OS | ต้องใช้ liblightdm-gobject ผ่าน GObject · ซับซ้อนกว่ามาก ทดสอบบนวินโดวส์ไม่ได้ |
| ค. คง login ปกติของ OS แล้วเปิด V2 หลังเข้า (ที่ทำไว้แล้วใน install-ui.sh) | ปลอดภัยที่สุด | ผู้ใช้ไม่ได้เห็นหน้า Login ที่ออกแบบตอนเปิดเครื่อง — ไม่ตรงคำสั่ง |

## 4. ความสัมพันธ์กับชิ้นส่วนอื่น

- **พึ่ง:** greetd + cage บน Pi (ต้องยืนยันจากผล `check-old-system.sh`) · PySide6 ที่ผู้ใช้ `_greetd` ใช้ได้ (glibc ≥ 2.39 ถ้าใช้ pip)
- **มีคนพึ่ง:** การ์ด 0001 นัดหมาย (เตือนหลังเข้าใช้ · Logout = ไม่เตือน) · ระบบใบหน้า (เฟส 2) จะมาต่อเป็นขั้นก่อนรหัสผ่าน · การสมัครบัญชีจริง (การ์ดแยก)
- **ชั้น:** หน้าจอ (greeter) + ตัวต่อ greetd ใน Python · รันเป็นผู้ใช้ `_greetd` ใน cage ก่อนมีใครเข้าเครื่อง

```
เปิดเครื่อง → greetd → cage → aipc.ui --greeter (ผู้ใช้ _greetd)
              ↑  socket ($GREETD_SOCK)  ↓ ชื่อ + รหัสผ่าน
              PAM ตรวจ ← greetd          ↓ ผ่าน
              greetd เริ่มเซสชันของผู้ใช้ (labwc) → หน้าจอ V2 เปิดเอง (install-ui.sh)
```

## 5. ข้อมูล

ไม่เก็บอะไรใหม่ · รหัสผ่านอยู่ในหน่วยความจำแค่ช่วงส่งให้ greetd · ชื่อผู้ใช้ล่าสุด: **ไม่จำ** ในรอบนี้

## 6. รอยต่อ

`aipc.login.greetd` (Python ล้วน ทดสอบได้ด้วย socket ปลอม):

- `Greetd(sock_path)` · `create_session(user)` → `AuthPrompt(kind, text)` | `Success` | `Failure(text)`
- `answer(response)` → เหมือนกัน (PAM อาจถามหลายรอบ เช่น รหัสหมดอายุ)
- `start(cmd, env)` · `cancel()`
- ข้อความ: ความยาว u32 (native endian) + JSON ตามโปรโตคอล greetd IPC
- `LoginController` ใน backend: ถ้ามี `$GREETD_SOCK` → ใช้ greetd จริง · ไม่มี → พฤติกรรมเดิม (dev/ปฏิเสธ)

## 7. กรณีที่ต้องคิดไว้ก่อน

- รหัสผิด → greetd ตอบ error → ยกเลิกเซสชัน, แสดง "ชื่อผู้ใช้หรือรหัสผ่านไม่ถูกต้อง", ล้างช่องรหัสผ่าน
- PAM ถามคำถามที่ไม่ใช่รหัสผ่าน (info/error/visible) → แสดงตามจริง ไม่เดา
- กดผิดหลายครั้ง → ให้ PAM (faillock ถ้าเปิด) ตัดสิน ไม่ทำกลไกล็อกเอง
- greetd socket หาย/ตอบผิดรูปแบบ → แสดงข้อผิดพลาด + บอกทางเข้าสำรอง Ctrl+Alt+F2
- หน้าจอเราพังตอนบูต → greetd รัน greeter ใหม่ · ถ้ายังพัง ใช้คอนโซล/SSH แล้วรันสคริปต์ย้อนกลับ
- ปุ่มปิดเครื่อง: `systemctl poweroff` ต้องได้สิทธิ์จาก polkit ของ `_greetd` → **ยังไม่รู้** ว่าได้ไหม ตรวจบน Pi · ถ้าไม่ได้ ปุ่มคงสถานะ "ยังไม่พร้อม"
- สมัครบัญชีจากหน้า Login ยังสร้างบัญชีจริงไม่ได้ → ในโหมดจริงปุ่มบอก "ยังไม่พร้อม" (ไม่ปล่อยให้กรอกแล้วหายเงียบ)

## 8. ต้นทุนบน Pi

greeter ทำงานเฉพาะก่อนเข้าเครื่อง แล้วปิดไป · RAM ขณะรัน: **ยังไม่รู้** วัดบน Pi 4 · ไม่เรียก LLM

## 9. การทดสอบ และเกณฑ์ผ่าน (ประกาศก่อนสร้าง)

- เทสต์ตัวต่อ greetd กับ server ปลอม: สำเร็จ / รหัสผิด / PAM ถามหลายรอบ / ข้อความ info / ยกเลิก / socket ตอบผิดรูปแบบ
- เทสต์ว่ารหัสผ่านไม่ถูกเขียนลง log หรือไฟล์ใด ๆ
- เทสต์ QML: โหมด greeter ไม่มีแถบโหมดพัฒนา, ปุ่มสมัครบอกยังไม่พร้อม
- บน Pi 4 (Pakon ทดสอบ ตาม runbook): รหัสถูก → เข้าเดสก์ท็อป · รหัสผิด → อยู่หน้าเดิมพร้อมข้อความ · รีบูต 3 ครั้งขึ้นหน้า Login ของเราทุกครั้ง · สคริปต์ย้อนกลับคืนหน้าเดิมได้
- เกณฑ์: ผ่านครบทุกข้อบน Pi 4 ก่อนนับว่าเสร็จ

## 10. ไม่ทำในรอบนี้

- เข้าด้วยใบหน้า (ยังไม่มีระบบใบหน้า — เฟส 2)
- สมัครบัญชีจริงจากหน้า Login (ต้องใช้สิทธิ์ root สร้างบัญชี → การ์ดแยก)
- สลับผู้ใช้ / ล็อกหน้าจอ
- เอาระบบเก่า "ai computer" ออกทั้งหมด (/opt/ai-pc ฯลฯ) — ทำหลังหน้า Login ใหม่ผ่านบน Pi แล้ว เพื่อให้ย้อนกลับได้เสมอ
