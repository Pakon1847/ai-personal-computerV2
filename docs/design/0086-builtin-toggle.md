# การ์ดออกแบบ 0086: เปิด/ปิดสกิลในตัว

- **สถานะ:** อนุมัติ (Pakon 2026-11-22 "อนุมัติ" · หัวข้อ 10 ตามคำแนะนำ)
- **ที่มา:** อาจารย์ขอ "ระบบ skill รองรับ เพิ่ม แก้ไข ลบ **เปิด/ปิด** แชร์" (Pakon สรุปมา 2026-11-20) · ตอนนี้เปิด/ปิดได้เฉพาะสกิลที่ Claude สร้าง (`setSkillEnabled` ยอมเฉพาะ `_is_user`) · Pakon ตัดสิน 2026-11-20 ให้แยกเป็นการ์ดเล็ก (การ์ด 0085 หัวข้อ 10)
- **ข้อกำหนดที่อ้าง:** SKILLS.md · การ์ด 0078 (จัดการสกิลครบวงจร) · 0027 (คีย์ลัดเสียง = สั่งงาน)

## 1. ปัญหาที่แก้ และใครใช้

ผู้ใช้ที่ไม่อยากให้สกิลในตัวบางตัวทำงาน (เช่น ไม่ใช้ Spotify · ไม่อยากให้พิมพ์แล้วสั่งเครื่อง) ปิดได้เองในหน้า Skill · ปิดแล้วเปิดคืนได้ทุกเมื่อ · มีผลเฉพาะบัญชีของคนนั้น

## 2. หลักการที่ใช้ตัดสิน

| หลักการ | ใช้ยังไง |
|---|---|
| H2 ไม่ทำงานหาย | ปิด ≠ ลบ · ไฟล์สกิลในตัวไม่ถูกแตะ (อยู่ใน git) · เปิดคืน = เหมือนเดิมทุกอย่าง |
| H5 ความจริง | สั่งงานของสกิลที่ปิด = บอกว่า "ปิดสกิล … ไว้ เปิดได้ที่หน้า Skill" ไม่ใช่ทำเงียบ ๆ หรือส่งให้ AI เดาแทน |
| H6 โค้ดตัดสิน | รายการสกิลที่ปิดใช้กรองในโค้ดก่อนถึงตัวคัดสกิล · AI ในเครื่องไม่เห็นสกิลที่ปิด |
| H7 backend ตัดสิน | หน้าจอส่งแค่ id + เปิด/ปิด · Python ตรวจว่าเป็นสกิลในตัวจริง |

## 3. ความสัมพันธ์กับชิ้นส่วนอื่น

- **พึ่ง (มีแล้ว):** `SkillsController._skills` (รายการที่ตัวคัดสกิลใช้) · หน้า Skill ส่วน "สกิลในเครื่อง" · `userskills` (ดัชนีต่อผู้ใช้)
- **กลไกหลัก:** กฎในตัวคัดสกิลผูกกับสกิลในรายการ (เช่น `router.py` ใช้คำสั่งเครื่องเมื่อ `"system-command" in by_id`) → **เอาสกิลที่ปิดออกจากรายการที่เดียว** = กฎ เครื่องมือของ AI และการเลือกสกิลปิดตามพร้อมกัน
- **ต้องแก้ตาม:** คีย์ลัดเสียง (`handsfree.route`) เรียก `command.parse` ตรง ไม่ผ่านรายการสกิล → ต้องเช็กรายการที่ปิดด้วย ไม่งั้นปิด "สั่งเครื่อง" แล้วพูดยังทำได้
- **ไม่กระทบ:** การเตือนนัดที่ถึงเวลา (ตัวจับเวลา 30 วิ ไม่ใช่สกิล) · หน้าปฏิทิน · ปุ่มย้อนกลับของคำสั่งที่ทำไปแล้ว

## 4. ข้อมูล

- **เก็บอะไร:** รายการ id สกิลในตัวที่ผู้ใช้ปิด (เช่น `["spotify-voice"]`) · ไม่มีข้อมูลส่วนตัวอื่น
- **เก็บที่ไหน:** ดัชนีสกิลของผู้ใช้เดิม (`userskills` · โฟลเดอร์ใน home 0700) คีย์ใหม่ `builtin_off` · เขียนแบบไฟล์ชั่วคราวแล้วเปลี่ยนชื่อ (กลไกเดิม)
- **ไฟล์เสีย / ไม่มีไฟล์:** ถือว่าเปิดทุกตัว (ค่าเริ่มต้นปลอดภัย = ระบบทำงานตามเดิม)
- **ลบบัญชี:** หายไปกับ home (ไม่ต้องแก้ตัวลบบัญชี)

## 5. รอยต่อ

- QML: `skills.setSkillEnabled(id, on)` เดิม → รับสกิลในตัวด้วย · `skills.skills` เพิ่มช่อง `enabled` · สวิตช์ในการ์ดสกิลในตัว
- Python: `UserSkills.builtin_off() -> set[str]` · `UserSkills.set_builtin(id, on) -> bool` · `SkillsController._reload()` = `[ในตัวที่ไม่ได้ปิด] + สกิลผู้ใช้`
- ทางคีย์ลัด: `handsfree.route(..., off=set)` → คำสั่งของสกิลที่ปิด = `DISABLED` (บอกเหตุผล)

## 6. กรณีที่ต้องคิดไว้ก่อน

- ปิดสกิลที่สกิลผู้ใช้ใช้อยู่ (เช่น สกิลโหมดที่มีขั้น "ปิดเสียง") → ขั้นคำสั่งเครื่องของสกิลผู้ใช้ยังทำงาน (เป็นขั้นของสกิลนั้น ไม่ใช่การเรียกสกิลในตัว) · บอกในหน้า Skill (หัวข้อ 10)
- ปิดสกิลนัดหมาย → พิมพ์ "เตือนพรุ่งนี้…" = บอกว่าปิดไว้ · นัดที่จดไว้แล้วยังเตือนตามเวลา
- ปิดครบทุกตัว → แชทกับ AI ในเครื่องยังใช้ได้ · Claude สร้างสกิลยังได้ (หัวข้อ 10)
- Claude สร้างสกิลใหม่ที่ซ้ำงานของสกิลในตัวที่ปิด → ด่านเดิม "ไม่แย่งคำสั่ง" ตรวจกับรายการที่ใช้จริง (หัวข้อ 10)
- หลายผู้ใช้ → ของใครของมัน (ดัชนีอยู่ใน home)

## 7. ต้นทุนบน Pi 5
