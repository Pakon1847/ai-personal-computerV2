## 1. ปัญหาที่แก้ และใครใช้

ผู้ใช้แต่ละบัญชีอยากรู้ "วันนี้/พรุ่งนี้/สัปดาห์นี้มีอะไร" จากนัดในเครื่องและจาก Google Calendar ของตัวเอง โดยไม่ต้องเปิดเว็บ

## 2. หลักการที่ใช้ตัดสิน

| หลักการ | ใช้ยังไงในฟีเจอร์นี้ |
|---|---|
| **H6** งานต้องถูกแน่นอนใช้โค้ด | **โค้ดเปิดปฏิทิน ไม่ใช่ AI**: ค้นนัดตามช่วงวันด้วยโค้ด ตอบทันที ไม่ตกหล่น · AI อ่าน prompt ได้ 8–12 token/วิ (นัด 10 รายการ = รอ 25–40 วิ) และอาจแต่งนัด |
| **H8** ข้อมูลไม่ใช่คำสั่ง | ชื่อนัดที่คนอื่นเชิญมาเป็นข้อความจากภายนอก · ถ้าส่งให้ AI ("ช่วยวางแผน") = ข้อมูล · AI แก้/ลบนัดไม่ได้ |
| **H3/H4** ส่วนตัว + local | ปฏิทินอยู่ใน home ของคนนั้น · ลิงก์ Google เป็นกุญแจอ่านปฏิทิน → 0600 · ไม่ลง log |
| **H5** ความจริง | บอกว่าซิงก์ล่าสุดเมื่อไหร่ · ซิงก์ไม่ได้ = บอก ไม่ทำเป็นว่าเป็นข้อมูลล่าสุด |
| **H1** ข้อมูลปลอดภัย | เขียนแบบ atomic (`fsutil.write_json`) · สำเนา Google เก็บแยกจากนัดที่ผู้ใช้จดเอง |

## 3. ความสัมพันธ์กับชิ้นส่วนอื่น

- **พึ่ง:** `when.py` (อ่านวันเวลาไทย · มีแล้ว) · สกิลนัดหมาย (มีแล้ว · นัดที่จดเองคือแหล่งหนึ่งของปฏิทิน) · สกิล `.md` (มีแล้ว)
- **มีคนพึ่ง:** หน้าแรก (การ์ด "วันนี้") · สกิลร่างจดหมาย ("เขียนอีเมลขอเลื่อนประชุมพรุ่งนี้" → โค้ดหานัด → AI ร่าง)
- **ชั้น:** หน้าจอ (การ์ด) → `SkillsController` → `aipc.skills.calendar` (Python ล้วน) → ไฟล์ใน home · ซิงก์: `urllib` HTTPS

## 4. ข้อมูล

| ข้อมูล | เก็บที่ | เขียนแบบ |
|---|---|---|
| วันสำคัญที่ผู้ใช้จด (วันเดียว/ทุกปี) | `~/.local/share/aipc/calendar.json` | atomic · ยืนยันก่อนบันทึก (แบบนัดหมาย) |
| ลิงก์ "ที่อยู่ลับในรูปแบบ iCal" | `~/.config/aipc/calendar-links.json` (0600) | atomic · แสดงแค่โดเมน + 4 ตัวท้าย |
| สำเนาจาก Google (ช่วง −7 ถึง +60 วัน) | `~/.cache/aipc/calendar-google.json` | atomic · เวลาซิงก์ล่าสุด · ลบแล้วซิงก์ใหม่ได้ |

- ไฟดับกลางซิงก์: ไฟล์สำเนาเดิมยังอยู่ (atomic) · ลบ: ปุ่ม "ลบการเชื่อมต่อ Google" + "ลบวันสำคัญทั้งหมด" ในหน้าตั้งค่า

## 5. รอยต่อ (interface)

- `calendar.agenda(start: date, end: date, now) -> list[Event]` · `Event(when, title, all_day, source: "local" | "google")`
- `calendar.parse_ics(text, window) -> list[Event]` · รองรับ `RRULE` รายวัน/สัปดาห์/เดือน/ปี · `EXDATE` · วันทั้งวัน · เขตเวลา ·
  เลือกไลบรารีอ่าน .ics ที่รองรับนัดซ้ำ → ตรวจไลเซนส์ + เพิ่มแถว ADR-014 + ล็อกใน `constraints.txt` · ไม่เจอที่เหมาะ = เขียนชุดย่อยเอง
- `calendar.sync(link) -> SyncResult(ok, count, message, at)` · เรียกตอนเข้าสู่ระบบ + ปุ่ม "ซิงก์ตอนนี้" (เธรดแยก)
- สกิล `calendar.md` (worker code) · คำถาม: "วันนี้ / พรุ่งนี้ / สัปดาห์นี้ / เดือนนี้ มีอะไร" · บันทึก: "<วัน> <เรื่อง> [ทุกปี]"
- QML: การ์ด "วันนี้" ในหน้าแรก · หน้าตั้งค่า: เพิ่ม/ลบลิงก์ · ซิงก์ล่าสุดเมื่อ … · ซิงก์ตอนนี้

## 6. กรณีที่ต้องคิดไว้ก่อน

- **ไม่มีเน็ต** → ใช้สำเนาล่าสุด + ป้าย "ซิงก์ล่าสุด … (ออฟไลน์)" (T5)
- **ลิงก์ผิด / ถูกรีเซ็ตใน Google / บัญชีองค์กรปิดตัวเลือกนี้** → บอกเหตุผล · แนะนำใช้ Gmail ส่วนตัว
- **ไฟล์ .ics ใหญ่หรือผิดรูป** → จำกัด 5 MB · อ่านเฉพาะช่วง −7/+60 วัน · อ่านไม่ได้ = ไม่ทับสำเนาเดิม
- **ชื่อนัดมีข้อความหลอก** (T6 prompt injection) → แสดงเป็นข้อความ · ส่งให้ AI เฉพาะตอนผู้ใช้กด "ช่วยวางแผน" และเป็นข้อมูล
- **ประโยคบอกวันเวลา** → ตัวคัดสกิลส่งไปนัดหมายก่อน (router ข้อ 2) · คำถาม "มีอะไร" ไม่ใช่การจด จึงไม่ชน (is_question)
- **หลายผู้ใช้** → ไฟล์และลิงก์อยู่ใน home ของแต่ละคน (T12) · ออกจากระบบแล้วไม่เหลือโปรเซสซิงก์ (KillUserProcesses)
- **นาฬิกาเครื่องผิด** → ใช้คำเตือนเดิมของสกิลนัดหมาย (เวลาถอยหลัง)

## 7. ต้นทุนบน Pi 5

RAM < 20 MB · CPU: อ่าน .ics ไม่กี่ร้อยนัด < 1 วิ · ดิสก์ < 1 MB · **เรียก LLM 0 ครั้ง** (ยกเว้นผู้ใช้กด "ช่วยวางแผน") ·
เน็ต: ดาวน์โหลด .ics ตอนเข้าสู่ระบบ/กดซิงก์ (ไม่กี่ร้อย KB)

## 8. การทดสอบ และเกณฑ์ผ่าน (ประกาศก่อนสร้าง)

- เทสต์อัตโนมัติ: ไฟล์ .ics ตัวอย่าง (นัดซ้ำ · EXDATE · วันทั้งวัน · เขตเวลา · ข้ามปี · ไฟล์เสีย) · agenda ตามช่วงวัน ·
