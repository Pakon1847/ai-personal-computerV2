## 5. รอยต่อ

- ① ไทล์สกิลประจำเว็บ: `id = "site:<เว็บ>"` · ชื่อ = ชื่อเว็บ (`SITES`) · ตัวอย่าง = คำพูด 2 คำแรก · `commands` = ทุกคำสั่งของทุกสกิลของเว็บนั้น
  ต่อท้ายที่มา เช่น `“พอแค่นี้ก่อน” → ทำคำสั่ง “หยุดคลิป” · Claude สร้าง` · ใช้ได้ถ้ามีอย่างน้อย 1 สกิลที่ใช้ได้ · สกิลอื่น (ไม่ใช่ประจำเว็บ) ไม่เปลี่ยน
- ② หน้าปฏิทิน ยังไม่เชื่อม → แถบ "ยังไม่ได้เชื่อมปฏิทิน Google · [เชื่อมปฏิทิน Google]" → พาไปหน้าตั้งค่า เปิดการ์ดปฏิทินไว้ ·
  เชื่อมแล้ว → แถบหายไป (จุดสีปฏิทิน Google ในหน้าปฏิทินมีอยู่แล้ว)

## 6. กรณีที่ต้องคิดไว้ก่อน

- เว็บเดียวมีหลายสกิล และบางสกิลปิดอยู่ → ไทล์แสดงเฉพาะคำสั่งของสกิลที่เปิดอยู่ · บอกจำนวนสกิลที่ปิด
- คำพูดเดียวกันอยู่สองสกิล → แสดงทั้งคู่ตามจริง (ตัวที่ทำงานคือตัวที่ `sitecmd.match` เจอก่อน · บอกที่มา)
- หน้าจออังกฤษ: ชื่อเว็บไม่ต้องแปล · ข้อความแถบปฏิทินเพิ่มใน `i18n/en.json`
- ตัวกรอง "ใช้ได้แล้ว / ยังไม่พร้อม" นับไทล์รวมเป็น 1

## 8. การทดสอบ และเกณฑ์ผ่าน (ประกาศก่อนสร้าง)

- **G1 (เทสต์อัตโนมัติ):** มีสกิลประจำเว็บ YouTube 2 ตัว + Spotify 1 ตัว → ไทล์ประจำเว็บ = 2 (YouTube · Spotify) · คำสั่ง YouTube ครบทั้งสองสกิลพร้อมที่มา ·
  สกิลที่ปิด = ไม่นับคำสั่ง · สกิลอื่นไม่เปลี่ยน · `userSkills` ยังแยกทีละสกิล
- **G2 (เทสต์ QML):** หน้าปฏิทิน ยังไม่เชื่อม = เห็นแถบ + ปุ่มพาไปหน้าตั้งค่า · เชื่อมแล้ว = ไม่เห็นแถบ · ภาษาอังกฤษมีคำแปล
- **G3 (Pi 5 · Pakon ที่จอ):** หน้า Skill เห็น YouTube ไทล์เดียว แตะแล้วเห็นคำสั่งทั้งหมด · หน้าปฏิทินกดปุ่มแล้วไปถึงการ์ดเชื่อมปฏิทิน
- เทสต์ทั้งชุดผ่าน (วินโดวส์ + Pi 5)

- **ผล G1 ✅ G2 ✅ (2026-10-27 · วินโดวส์):** YouTube (ระบบ + ของผู้ใช้) + Spotify = ไทล์ประจำเว็บ 2 · คำสั่งครบพร้อมที่มา · สกิลที่ปิด = ไม่นับ ·
  "สกิลของฉัน" ยังทีละสกิล · แถบปฏิทินขึ้น/หายตามการเชื่อม · ปุ่มพาไปหมวด "AI และอินเทอร์เน็ต" + เปิดขั้นตอนเชื่อม · คำแปลอังกฤษ ·
  ไม่ได้เลื่อนหน้าไปที่การ์ดเอง (หมวดนั้นมีหลายการ์ด อาจต้องเลื่อนลง) · ทั้งชุด **1332 ผ่าน · ข้าม 19** · ระดับ 3
