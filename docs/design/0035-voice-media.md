# การ์ดออกแบบ 0035: คุมเพลง/วิดีโอด้วยเสียง (ข้อ D)

- **สถานะ:** **อนุมัติ (Pakon 2026-10-15 ~22:00 · "อนุมัติ" ทั้ง 0032–0038)** · ร่าง (2026-10-15 ~21:30 · ผู้ช่วย) · Pakon สั่ง "ที่ต่อยอดได้ทำมาทั้งหมดเลย" (2026-10-15) ·
  สาขา `feature/0035-voice-media` (ต่อจาก 0031 · ต้องให้ YouTube เปิดในเบราว์เซอร์ของผู้ช่วย) · ไม่ติดตั้ง/ไม่รวมเข้า master จนกว่าผ่านหัวข้อ 8 และ Pakon อนุมัติ
- **ข้อกำหนดที่อ้าง:** การ์ด 0024/0027 (กฎคำสั่งเว็บ · คีย์ลัดสั่งงานอย่างเดียว) · 0026 (hotwords) · 0031 · H6 H8 H9

## 1. ปัญหาที่แก้ และใครใช้

เปิด "โหมดฟังเพลง" ได้ แต่สั่งหยุด/เล่นต่อ/ข้ามเพลงด้วยเสียงไม่ได้ (ผลสำรวจ YouGov 2025: เปิดเพลงด้วยเสียง 51%) ·
**อธิบายกรรมการ:** "กฎในโค้ดจับคำสั่ง แล้วสั่งตัวเล่นวิดีโอในหน้าเว็บผ่านช่องควบคุมของ Chrome เหมือนคำสั่งเลื่อนหน้า"

## 2. หลักการที่ใช้ตัดสิน

| หลักการ | ใช้ยังไง |
|---|---|

`browse.parse` (ชนิดคำสั่งใหม่ `media`) · `BrowserControl` (CDP) · `zipformer.FIXED` (hotwords) · 0031 (เบราว์เซอร์ตัวเดียว)

## 4. ข้อมูล

ไม่เก็บอะไร

## 5. รอยต่อ

- หยุด: "หยุดเพลง / หยุดวิดีโอ / หยุดคลิป / หยุดชั่วคราว / พักเพลง" → `video.pause()` ของตัวเล่นที่กำลังเล่น (ใช้ได้ทุกเว็บที่มี `<video>`/`<audio>`)
- เล่นต่อ: "เล่นต่อ / เล่นเพลงต่อ / เล่นวิดีโอต่อ" → `play()`
- ถัดไป: "เพลงถัดไป / คลิปถัดไป / วิดีโอถัดไป / ข้ามเพลง" → YouTube: Shift+N (ส่งปุ่มผ่าน CDP) · ไม่ได้ผลกดปุ่ม "ถัดไป" ของตัวเล่น ·
  **ยังไม่รู้** ว่า Shift+N ยังใช้ได้ (หน้าช่วยเหลือของ YouTube ยืนยันแค่ปุ่ม k · Shift+N มาจากคู่มือของคนอื่น) → ตรวจบน Pi ในข้อ 8.3
- ผลบอกตามจริง: ไม่มีวิดีโอในหน้า = "หน้านี้ไม่มีเพลงหรือวิดีโอ" · เล่นต่อไม่ได้ (เว็บไม่ยอม) = บอก

## 6. กรณีที่ต้องคิดไว้ก่อน

"หยุดเพลงตอนสามทุ่ม" = งานให้ทำทีหลัง (ส่งสกิลนัด ตามกฎเดิม) · ไม่ได้เปิดเบราว์เซอร์ของผู้ช่วย = "ยังไม่ได้เปิดเพลงในเบราว์เซอร์ของผู้ช่วย" ·
โฆษณา YouTube กำลังเล่น = หยุด/เล่นต่อได้ · **ไม่ทำ "ข้ามโฆษณา"**

## 7. ต้นทุนบน Pi 5

~0 · LLM 0
