- **สถานะ:** **อนุมัติแล้ว 2026-10-26 (Pakon) · เลือกทาง A** · กำลังสร้าง · Pakon ขอ "ให้มันใช้คำสั่งเสียงได้ใน Chromium ปกติ"
- **ที่มาของโค้ด:** คำสั่ง "เข้าสู่ระบบยูทูบ" เขียนโดย Claude Code บน Pi (บัญชี pakon · `~/aipc-work` สาขา `feature/youtube-login` `af56f94` · 2026-10-26) ·
  นำเข้าเฉพาะ `control.py` `browse.py` และเทสต์ 2 ไฟล์ (ไม่เอา `__pycache__`) · การ์ดร่างแบบส่วนขยาย (`0064-normal-chromium-extension` บน Pi) **ไม่ใช้** (Pakon เลือกทาง A แทน)
- **ข้อกำหนดที่อ้าง:** [การ์ด 0031](0031-web-apps.md) ข้อ 0 (หน้าต่างบัญชี) · [0024](0024-voice-browser.md) · [0046](0046-site-skills.md) สกิลประจำเว็บ · H1 H5 H7 H8
- **หลังวันหยุดเพิ่มฟีเจอร์** → อยู่บนสาขา `feature/0064-voice-account-window` · ไม่ติดตั้งบน Pi และไม่รวม master จนกว่าผ่านเกณฑ์ + Pakon อนุมัติ (กฎเหล็กข้อ 2)

## 1. ปัญหาที่แก้ และใครใช้

**YouTube:** เบราว์เซอร์ของผู้ช่วยเข้าสู่ระบบ Google ไม่ได้ → หน้าแรก YouTube ว่าง → "เปิดคลิปแรก" ตอบ "หน้านี้ไม่มีคลิปให้เลือก" (ตรวจ 2026-10-26: โปรไฟล์ไม่มีคุกกี้เข้าสู่ระบบ Google) ·
**Gmail/ปฏิทิน/ไดรฟ์/เอกสาร:** ผู้ใช้ที่เปิดเว็บเหล่านี้ ตอนนี้ได้หน้าต่างบัญชี (Chromium ไม่ถูกคุม เพราะ Google ไม่ยอมให้เข้าสู่ระบบในเบราว์เซอร์ที่ถูกโปรแกรมคุม · 0031 ข้อ 0)
แต่**สั่งด้วยเสียงต่อในหน้านั้นไม่ได้** (`ACCOUNT_NOTE` ใน `src/aipc/skills/actions.py:198` · `sitecmd.py:118`)

## 5. ทางเลือก (ต้องเลือกก่อนสร้าง)

| | ทาง A: เข้าสู่ระบบแบบปกติ แล้วค่อยคุม | ทาง B: ส่งปุ่มคีย์บอร์ดด้วย `wtype` |
|---|---|---|
| ทำยังไง | ครั้งแรกเปิด Chromium ไม่ถูกคุมให้ผู้ใช้เข้าสู่ระบบ Google → ปิด → เปิดโปรไฟล์เดิมแบบถูกคุม (pipe) ใช้คำสั่งเสียงเต็มรูปแบบเหมือน YouTube | Chromium ยังไม่ถูกคุม · คำพูด → ปุ่มคีย์ลัด เช่น เลื่อนลง ย้อนกลับ รีเฟรช แท็บใหม่ · Gmail: `c` เขียนใหม่ `/` ค้นหา `j/k` ฉบับถัดไป |
| ทำได้ | ทุกอย่างที่เบราว์เซอร์ของผู้ช่วยทำได้ (อ่านหน้า · คลิก · สกิลประจำเว็บ) | เฉพาะคำสั่งที่เป็นปุ่ม · **อ่านเนื้อหาหน้าไม่ได้** |
| ความเสี่ยง | **ยังไม่รู้** ว่า Google ยอมให้คุกกี้ที่เข้าสู่ระบบแล้วใช้ต่อในเบราว์เซอร์ที่ถูกคุมไหม หรือจะเตะออก / ตั้งธงบัญชี | ปุ่มอาจไปโดนหน้าต่างอื่นถ้าโฟกัสเปลี่ยน (H1) → ต้องเรียกหน้าต่างบัญชีขึ้นหน้าก่อนส่งทุกครั้ง และใช้เฉพาะปุ่มที่ไม่ทำลายข้อมูล |
| dependency | ไม่เพิ่ม | `wtype` มีบน Pi 5 แล้ว (`/usr/bin/wtype` · ตรวจ 2026-10-26) แต่ยังไม่อยู่ในรายการติดตั้ง/ไลเซนส์ของโปรเจกต์ → **ต้องถามก่อน** (กฎเหล็กข้อ 5) |
| โค้ด | น้อย (เปลี่ยนลำดับเปิดหน้าต่าง + `SYSTEM_BROWSER_SITES`) | ปานกลาง (ตารางคำพูด → ปุ่ม · ตรวจโฟกัส) |

**Pakon เลือก A (2026-10-26)** · วิธี: พูด "เข้าสู่ระบบยูทูบ" → ปิดเบราว์เซอร์ที่ถูกคุม → เปิด Chromium **โปรไฟล์เดียวกัน**แบบไม่คุมที่หน้าเข้าสู่ระบบ Google →
ผู้ใช้กรอกเอง (ระบบไม่เห็นรหัส) → ปิดหน้าต่าง → "เปิดยูทูบ" = เบราว์เซอร์ของผู้ช่วยเปิดใหม่ด้วยคุกกี้เดิม · ระหว่างหน้าต่างเข้าสู่ระบบเปิด คำสั่งเว็บอื่นตอบให้ปิดก่อน
(`BrowserControl._do_login` · `logging_in` · `LOGIN_URL` ใน `src/aipc/browser/control.py` · คำพูด `_LOGIN` ใน `src/aipc/skills/browse.py`)

~~ผู้ช่วยฟันธง:~~ ทดลอง A ก่อน (ข้อ S0 ด้านล่าง · ใช้เวลาที่จอราว 15 นาที ไม่ต้องเขียนโค้ด) · ผ่าน → สร้างแบบ A · ไม่ผ่าน → สร้างแบบ B
เหตุผล: A ได้คำสั่งเสียงครบและโค้ดน้อยกว่า แต่ตอบไม่ได้โดยไม่ลองจริง (H5 · ไม่เดา)

## 6. กรณีที่ต้องคิดไว้ก่อน

- Google เตะออกระหว่างใช้ (A) → กลับไปเปิดหน้าต่างบัญชีแบบเดิม + บอกผู้ใช้ ไม่วนเปิดซ้ำ
- หน้าต่างบัญชีปิดอยู่/ไม่ได้อยู่บนสุด (B) → เปิด/เรียกขึ้นก่อน · ยืนยันไม่ได้ = ไม่ส่งปุ่ม + บอก
- หลายผู้ใช้ · ออกจากระบบ · ลบบัญชี → โปรไฟล์อยู่ใน home ของแต่ละคน เหมือน 0031
- คำสั่งที่ส่งอีเมล ลบ หรือแชร์ไฟล์ → ไม่ทำในรอบนี้ (หัวข้อ 9)

## 7. ต้นทุนบน Pi 5

- A: RAM เท่าเดิมหรือน้อยลง (เหลือ Chromium ตัวเดียวแทนสองตัว) · ยังไม่ได้วัด
- B: `wtype` 1 โปรเซสสั้น ๆ ต่อคำสั่ง · ไม่ได้วัด
- ไม่เรียก LLM เพิ่ม · ดิสก์เท่าเดิม

## 8. การทดสอบ และเกณฑ์ผ่าน (ประกาศก่อนสร้าง)

- **S0 (Pakon ที่จอ Pi 5 · บัญชี Google สำหรับสาธิต ไม่ใช่บัญชีหลัก · ก่อนรวม/ใช้วันสอบ):** พูด "เข้าสู่ระบบกูเกิล" → กรอกเอง → ปิดหน้าต่าง → พูด "เปิดยูทูบ" แล้ว "เปิดจีเมล" →
  ยังเข้าสู่ระบบอยู่ไหม (YouTube: เห็นรูปโปรไฟล์ · "เปิดวิดีโอแรก" ได้ · Gmail: เห็นกล่องจดหมาย ไม่เด้งไปหน้าเข้าสู่ระบบ) · ทำซ้ำ 3 รอบ (ออก/เข้าเซสชันเครื่องคั่น) · **3/3 ทั้งสองเว็บ = A ผ่าน** · ครั้งใดถูกเตะออกหรือขึ้นเตือนความปลอดภัย = บันทึก แล้ว ใส่เว็บที่โดนกลับใน `SYSTEM_BROWSER_SITES` (ย้อนบรรทัดเดียว) · บันทึกทุกรอบ
- **ผล V1 รอบ 2 (2026-10-26 · วินโดวส์ · Pakon "OK" ย้ายเว็บบัญชี Google มาเบราว์เซอร์ของผู้ช่วย):** `SYSTEM_BROWSER_SITES` = ว่าง ·
  เปิด Gmail/ค้นในจีเมลแล้วเด้งไป `accounts.google.com` = ตอบ "ยังไม่ได้เข้าสู่ระบบ Google · พูด “เข้าสู่ระบบกูเกิล”…" ไม่บอก "เปิดแล้ว" (H5) ·
  "เข้าสู่ระบบจีเมล" = login · เทสต์ใหม่ 4 ข้อ · **ชุดวัดเสียง 0042 ไม่แก้** (Pakon เลือกทาง 1): คำตอบที่เปลี่ยนตามการออกแบบอยู่ใน
  `voice_all_eval.CHANGED_BY_DESIGN` ที่เดียว = 4 ประโยค (dev3 เปิดจีเมล · test เปิดจีเมลให้หน่อย · test3 เปิดจีเมลหน่อย · เข้ากูเกิลไดรฟ์ · command → browser:site) ·
  ตรวจก่อน/หลังแก้ทั้ง 3 ชุด: ต่างกันเฉพาะ 4 ประโยคนี้ ข้อผิดอื่นเหมือนเดิมทุกข้อ (รันชุด held-out test/test3 เพื่อเทียบเท่านั้น ไม่ได้ใช้ปรับกฎ)
