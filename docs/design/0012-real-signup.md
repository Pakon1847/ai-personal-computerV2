## 1. ปัญหาที่แก้ และใครใช้

หน้าสมัครตรวจฟอร์มได้ แต่ **ไม่ได้สร้างบัญชีจริง** (การ์ด 0007) คนใหม่จึงใช้เครื่องไม่ได้ถ้าไม่มีคนเปิด terminal สร้างให้

## 3. ความสัมพันธ์กับชิ้นส่วนอื่น

- **พึ่ง:** greetd + PAM (การ์ด 0003, มีแล้ว) · `aipc.accounts.validation` (มีแล้ว ต้องแก้ `re.match` เป็น `fullmatch` — ตอนนี้ `"root\n"` ผ่านกฎ) ·
  sudo, `useradd`, `chpasswd`, libpam (มีใน OS) · หน้าสมัคร (การ์ด 0002/0007)
- **มีคนพึ่ง:** ข้ออ้างที่ 2 ของเล่ม (หลายคนใช้เครื่องเดียวกัน) · ทดสอบข้ามบัญชี (T12) · ใบหน้า (ลงทะเบียนในหน้าตั้งค่าหลังเข้าครั้งแรก)
- **ชั้น:** หน้า Login (ผู้ใช้ `_greetd`) → ตัวช่วยสิทธิ์ root (โปรเซสสั้น ๆ ต่อคำขอ) → เครื่องมือของ OS

```text
สมัคร (3 ขั้น · ตั้งแต่ 2026-09-29)
  1 บัญชีและรหัสผ่าน   ชื่อที่แสดง · ชื่อผู้ใช้ · รหัสผ่าน ×2       (หน้าจอตรวจเพื่อบอกเร็ว ๆ)
     กด "สร้างบัญชี"
        └─ sudo -n /usr/local/sbin/aipc-accounts  (stdin = JSON)
             ตัวช่วย root: ตรวจกฎซ้ำ → ชื่อว่าง?
             → จดงานค้าง → useradd (ไม่ใส่กลุ่ม sudo) → chpasswd → home 0700 → ออกรหัสกู้คืน เก็บ hash → ลบงานค้าง
  2 รหัสกู้คืน          แสดงครั้งเดียว + ติ๊ก "จดไว้แล้ว"
  3 พร้อมใช้            เข้าสู่ระบบด้วยรหัสที่ตั้ง (ผ่าน greetd + PAM ตามปกติ) → หน้าจอ V2
                        ลงทะเบียนใบหน้าได้ในหน้าตั้งค่า (ไม่บังคับ)

ลืมรหัสผ่าน
  หน้า Login → "ลืมรหัสผ่าน" → ชื่อผู้ใช้ + รหัสกู้คืน + รหัสใหม่ ×2
        └─ ตัวช่วย root: เช็กจำนวนครั้งที่ผิด → เทียบ hash → chpasswd → ออกรหัสกู้คืนใหม่ (อันเก่าใช้ไม่ได้ทันที)
  → แสดงรหัสกู้คืนใหม่ครั้งเดียว → เข้าสู่ระบบ
```

ขั้น "ลงทะเบียนใบหน้า" ออกจากการสมัคร เพราะหน้า Login (ผู้ใช้ `_greetd`) เขียนลง home ของคนใหม่ไม่ได้
และ BRIEF 5.1 ข้อ 6 ให้ลงทะเบียนใบหน้าเมื่อยืนยันตัวตนแล้วเท่านั้น → ทำในหน้าตั้งค่าหลังเข้าครั้งแรก (มีอยู่แล้ว การ์ด 0006/0010)

## 4. ข้อมูล

| ข้อมูล | เก็บที่ | สิทธิ์ | เขียนแบบ |
|---|---|---|---|
| บัญชี Linux | `/etc/passwd`, `/etc/shadow`, `/home/<ชื่อ>` | ของ OS · home 0700 | `useradd` / `chpasswd` (เครื่องมือของ OS เขียนเอง) |
| hash รหัสกู้คืน | `/var/lib/aipc/recovery/<ชื่อ>.json` (salt, ค่าตั้ง scrypt, hash, วันที่ออก, จำนวนครั้งที่ผิด, ห้ามลองถึงเวลา) | root 0600 · โฟลเดอร์ 0700 | atomic (tmp → fsync → rename) |
| งานสมัครค้าง | `/var/lib/aipc/pending/<ชื่อ>` | root 0600 | สร้างก่อน `useradd` · ลบเมื่อสำเร็จ |
| บันทึกเหตุการณ์ | journal ของระบบ: "สร้างบัญชี X อนุมัติโดย Y", "กู้คืน X สำเร็จ/ไม่สำเร็จ" | root | ไม่มีรหัสผ่านหรือรหัสกู้คืน |

- รหัสกู้คืนตัวจริงอยู่ในหน่วยความจำของหน้า Login แค่ช่วงแสดง แล้วล้าง
- **ไฟดับกลางคัน:** เหลือไฟล์งานค้าง → ตัวช่วยครั้งถัดไปเรียก `userdel -r` ลบบัญชีนั้นก่อนทำงานใหม่ → ไม่มีบัญชีครึ่ง ๆ และสมัครชื่อเดิมใหม่ได้
- **ลบบัญชี:** รอบนี้ทำผ่าน terminal (`sudo userdel -r <ชื่อ>` + ลบไฟล์ hash) ตามคู่มือ · ไม่มีปุ่มในหน้าจอ

## 6. กรณีที่ต้องคิดไว้ก่อน

- ~~รหัสผู้ดูแลผิด~~ (ตัดออก 2026-09-29) · **คำขอพยายามขอกลุ่ม sudo** → ไม่มีผล ตัวช่วยใส่ได้เฉพาะ video render audio
- **ชื่อซ้ำหรือชื่อสงวน** → หน้าจอบอกที่ขั้น 1 · ตัวช่วยตรวจซ้ำ (เผื่อมีคนสมัครชื่อนี้ไปก่อนระหว่างกรอก)
- **ไฟดับระหว่างสร้าง** → งานค้าง → ลบทิ้งครั้งถัดไป (หัวข้อ 4)
- **ดิสก์เต็ม / `useradd` ล้ม** → ย้อนทุกขั้นที่ทำแล้ว (`userdel -r`) → บอกผู้ใช้
- **`chpasswd` ล้มหลัง `useradd`** → `userdel -r` → ไม่มีบัญชีที่ไม่มีรหัสผ่านค้าง
- **ตัวช่วยค้าง** → หน้าจอหมดเวลา 30 วิ แล้วบอกว่าไม่สำเร็จ · หน้า Login ยังใช้ได้
- **กดซ้ำ / สองคำขอพร้อมกัน** → ปุ่มปิดระหว่างทำ · ตัวช่วยล็อกไฟล์ (`fcntl.flock`) ทำทีละคำขอ
- **ลองรหัสกู้คืนผิดหลายครั้ง** → ผิดครบ 5 ครั้ง ต้องรอ 1 นาที แล้วเพิ่มเท่าตัวทุกครั้งที่ผิดต่อ (สูงสุด 1 ชม.) ·
  รหัส 120 บิตเดาไม่ได้อยู่แล้ว การจำกัดนี้กันการกลั่นแกล้งและ log ท่วม
- **พิมพ์รหัสกู้คืนด้วยมือ** → ไม่สนตัวพิมพ์เล็ก/ใหญ่ ขีด และช่องว่าง · แปลง I, L → 1 และ O → 0 (ตามชุดตัวอักษร Crockford ที่ใช้ออกรหัส)
- **บัญชีที่ไม่มีรหัสกู้คืน** (บัญชีแรกที่มาจากตอนลง OS) → ข้อความรวม "ชื่อผู้ใช้หรือรหัสกู้คืนไม่ถูกต้อง" · ผู้ดูแลตั้งรหัสใหม่ด้วย `sudo passwd`
- **ชื่อที่แสดงภาษาไทย** → ใช้ได้ · ห้ามมี `:` `,` และขึ้นบรรทัด (ทำให้ `/etc/passwd` เสีย) · ยาวไม่เกิน 64 ตัวอักษร
- **รหัสผ่านที่มีตัวควบคุม/ขึ้นบรรทัด** → ปฏิเสธ (ทำให้รูปแบบ `ชื่อ:รหัส` ของ `chpasswd` เสีย)
- **ผู้เรียกไม่ใช่ `_greetd`** (`SUDO_USER` ไม่ตรง) → ปฏิเสธ แม้ผู้ดูแลจะรันเองด้วย sudo
- **ออฟไลน์ / Logout / อุปกรณ์หลุด** → ไม่เกี่ยว (ทำงานก่อนมีเซสชัน ไม่ใช้เน็ต ไม่ใช้กล้อง)

## 9. ไม่ทำในรอบนี้

- **ผู้ดูแลอนุมัติ (ทั้งทันทีและภายหลัง) / จำกัดจำนวนบัญชี / โควตา** — Pakon เลือกสมัครเสรีไม่มีขีดจำกัด (หัวข้อ 10)
- **ลบบัญชีจากหน้าจอ** — ทำผ่าน terminal ตามคู่มือ
- **รหัสกู้คืนของบัญชีแรก** — บัญชีแรกมาจากตอนลง OS · ผู้ดูแลใช้ `sudo passwd` แทน
- **ลงทะเบียนใบหน้าระหว่างสมัคร** — ย้ายไปหน้าตั้งค่าหลังเข้าครั้งแรก (หัวข้อ 3)
- **โควตาพื้นที่ต่อบัญชี, จำกัดจำนวนบัญชี, บัญชี Guest, เปลี่ยนรหัสผ่านในเซสชัน** — นอกขอบเขตรอบ 3

## 10. เปลี่ยนหลังอนุมัติ: สมัครเสรี (Pakon 2026-09-29)

**ตัดสิน:** เอาขั้น "ผู้ดูแลอนุมัติ" ออก · ใครอยู่ที่หน้า Login ก็สร้างบัญชีได้ · ไม่จำกัดจำนวนบัญชีและไม่มีโควตา
(ทางเลือกที่เสนอแต่ไม่เลือก: เปิดเสรีแต่จำกัด 10 บัญชี + บัญชีที่สมัครเองเข้า SSH ไม่ได้ · ให้ผู้ดูแลเลือกเปิด/ปิด)

**ที่เปลี่ยน:** ตัวช่วย root ไม่ตรวจรหัสผู้ดูแลแล้ว · ลบ `aipc.accounts.pam` และไฟล์ `/etc/pam.d/aipc-accounts` ·
หน้าสมัครเหลือ 3 ขั้น (บัญชี → รหัสกู้คืน → พร้อมใช้) · ส่วนอื่นคงเดิม: ตรวจกฎซ้ำ, ครบหรือไม่มีเลย, home 0700, ไม่ใส่กลุ่ม sudo, เรียกได้จาก `_greetd` เท่านั้น

**ความเสี่ยงที่ยอมรับ (ต้องเขียนในเล่ม บทที่ 3 และข้อจำกัดในบทที่ 5):**

- ใครก็ตามที่เข้าถึงหน้า Login ได้ สร้างบัญชี Linux จริงได้ (ไม่มีสิทธิ์ผู้ดูแล)
- บัญชีนั้นเข้าทาง SSH ได้ ถ้าเครื่องเปิด SSH แบบรหัสผ่าน (Pi 4 ตอนนี้เปิดรับทุกเครือข่าย) → ผู้ติดตั้งควรปิด SSH หรือจำกัดผู้ใช้ SSH ในเครื่องที่ใช้จริง
- ไม่จำกัดจำนวน → สร้างบัญชีจำนวนมากจนพื้นที่เต็มได้ (T8) · ลบบัญชีทำผ่าน terminal (`sudo userdel -r <ชื่อ>`)
- ไม่ตรง BRIEF 5.1 ข้อ 3 ฉบับเต็ม (เปิดเสรีต้องจำกัดจำนวนและโควตา) → BRIEF บันทึกข้อยกเว้นของรุ่นนี้ไว้แล้ว
