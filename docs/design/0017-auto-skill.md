# การ์ดออกแบบ 0017: สกิลอัตโนมัติ (AI ในเครื่องขอให้ Claude สร้างสกิล .md แล้วใช้ทันที)

- **สถานะ:** สร้างเสร็จ (บนวินโดวส์ + AI ในเครื่องบน Pi 5) · อนุมัติ 2026-09-30 Pakon (แบบ ข.) · ผลวัด [docs/benchmarks/2026-09-30-auto-skill](../benchmarks/2026-09-30-auto-skill/README.md) · รอทดสอบทั้งสายบน Pi (ต้องมี Claude Code บน Pi)
- **ข้อกำหนดที่อ้าง:** ความต้องการของอาจารย์ ([ข้อเสนอ 2026-09-29 หัวข้อ 11](../reviews/2026-09-29-feature-proposal.md)) ·
  ADR-011 ข้อ 3 (**แก้ในการ์ดนี้**) · SKILLS.md · การ์ด 0016 (ไฮบริด) · `aipc.skills.forge` (มีแล้ว)
- **งานวิจัยที่ใช้อ้าง:** *Large Language Models as Tool Makers* (Cai et al., 2023, arXiv:2305.17126) —
  โมเดลใหญ่สร้างเครื่องมือครั้งเดียว + ตรวจด้วยตัวอย่าง แล้วโมเดลเล็กใช้ซ้ำ ·
  *Voyager* (Wang et al., 2023, arXiv:2305.16291) — คลังทักษะที่โตขึ้นเรื่อย ๆ + แก้ทักษะจากผลลัพธ์/ข้อผิดพลาด

## 1. ปัญหาที่แก้ และใครใช้

ผู้ใช้สั่งงานที่เครื่องยังไม่มีสกิล (เช่น "เปิดโหมดทำงาน") → ตอนนี้ AI ในเครื่องทำไม่ได้และไม่มีทางเรียนรู้ ·
การสร้างสกิลด้วย Claude มีแล้วแต่เป็นคำสั่งที่ผู้ดูแลต้องรันเองและอนุมัติเอง (ไม่อัตโนมัติ) ·
ผู้ใช้: ทุกบัญชีบนเครื่องที่มี Claude Code ติดตั้งและเข้าสู่ระบบแล้ว

## 2. หลักการที่ใช้ตัดสิน

| หลักการ | ใช้ยังไง |
|---|---|
| ข้อมูลผู้ใช้ไม่ออกนอกเครื่อง | Claude เห็นแค่ "คำขอสร้างสกิล" (ประโยคที่ผู้ใช้พิมพ์) + รายชื่อสกิล/เว็บ/แอปที่ระบบมี · ไม่เห็นแชท นัด ไฟล์ |
| AI สั่งเครื่องเองไม่ได้ (H8) | สกิลเป็น **ข้อมูล** (.md) · ขั้นตอนเขียนได้เฉพาะคำสั่งที่โค้ดรู้จัก · โค้ดเป็นคนทำตาม |
| บอกตามจริง (H2/H5) | สร้างไม่สำเร็จ / ไม่ผ่านตัวตรวจ = บอกตรง ๆ แล้วให้ Claude ตอบคำขอนั้นแทน · ทุกการ์ดบอกว่า "Claude สร้าง" |
| ย้อนกลับได้เสมอ | ติดตั้งอัตโนมัติ แต่ **ยกเลิก/แก้ได้ทุกครั้ง** · เก็บทุกรุ่น |
| ความเสี่ยงตามงาน | ขั้นที่สั่งเครื่องยังถามยืนยันก่อนทำตามกติกาเดิมของทุกสกิล (ไม่ใช่การอนุมัติติดตั้ง) |

## 3. การตัดสินใจ: แก้ ADR-011 ข้อ 3

เดิม: "ผู้ใช้ยืนยันก่อนติดตั้งเสมอ" → ใหม่ (Pakon 2026-09-30): **"ติดตั้งอัตโนมัติเมื่อผ่านตัวตรวจทุกชั้น ·
ผู้ใช้เห็นทุกครั้งที่สกิลที่ Claude สร้างทำงาน และยกเลิก/สั่งแก้ได้ทันที"** · คำสั่ง `forge install` ด้วยมือยังอยู่

## 4. ลำดับการทำงาน

1. ผู้ใช้พิมพ์งาน → กฎคำสั่งตรง → ไม่ตรง → AI ในเครื่องเลือกเครื่องมือ (มีเครื่องมือใหม่ `create-skill`)
2. AI เรียก `create-skill` (งานที่ทำซ้ำได้แต่ไม่มีสกิล) → หน้าจอขึ้น "กำลังให้ Claude สร้างสกิลสำหรับงานนี้…"
3. เธรดแยก: `forge.forge(คำขอ)` → ไฟล์ .md → **ชั้นที่ 1** (ด้านล่าง) → ไม่ผ่านแก้ได้ 2 รอบ
4. ผ่าน = ติดตั้งลงโฟลเดอร์สกิลของผู้ใช้ → ทำงานนั้นทันทีผ่านทางเดียวกับสกิลอื่น (`handleAs`)
5. ไม่ผ่าน = บอก "สร้างสกิลไม่สำเร็จ: …" แล้วส่งคำขอให้ Claude ตอบแทน (การ์ด 0016)
6. ครั้งต่อไปที่สั่งแบบเดิม AI ในเครื่องเห็นสกิลใหม่ในรายการเครื่องมือ → เรียกเอง ไม่ต้องใช้เน็ต

## 5. กันพลาด 3 ชั้น

**ชั้นที่ 1 ก่อนติดตั้ง (โค้ด · อัตโนมัติ):** ตัวตรวจไฟล์ (mdskill + manifest · ขั้นตอนเฉพาะที่รู้จัก · ≤ 8,000 ไบต์) ·
id ไม่ซ้ำ · ทดลองเส้นทาง: ประโยค "ควรเรียก" ต้องไปสกิลใหม่ · "ไม่ควรเรียก" ต้องไม่ไป · **ประโยคของสกิลเดิมต้องไม่ถูกแย่ง** ·
สิทธิ์ที่ขอต้องอยู่ในรายการของระบบ

**ชั้นที่ 2 หลังใช้ (ผู้ใช้):** การ์ดของสกิลที่ Claude สร้างมีบรรทัด "สกิลใหม่ (Claude สร้าง · รุ่น N)" + ปุ่ม
**[ยกเลิกสกิลนี้]** (ลบทันที) และ **[ไม่ใช่แบบนี้]** → ช่องพิมพ์เปลี่ยนเป็น "บอกว่าผิดตรงไหน" → ส่งไฟล์เดิม + คำติให้ Claude
แก้เป็นรุ่นใหม่ (id เดิม) → ผ่านชั้นที่ 1 ใหม่ → แทนที่ · รุ่นเก่าเก็บไว้

**ชั้นที่ 3 ปิดเอง (โค้ด):** กด "ไม่ใช่แบบนี้" 2 ครั้งติดกันโดยรุ่นใหม่ยังไม่ถูกใช้สำเร็จ = ปิดสกิล · ขั้นที่สั่งเครื่องล้มเหลว = นับเป็นเสีย 1 ครั้ง
(เสีย 2 ครั้งติด = ปิด) · สกิลที่ปิดไม่อยู่ในรายการเครื่องมือของ AI · เปิดคืน/ลบได้ในหน้า Skill

## 6. ข้อมูล

- ที่เก็บ: `~/.local/share/aipc/skills/` (ใน home 0700 · ของผู้ใช้คนนั้นคนเดียว · บัญชีอื่นไม่เห็นสกิลนี้)
  - `<id>.md` = รุ่นที่ใช้ · `.versions/<id>/<n>.md` = ทุกรุ่น · `index.json` = ที่มา (คำขอ รุ่น วันที่ โมเดล ค่าใช้จ่าย)
    จำนวนครั้งที่ใช้ นับผิดติดกัน สถานะ (on/off)
- เขียน: ไฟล์ชั่วคราว + `os.replace` (ไฟดับกลางคัน = ได้รุ่นเก่าหรือรุ่นใหม่ครบ ไม่ครึ่ง) · `index.json` เสีย = ถือว่าทุกสกิลในโฟลเดอร์
  เป็นรุ่น 1 เปิดอยู่ (ไม่ทำให้หน้าจอเปิดไม่ขึ้น)
- ลบ: ปุ่มยกเลิก = ลบ `<id>.md` และรายการใน index (รุ่นเก่าใน `.versions` ลบด้วย)

## 7. รอยต่อ

- `aipc.skills.userskills.UserSkills(folder)`: `load() → [Manifest]` (เฉพาะที่เปิด) · `install(proposal) → Manifest` ·
  `remove(id)` · `record(id, ok: bool)` · `wrong(id) → ปิดแล้วไหม` · `info(id)` · `entries()`
- `aipc.skills.forge.forge(..., revise=(ไฟล์เดิม, คำติ))` → Proposal (id เดิมได้เมื่อแก้)
- `catalog.CREATE_SKILL = "create-skill"` · `catalog.tools(..., forge=True)` · ข้อความกฎใน system prompt
- `SkillsController.handleAs("create-skill", ข้อความ)` → การ์ด `kind="forging"` + สัญญาณ `forgeDone(card)` ภายหลัง ·
  `removeSkill(id)` · `reviseSkill(id, คำติ)` · `skills` แสดงที่มา/เปิดปิด

## 8. กรณีที่ต้องคิดไว้ก่อน

- **ไม่มี Claude Code / ไม่ได้เข้าสู่ระบบ / ออฟไลน์:** ไม่มีเครื่องมือ `create-skill` ในรายการ (AI เรียกไม่ได้) · ถ้าเรียกแล้ว claude ล้ม
  = บอกตรง ๆ ว่าสร้างไม่ได้เพราะอะไร
- **ผู้ใช้ออกจากระบบระหว่างสร้าง:** เธรดตายไปกับเซสชัน · ยังไม่ติดตั้ง = ไม่มีอะไรค้าง (ไฟล์ชั่วคราวอยู่ใน /tmp ของ claude -p)
- **สร้างซ้ำระหว่างรอ:** สร้างได้ครั้งละ 1 งาน · ระหว่างนั้นช่องพิมพ์ใช้ได้ตามปกติ
- **สกิลผิดแต่ผ่านตัวตรวจ:** ชั้นที่ 2 และ 3 · ขั้นที่สั่งเครื่องยังถามยืนยันก่อนทำ
- **AI เรียก create-skill ผิดจังหวะ (เช่น คำถามความรู้ทั่วไป):** เสียเวลา + ค่าใช้จ่าย 1 ครั้ง · วัดในข้อ 10
- **หลายผู้ใช้:** แยกโฟลเดอร์ต่อบัญชี (home) · Claude Code บน Pi เป็นบัญชี Claude เดียวของเครื่อง (ต้องบอกผู้ใช้)

## 9. ต้นทุนบน Pi 5

RAM เพิ่ม ~0 (ไม่มีโมเดลเพิ่ม · `claude` เป็นโปรเซสชั่วคราว) · รายการเครื่องมือยาวขึ้นตามจำนวนสกิล (~60–120 token ต่อสกิล ·
แคชช่วยหลังข้อความแรก) · Claude: 1–3 ครั้งต่อสกิล (ผลเดิม: มัธยฐาน 26 วิ · ~$0.10/สกิล)

## 10. การทดสอบ และเกณฑ์ผ่าน (ประกาศก่อนวัด · H9)

1. **เทสต์อัตโนมัติ** (Claude ปลอม): ผ่านตัวตรวจ = ติดตั้ง + ทำงานทันที · ไม่ผ่าน = ไม่ติดตั้ง ส่ง Claude ตอบแทน ·
   แก้ = รุ่น 2 แทนที่ รุ่น 1 เก็บไว้ · ผิด 2 ครั้ง = ปิด · index เสีย = หน้าจอยังเปิด
2. **ประตูกันสกิลผิด (ชั้นที่ 1) ด้วยสกิลเสียที่ตั้งใจทำ** `tests/data/bad_skills/` ≥ 10 ไฟล์ (ขั้นตอนที่ไม่รู้จัก เว็บนอกรายการ
   แย่งประโยคสกิลเดิม ไฟล์ใหญ่ id ซ้ำ ส่วนหัวผิด ฯลฯ): **ติดตั้งไม่ได้ 100%**
3. **AI ในเครื่องเรียก create-skill ถูกจังหวะ** (Gemma 4 E2B บน Pi 5 · prompt จริงของแอป) ชุดใหม่ `tests/data/create_skill_calls.json`
   (เขียนและ commit ก่อนวัด · ไม่ปรับ prompt ด้วยชุดนี้): งานที่ควรสร้างสกิล ≥ 15 ข้อ **เรียก ≥ 70%** ·
   คำถาม/งานที่มีสกิลแล้ว ≥ 20 ข้อ **เรียกผิด ≤ 10%**
4. **ปลายทางจริง** (Claude จริง · เครื่องที่มี claude): คำขอจากข้อ 3 ที่ควรสร้าง 5 ข้อ → ติดตั้งได้ ≥ 4/5 · เวลาจากส่งถึงทำงาน มัธยฐาน ≤ 60 วิ ·
   สั่งซ้ำครั้งที่ 2 AI ในเครื่องเรียกสกิลใหม่เอง ≥ 4/5
