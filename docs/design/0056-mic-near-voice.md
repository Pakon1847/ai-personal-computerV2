## 1. ปัญหาที่แก้ และใครใช้

Pakon (2026-10-23): "ให้ไมค์รับเสียงแค่ตรง ๆ รอบข้างไม่ต้องรับ · ตัดเสียงรอบก่อนเพื่อแก้การประมวลผลคำช้า · เก็บค่าเสียงรอบ ๆ เพื่อไม่เอาตรงนั้นมาประมวลผล" ·
ผู้ใช้ทุกคนที่สั่งด้วยเสียง (F9 / ปุ่มไมค์) ในห้องที่มีเสียง เช่น ทีวี พัดลม คนคุยกัน (วันสอบ)

**สิ่งที่มีอยู่แล้ว (ตรวจโค้ด `src/aipc/voice/stt.py:41-110`):** วัดเสียงรอบข้าง 0.3 วิแรกทุกครั้ง → "เริ่มพูด" = ดังกว่า 3 เท่า ·
"จบ" = เบากว่า 0.7 × เกณฑ์นั้น ต่อกัน 1 วิ · แต่ **ไฟล์ทั้งไฟล์ (รวมช่วงเงียบ/เสียงรอบข้าง) ถูกส่งไปถอด**

**จุดอ่อนที่เห็นจากโค้ด (ยังไม่ได้วัด):**
- ก. เสียงรอบข้างที่ดังขึ้นลง (ทีวี คนคุย) ทำให้ "เงียบครบ 1 วิ" มาไม่ถึง → ฟังต่อไปจนครบ 15 วิ = **รู้สึกช้า** และไฟล์ยาว ถอดนาน
- ข. กด F9 แล้วพูดทันที → 0.3 วิแรกที่ใช้วัด "เสียงรอบข้าง" เป็นเสียงเราเอง → เกณฑ์สูงเกิน → ตัดผิด/ไม่ได้ยิน
- ค. ช่วงก่อนพูดและหลังพูดถูกถอดไปด้วย = เสียเวลาถอดและอาจถอดเสียงรอบข้างเป็นคำ

## 3. ออกแบบ (3 ส่วน · ทำได้ทีละส่วน)

1. **ฟังแค่คนใกล้ไมค์ (near-field gate):** เสียงจากแหล่งจุดเบาลง ~6 dB ทุกครั้งที่ระยะเพิ่มเท่าตัว →
   คนพูดห่างไมค์ 30 ซม. ดังกว่าทีวี/คนที่ 2 ม. ราว 15 dB · หลังเริ่มพูด จำ "ความดังเสียงเรา" ไว้ ·
   เสียงที่เบากว่าเสียงเรา > 15 dB (ค่าเริ่ม · ตั้งจากชุดพัฒนา) **นับเป็นเงียบ** → พูดจบแล้วจบทันที ไม่รอทีวีเงียบ
2. **ตัดช่วงไม่พูดก่อนถอด (trim):** ส่งไปถอดเฉพาะ จุดเริ่มพูด − 0.25 วิ ถึง จุดจบ + 0.3 วิ · เสียงช่วงอื่นไม่ถูกถอด ·
   (+0.3 วิ เท่าไฟล์ที่ถอดล่วงหน้าของการ์ด 0044 ที่ผ่านความแม่นแล้ว · แก้จาก 0.15 ในร่าง ก่อนวัด)
3. **จำระดับเสียงรอบข้าง:** จำค่าล่าสุด (ตัวเลข) ไว้ในแอปตลอดการเข้าระบบ · ครั้งต่อไปเริ่มด้วยค่านี้ → พูดทันทีหลังกด F9 ได้ ·
   ยังปรับตามห้องระหว่างฟังเหมือนเดิม · ออกจากระบบ = ลืม

**ทำไมไม่ทำแบบอื่น:**
- "รับแค่ทิศตรงหน้า" จริง ๆ ต้องใช้ไมค์หลายตัว (beamforming) · ไมค์ตอนนี้ส่งเสียงช่องเดียว → ซอฟต์แวร์รู้ทิศไม่ได้ · ทางฮาร์ดแวร์ = ไมค์ใกล้ปาก/หูฟังมีไมค์
- ตัวลดเสียงรบกวน rnnoise / highpass / VAD: **วัดแล้วไม่ผ่าน** (2026-10-01: VAD ทำเสียงปกติถอดถูกลดจาก 16 → 12/22) · ระยะไมค์สำคัญกว่าทุกตัวกรอง

## 10. แผนวัด (ประกาศก่อนวัด · H9)

"คนพูดห่าง ~2 ม." จำลองด้วย **babble** (เสียงพูดประโยคอื่นซ้อนต่อเนื่อง) ที่เบากว่าเสียงเรา **15–20 dB**
(ผู้ใช้ห่างไมค์ ~30 ซม. · อีกคน 2 ม. = ระยะต่างกัน ~2.7 เท่าตัว × 6 dB ≈ 16 dB ถ้าพูดดังเท่ากัน) · เสียงรอบข้างดังต่อหลังเราพูดจบ 15 วิ (เหมือนในห้อง) ·
เสียงสังเคราะห์ (Piper) ทั้งหมด → ระดับหลักฐาน 3 · ของจริงที่จอ (N1 N3 N4) = ระดับ 4

**ชุดข้อมูล**
- **พัฒนา (ใช้ปรับค่า):** `~/voice-bench/noise/ep` บน Pi (44 ไฟล์ · ประโยคคู่ลำดับ `[::2]` ของ sentences.json · ชุดเดียวกับการ์ด 0019 ข้อ 10)
- **ทดสอบ (ไม่เปิดดูก่อนล็อกค่า):** สร้างใหม่จากประโยคลำดับคี่ `[1::2]` (22 ประโยค · 44 ไฟล์) หลัง commit ค่าที่เลือกแล้ว
- ความแม่น: `voice_cmd_test.json` (34) · ชุด H (`voice_h_eval --zip-only` · 80) · ความเร็ว: `voice_latency_dev.json` (30 · ชุดของการ์ด 0044)

**ปรับค่าบนชุดพัฒนา:** near_db ∈ {10, 12, 15, 18, 20} · เลือกค่าที่ "หยุด ≤ 1.5 วิหลังพูดจบ" ใน babble15 + babble20 มากที่สุด
โดยไม่ตัดกลางประโยค (คู่ที่เว้น 0.5 วิ) ใน clean / brown20 / babble20 · บันทึกทุกค่าที่ลอง

| # | เกณฑ์ (ชุดทดสอบ · เครื่องมือ) |
|---|---|
| T1 | babble15 + babble20: หยุด ≤ 1.5 วิหลังพูดจบ ≥ 75/88 และมากกว่ารุ่นเดิม (`endpoint_eval`) |
| T2 | clean + brown20: หยุด ≤ 1.5 วิ ไม่ลดเกิน 1/88 จากรุ่นเดิม · ตัดกลางประโยค = 0 ใน clean / brown20 / babble20 |
| N1s | babble 15 dB ต่อเนื่อง: พูดจบ → ได้ข้อความ (ค่ากลาง คำสั่ง และคำถาม) เร็วขึ้น ≥ 30% (`voice_e2e_latency --babble 15` · Pi 5) |
| N2 | ตัดช่วงไม่พูดแล้ว: ชุดทดสอบคำสั่ง ≥ 29/34 · ชุด H ≥ 68/80 · ไม่ใช่คำสั่งถูกทำทันที 0 (`--trim`) |
| N3s | พูดทันทีไม่มีช่วงเงียบนำ + จำระดับเสียงรอบข้างไว้: ไม่ขึ้น "ไม่ได้ยิน" และไม่ถูกตัด 30/30 (`voice_e2e_latency --lead 0`) |

N1 N3 N4 (หัวข้อ 8) วัดที่จอกับไมค์จริงหลัง Pakon อนุมัติติดตั้ง · เกณฑ์ไม่ผ่าน = บันทึกตามจริง ไม่แก้ชุดข้อมูล

**เปลี่ยนตัววัดหลังเห็นผลชุดพัฒนารอบแรก (2026-10-23 · ก่อนสร้างชุดทดสอบ):** babble ของ `endpoint_eval` เดิมต่อไฟล์ทั้งไฟล์
ซึ่งมีเงียบ ~3.5 วิ ระหว่างประโยค → ตัวจับจุดจบรุ่นเดิมได้อาศัยช่วงเงียบนั้น (ไม่ใช่คนคุยต่อเนื่อง) ·
เพิ่ม `--continuous` (ต่อเฉพาะช่วงพูด) และใช้ตัวนี้เลือก near_db ใหม่ + วัด T1/T2 · ผลรอบแรก (babble มีช่วงเงียบ) เก็บไว้ทั้งหมด
