# การ์ดออกแบบ 0074: ด่านกันสกิลไม่ดี · แกนกลางเลือกสกิลแม่นแม้สกิลมากขึ้น

- **สถานะ:** ร่าง · รออนุมัติ (2026-11-05 · ผู้ช่วย) · สาขา `feature/0074-skill-guard` (แตกจาก `feature/0072-gmail-api` = รุ่นที่ติดตั้งบน Pi ล่าสุด) · **ยังไม่เขียนโค้ด**
- **ที่มา:** คำแนะนำอาจารย์และกรรมการ ข้อ 10 "ทำแกนกลางให้มันดี เราจะไม่โฟกัสการเพิ่มสกิล ป้องกันสกิลที่ไม่ดี" ·
  [บันทึกคำแนะนำ 11 ข้อ](../reviews/2026-11-05-committee-advice.md) · Pakon จัดเป็นงานแรกของช่วง 1 (2026-11-05)
- **ข้อกำหนดที่อ้าง:** BRIEF 5.8 (Skill · ข้อ 3 4 5 และเกณฑ์ผ่าน 2 ข้อ) · BRIEF 5.6 ข้อ 6 (เนื้อหาสกิลที่นำเข้า = เนื้อหาจากภายนอก) ·
  ADR-011 (สกิลเป็นข้อมูล ไม่ใช่โค้ด) · THREAT_MODEL T5 · การ์ด 0017 (ประตูสกิลอัตโนมัติ) · 0046/0066 (สกิลประจำเว็บ) · H2 H6 H7 H8 H9

## 1. ปัญหาที่แก้ และใครใช้

สกิลจะเข้ามาได้ 3 ทาง: Claude สร้างให้เอง (0017 · ติดตั้งอัตโนมัติ) · นำเข้าจากไฟล์ (มีแล้ว) · แชร์จากเพื่อน (คำแนะนำข้อ 5 · ยังไม่มี) ·
ยิ่งสกิลมาก ยิ่งต้องตอบได้ 3 ข้อ: **(ก) สกิลอันตรายเข้ามาไม่ได้ (ข) สกิลที่เข้ามาแล้วทำได้แค่ที่บอก (ค) ระบบยังเลือกสกิลถูกแม้มีสกิลเป็นสิบ ๆ ตัว** ·
ผู้ใช้: ทุกคนที่ติดตั้งสกิล · กรรมการที่จะถาม "ถ้าสกิลไม่ดีล่ะ" และ "สกิลเยอะแล้วระบบยังแม่นไหม"

## 2. "สกิลไม่ดี" มี 4 แบบ (นิยามก่อนวัด)

| แบบ | ตัวอย่าง | การ์ดนี้ |
|---|---|---|
| **A อันตราย** | ลบไฟล์ · รันคำสั่ง shell · เปิดลิงก์หลอก · อ่าน home คนอื่น · ออกเน็ตเอง · ขอสิทธิ์ที่ไม่มี | ✅ |
| **B หลอกผ่านข้อความ** (prompt injection) | "## คำสั่งให้ AI" สั่งให้ขอรหัสผ่าน/OTP/เลขบัตร · ให้บอกว่าทำแล้วทั้งที่ไม่ได้ทำ · แอบอ้างเป็นระบบ · สั่งให้ AI ส่งข้อมูลต่อ | ✅ |
| **C แย่งงาน / กว้างเกิน** | ตัวอย่างซ้ำสกิลเดิม · "ใช้กับทุกคำขอ" → ระบบเลือกผิด | ✅ |
| **D ทำงานไม่ถูก / ไม่ได้แก้ปัญหาจริง** | Claude สร้างไม่ตรงที่ขอ | การ์ดข้อ 6 (หน้าจัดการสกิล) · การ์ดนี้ใช้กลไกเดิม "ผิด 2 ครั้งปิดเอง" |

## 4. ช่องว่าง (เทียบ BRIEF 5.8 และคำแนะนำข้อ 10)

1. **ไม่มีชุดทดสอบอิสระของด่าน:** 15/15 มาจากชุดที่ผู้ช่วยเขียนเองและปรับประตูหลังเห็นผล → อ้างเป็นผลทดสอบในเล่มไม่ได้ ·
   เกณฑ์ BRIEF 5.8 ("อ่าน home คนอื่น ออกเน็ต เรียก Action นอก allow-list หรือแทรกคำสั่งผ่านเนื้อหา → ถูกปฏิเสธหรือต้องยืนยัน") ยังไม่มีชุดวัดครบ
2. **แบบ B ไม่มีตัวตรวจเนื้อหา:** ตัวตรวจดูแค่ความยาวของ prompt · **คาดว่า** prompt ที่ให้ขอรหัสผ่านจะผ่านได้ (ยังไม่ได้ลอง → วัดในขั้น 0)
3. **หน้าตรวจก่อนติดตั้ง (BRIEF 5.8 ข้อ 4) ยังไม่ครบ:** ไม่บอกสิทธิ์ที่เพิ่มจากรุ่นเดิม · ไม่บอกผลลองกับตัวอย่าง · ไม่บอกที่มา ·
   รุ่นแก้จาก Claude ที่ขอสิทธิ์เพิ่ม ยังติดตั้งเองได้ (ต้องตรวจว่าเป็นอย่างนั้นจริงในขั้น 0)
4. **ไม่รู้ว่าแกนกลางเลือกสกิลแม่นแค่ไหนเมื่อสกิลเยอะ:** ชุดวัดการเลือกสกิลมี 58 ข้อ (BRIEF ต้อง ≥ 100) · มีแค่สกิลในตัว 6 ตัว ·
   ไม่เคยวัดตอนมีสกิลของผู้ใช้ 20–50 ตัว · เกณฑ์ top-1 ใน BRIEF ยังเป็น "[ต้องกรอก]"
5. **ผู้ใช้ไม่เห็นประวัติ** ว่าสกิลไหนถูกปฏิเสธ ถูกปิดเอง หรือถูกกันเพราะอะไร (BRIEF 5.8: "บันทึกให้ผู้ใช้เห็น")

## 6. ออกแบบ (ร่าง · ปรับตามผลขั้น 0 · แก้เฉพาะช่องที่ขั้น 0 พบจริง)

1. **ตรวจเนื้อหา prompt (แบบ B):** รายการรูปแบบต้องห้าม เช่น ขอรหัสผ่าน · OTP · PIN · เลขบัตร/บัญชี · แอบอ้าง "ระบบ/ผู้ดูแล" ·
   "ไม่ต้องบอกผู้ใช้" · "บอกว่าทำแล้ว" → ไม่ผ่าน + บอกเหตุผลเป็นภาษาคน · ทำข้อความให้เป็นรูปเดียวกันก่อนตรวจ (ตัดอักขระล่องหน · รวมสระ) ·
   **ข้อจำกัดที่รู้ก่อน:** รายการคำเลี่ยงได้ด้วยการพูดอ้อม → ชั้นที่ 2 คือ prompt ไม่มีเครื่องมือ + ป้ายบอกที่มาของคำตอบ
2. **หน้าตรวจก่อนติดตั้ง** (นำเข้าจากไฟล์ · และรุ่นแก้ที่ขอสิทธิ์เพิ่ม): ชื่อ · มาจากไหน (Claude สร้าง / ไฟล์) · ทำอะไรบ้าง (ขั้นตอนเป็นภาษาคน) ·
   สิทธิ์ที่ขอเป็นรายการ · **สิทธิ์ใหม่เทียบรุ่นเดิม (เน้นสี)** · ผลลองกับตัวอย่าง (ระบบเลือกสกิลนี้ไหม · แย่งงานสกิลไหนไหม) · ปุ่ม ติดตั้ง / ยกเลิก ·
   สกิลที่ Claude สร้างใหม่ (0017) ยังติดตั้งอัตโนมัติเหมือนเดิม **ยกเว้น** รุ่นแก้ที่ขอสิทธิ์เพิ่ม = ต้องผ่านหน้าตรวจ
3. **ประวัติสกิล:** ในหน้า Skill แต่ละสกิลมี "ประวัติ" (ติดตั้ง · แก้ · ปิดเอง · ถูกกัน พร้อมเหตุผลและเวลา) · การนำเข้าที่ถูกปฏิเสธก็จดไว้
4. **แกนกลางเมื่อสกิลเยอะ:** ไม่แก้อะไรก่อนวัด · ถ้า S2 พบว่าแม่นลด → เลือกทางแก้จากผล (ปรับจำนวนสกิลที่ค้นส่งให้ AI ใน `retrieval.py` ·
   จำกัดจำนวนสกิลที่เปิดพร้อมกัน · ฯลฯ) แล้วเสนอ Pakon ก่อนทำ

## 7. ข้อมูล

ประวัติเก็บใน `index.json` เดิมของผู้ใช้ (home 0700 · ≤ 50 รายการต่อสกิล · เก่าสุดหลุดก่อน) · ไม่เก็บข้อมูลส่วนตัวเพิ่ม · ไฟดับ = เขียนแบบไฟล์ชั่วคราว + `os.replace` เหมือนเดิม

## 8. รอยต่อ (ร่าง)

`userskills.gate()` เพิ่มตรวจเนื้อหา · `userskills.review(skill_md, old_md | None) -> dict` (ข้อมูลหน้าตรวจ) · `UserSkills.history(id) -> list[dict]` ·
หน้าจอ: การ์ดตรวจก่อนติดตั้งใน `SkillsPage` (หน้าตาตาม skill `ui-ux-pro-max`)

## 9. กรณีที่ต้องคิดไว้ก่อน

ไฟล์ใหญ่/ไม่ใช่ข้อความ (ตัวตรวจขนาดเดิม) · คำต้องห้ามปนไทย-อังกฤษ หรือซ่อนด้วยอักขระล่องหน · สกิลเดิมที่ติดตั้งอยู่แล้วไม่ผ่านตัวตรวจใหม่ (ปิด + เหตุผล ไม่ลบ) ·
หลายผู้ใช้ (สกิลอยู่ใน home ของแต่ละคนอยู่แล้ว) · ออฟไลน์ (ตรวจในเครื่องทั้งหมด) · ทำงานแบบแชทงาน (0053) ที่ส่งเข้า Claude (ไม่ใช้ prompt ของสกิล · ตรวจซ้ำในเทสต์)

## 10. ต้นทุนบน Pi 5

โค้ดล้วน · ไม่เพิ่มโมเดล ไม่เพิ่ม dependency · ตรวจตอนติดตั้งเท่านั้น (คาดไม่ถึง 0.1 วิ) · ดิสก์ ~0 · การวัด S2 ใช้เวลา Pi ราว 1 ชั่วโมง (Gemma 3 รอบ × ≥ 150 ประโยค)

**เกณฑ์ top-1 ใน BRIEF 5.8 ("[ต้องกรอก]"):** ผู้ช่วยเสนอให้กรอกหลังขั้น 0 = ผล S2a ตอน 0 สกิล (ไม่แย่กว่าเดิม) · Pakon ตัดสิน

ไม่ผ่านข้อใด = ไม่ติดตั้ง ไม่รวมเข้า master จนกว่า Pakon ตัดสิน (กฎเหล็กข้อ 2) · บันทึกผลทุกรอบรวมรอบที่ไม่ผ่าน

## 12. ไม่ทำในรอบนี้

- ลายเซ็นดิจิทัลและแชร์ด้วยรหัส 6 หลัก → การ์ดข้อ 5 (ใช้หน้าตรวจของการ์ดนี้)
