# การ์ดออกแบบ 0084: ใช้ขีดจำกัดของบัญชี Claude แทนเพดานของระบบ

- **สถานะ:** **อนุมัติแล้ว (2026-11-18, Pakon "อนุมัติ")** · แผน [docs/plans/2026-11-18-0084-claude-account-limit.md](../plans/2026-11-18-0084-claude-account-limit.md) · ที่มา (Pakon ตัดสินแนวทางแล้วใน grilling 2026-11-18: บัญชี Pro · ลบเพดานออกจากโค้ดทั้งหมด · ชนขีดจำกัดต้องบอกผู้ใช้ตรง ๆ · ทำก่อนการ์ด 0083)
- **ข้อกำหนดที่อ้าง:** การ์ด 0016 (ไฮบริด) · การ์ด 0017 (สกิลอัตโนมัติ) · การ์ด 0021 (เชื่อมต่อ Claude) · การ์ด 0070 (ออกจาก Claude) · ADR-011

## 1. ปัญหาที่แก้ และใครใช้

ผู้ใช้ที่เชื่อม Claude ด้วยแพ็กเกจรายเดือน ถูกระบบตัดไม่ให้ถาม Claude หรือสร้างสกิลเมื่อ "ค่าใช้จ่ายอ้างอิง" ครบเพดานรายวัน
ทั้งที่บัญชี Pro ไม่เสียเงินเพิ่ม → ให้ขีดจำกัดของบัญชี Claude เป็นตัวตัดสินอย่างเดียว และบอกตรง ๆ เมื่อบัญชีใช้ครบ

## 2. หลักการที่ใช้ตัดสิน

| หลักการ | ใช้ยังไง |
|---|---|
| H2 ไม่ทำงานผู้ใช้หายโดยไม่แจ้ง | ไฟล์ `~/.local/share/aipc/cloud-usage.json` ของผู้ใช้เดิม **ไม่ลบ** · แค่ระบบเลิกอ่าน · สมุดบัญชีคลาวด์ (ledger) คงเดิมทุกอย่าง |
| H3 ความเป็นส่วนตัว | ไม่เปลี่ยนสิ่งที่ส่งออก · สวิตช์ "ให้ถาม Claude" และ ledger ยังอยู่ |
| H5 ความจริงก่อนความสวย | ชนขีดจำกัด → ข้อความบอกว่า "บัญชี Claude ใช้ครบแล้ว" พร้อมข้อความต้นฉบับของ Claude · ไม่ใช่ "ไม่มีอินเทอร์เน็ต" |
| H6 งานที่ต้องถูกแน่นอน = โค้ด | การจัดว่าเป็น "ชนขีดจำกัด" ทำด้วยโค้ดจาก `is_error` + ข้อความ · ไม่ให้ AI ตัดสิน |

## 3. ความสัมพันธ์กับชิ้นส่วนอื่น

- **ลบ:** `src/aipc/cloud/budget.py` · `tests/test_cloud_budget.py` · การเช็ก `budget.allow()` ใน `ui/app.py` (`_cloud_client` · `_skill_forge`) · ตัวเลือกระดับ น้อย/ปกติ/มาก/มากที่สุด ในหน้าตั้งค่า (`CloudUsage.limit` `limits` `levels` `usedPercent` `setLimit`) · แถบ % และป้าย "ครบวันนี้แล้ว"
- **ยังอยู่:** จำนวนครั้งที่ถาม Claude วันนี้ → นับจาก ledger แทน (ledger บันทึกเวลาทุกครั้งอยู่แล้ว)
- **ต้องแก้ตาม:** `CloudUsage.available` ตอนนี้ขึ้นกับ `budget is not None` → เปลี่ยนให้ขึ้นกับ "มี Claude" (`ledger is not None` / มีตัวส่งต่อ) ไม่งั้นการ์ดเชื่อมต่อ/ออกจาก Claude หายไปด้วย · ตัววัด `spikes/hybrid_eval.py` `spikes/skill_intent_eval.py` (เลิกส่ง budget)
- **มีคนพึ่ง:** การ์ด 0083 (วัดวงจรสกิล · ต้องไม่ถูกเพดานตัดกลางรอบ)
- **ชั้น:** cloud + ui · รันในโปรเซสหน้าจอของผู้ใช้

## 4. ข้อมูล

ไม่มีข้อมูลใหม่ · `cloud-usage.json` เดิมค้างอยู่ในโฮมผู้ใช้ (ไม่อ่าน ไม่ลบ · ขนาดเล็ก ≤ 31 วัน) · ledger เหมือนเดิม

## 5. รอยต่อ

- `ask.account_limit_message(data) -> str` ใช้ร่วมกัน · `ask.CloudReply` และ `forge.Reply` เพิ่มช่อง `limited: bool` (สร้างสกิล: ข้อความไปอยู่ใน `Proposal.errors`) · `True` เมื่อ Claude ตอบ `is_error` และข้อความตรงรูปแบบ "ใช้ครบ"
- ข้อความผู้ใช้เมื่อ `limited`: «บัญชี Claude ใช้ครบโควตาแล้ว · AI ในเครื่องยังใช้ได้ · Claude แจ้งว่า: “…”» (ตัดข้อความ Claude ≤ 200 ตัวอักษร · ถ้าข้อความมีเวลาที่ใช้ได้อีก ก็จะอยู่ในนั้นเอง)

**รูปแบบข้อความ "ใช้ครบ" — ยังไม่รู้แน่:** เอกสารทางการของ Claude Code ไม่ได้แสดงรูปแบบ error ของ `claude -p`
มีแค่รายงานบั๊กที่รูปแบบต่างกัน เช่น `is_error: true` + `result: "API Error: Rate limit reached"` ทั้งที่ exit code 0 และ subtype `success`
(github issue 79500) · "You're out of extra usage" + 429 (issue 57096 · บัญชี Max) ·
→ ตัวจัดใช้ `is_error` (ไม่ใช้ exit code/subtype) + คำใน `result`: `limit` `usage` `quota` `429` (ไม่สนตัวพิมพ์) · ไม่ตรง = ข้อความผิดพลาดแบบเดิม ·
**วิธีหาคำตอบ:** เมื่อบัญชีชนขีดจำกัดจริงครั้งแรก ledger จะเก็บข้อความต้นฉบับ → บันทึกลงหัวข้อ 10 แล้วปรับรายการคำ (ไม่ตั้งใจใช้โควตาจนหมดเพื่อทดสอบ)

## 6. กรณีที่ต้องคิดไว้ก่อน

- ไม่มีเน็ต → ข้อความเดิม "ติดต่อ Claude ไม่ได้ (ไม่มีอินเทอร์เน็ต?)" · ไม่ใช่ `limited`
- ข้อความ error อื่นที่มีคำว่า limit แต่ไม่ใช่โควตา (เช่น context limit) → อาจถูกจัดเป็น `limited` ผิด · ยอมรับได้เพราะข้อความต้นฉบับของ Claude แสดงด้วยเสมอ (ผู้ใช้เห็นของจริง)
- การสร้างสกิลระหว่างชนขีดจำกัด → `Proposal(ok=False)` + ข้อความเดียวกัน · ไม่ติดตั้งอะไร (การ์ด 0017 เดิม)
- **เพดานต่อครั้ง `--max-budget-usd`** (ถาม 0.50 · สร้างสกิล 1.00 ใน `ask.py` `forge.py`) = เพดานของระบบเหมือนกัน → **ลบ** (Pakon 2026-11-18) · การวนไม่รู้จบยังถูกกันด้วย `--tools ""` (ไม่มีเครื่องมือ) และเวลาจำกัด `TIMEOUT_S`

## 9. ไม่ทำในรอบนี้

- ไม่อ่านโควตาที่เหลือของบัญชีมาแสดง (Claude Code ไม่มีคำสั่งอ่านโควตาแบบ headless ที่ผมยืนยันได้ · ยังไม่รู้)
