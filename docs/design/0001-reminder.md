## 1. ปัญหาที่แก้ และใครใช้

ผู้ใช้พูดหรือพิมพ์นัดเป็นประโยคธรรมดา ("เตือนส่งรายงานวันศุกร์หน้าบ่ายสอง") แล้วเครื่องจำและเตือนให้เมื่อถึงเวลา
โดยไม่ต้องกรอกฟอร์มวันที่ · Pakon เลือกสกิลนี้เองว่าได้ใช้จริง

## 4. ข้อมูล

- **เก็บ:** `id, what, when (ISO 8601 พร้อมเขตเวลา), remind_before_min, created, done, fired`
- **เจ้าของ:** ผู้ใช้ที่สร้าง · **ที่เก็บ:** `~/.local/share/aipc/reminders.json` (ใน home ที่เข้ารหัส)
- **เขียน:** atomic · เก็บสำเนาก่อนหน้า 1 รุ่น (`reminders.json.bak`) กันไฟล์เสียจากสาเหตุอื่น
- **ไฟดับกลางคัน:** ได้ไฟล์เก่าหรือไฟล์ใหม่ครบ อย่างใดอย่างหนึ่ง (rename เป็น atomic)
- **ไฟล์เสีย:** ใช้ `.bak` แล้วบอกผู้ใช้ · ถ้าทั้งคู่เสีย แสดงว่าอ่านไม่ได้ และ **ไม่เขียนทับ** จนผู้ใช้เลือก
- **ลบ:** ผู้ใช้ลบรายการได้ · Privacy Center จะแสดงหมวดนี้ (ภายหลัง)

## 5. รอยต่อ

```text
when.parse(text: str, now: datetime) -> WhenResult
    WhenResult = { at: datetime | None, what: str, assumptions: list[str], confident: bool }
    # assumptions = สิ่งที่ตีความเอง เช่น "ไม่ได้บอกเวลา ใช้ 09:00" · แสดงให้ผู้ใช้เห็นทุกข้อ

ReminderStore.load() / add(r) / update(r) / delete(id) / list()
Scheduler.due(now) -> list[Reminder]      # ถึงเวลาเตือนแล้ว
Scheduler.missed(now) -> list[Reminder]   # เลยเวลาไปขณะที่ไม่ได้เปิดใช้
```

## 6. กรณีที่ต้องคิดไว้ก่อน

| กรณี | ทำยังไง | หลักการ |
|---|---|---|
| "ศุกร์นี้" กับ "ศุกร์หน้า" | กำหนดชัด: **นี้** = ศุกร์ที่ใกล้ที่สุดที่ยังไม่ผ่าน · **หน้า** = ศุกร์ของสัปดาห์ถัดไป · แสดงวันที่ให้ยืนยันเสมอ เพราะคนไทยใช้สองคำนี้ไม่ตรงกันทุกคน | H5 H6 |
| ไม่บอกเวลา ("พรุ่งนี้ส่งรายงาน") | ใช้ 09:00 แล้วเขียนในการ์ดว่า "ไม่ได้บอกเวลา ใช้ 09:00" ให้แก้ได้ | H5 |
| ไม่บอกวัน ("บ่ายสองโทรหาแม่") | วันนี้ ถ้าเวลาผ่านไปแล้ว → พรุ่งนี้ พร้อมบอกว่าเลื่อนเป็นพรุ่งนี้ | H5 |
| หาเวลาไม่เจอเลย | ไม่บันทึก · ถามให้ระบุเวลา (เมื่อมี LLM จะลองให้ LLM แยกคำก่อน) | H5 H6 |
| เวลาแบบไทย | บ่ายโมง–บ่ายห้า = 13–17 · X โมงเย็น = 12+X · X ทุ่ม = 18+X · ตี X = X · เที่ยง / เที่ยงคืน · "ครึ่ง" = 30 นาที · 14:00 / 14.30 | H6 |
| ปิดเครื่อง/Logout ตอนถึงเวลา | ไม่มีใครเตือน (Logout ปิดโปรเซสทั้งหมด BRIEF 5.2 ข้อ 6) → เข้าใช้ครั้งถัดไปแสดง "พลาดไป N รายการ" | H2 |
| นาฬิกาผิดหลังไฟดับ | บันทึก "เวลาล่าสุดที่เห็น" · ถ้าเวลาปัจจุบันถอยหลังกว่านั้น แสดง "นาฬิกาเครื่องอาจไม่ถูก การเตือนอาจคลาดเคลื่อน" | H2 H5 |
| หลายผู้ใช้ | แต่ละคนมีไฟล์ใน home ของตัวเอง · ไม่มีนัดกลาง | H3 |

## 7. ต้นทุนบน Pi 5

RAM < 1 MB · CPU: ตรวจทุก 30 วินาที (เปรียบเทียบเวลาในรายการ ไม่กี่ร้อยรายการ) · ดิสก์: KB · **เรียก LLM: 0 ครั้ง** สำหรับประโยคทั่วไป

## 8. การทดสอบ และเกณฑ์ผ่าน (ประกาศก่อนสร้าง)

- **ชุดประโยค 50 ข้อ** เก็บเป็นไฟล์ข้อมูลใน repo พร้อมวันเวลาที่ถูกต้อง โดยตรึง "ตอนนี้" ไว้ที่ค่าเดียว (พ. 23 ก.ย. 2569 10:00)
  - 40 ข้อ **รูปแบบที่ประกาศว่ารองรับ** (หัวข้อ 6) → ต้องถูก **100%** เพราะเป็นกฎที่กำหนดแน่นอน ผิดข้อเดียว = บั๊ก
  - 10 ข้อ **รูปแบบยาก/ไม่รองรับ** → ต้อง **ไม่บันทึกผิดเงียบ ๆ แม้แต่ข้อเดียว** (ถามกลับหรือบอกสมมติฐาน) และรายงานว่าตีความได้กี่ข้อ
  - ชุดนี้คือชุดเดียวกับที่ใช้ในบทที่ 4 (SKILLS.md สกิล 3)
- เทสต์ตัวเก็บข้อมูล: atomic, ไฟล์เสียใช้ .bak, ไฟล์เสียทั้งคู่ไม่เขียนทับ
- เทสต์ตัวจับเวลา: ถึงเวลา / เตือนก่อน N นาที / พลาดขณะปิดเครื่อง / นาฬิกาถอยหลัง — ด้วยนาฬิกาปลอม
- เกณฑ์การเตือนตรงเวลา ±1 นาที (SKILLS.md) วัดบน Pi 5 ภายหลัง

## 9. ไม่ทำในรอบนี้

- นัดซ้ำ ("ทุกวันจันทร์") — ต้องออกแบบกฎเพิ่ม และทดสอบมากขึ้น
- เสียงเตือน / อ่านออกเสียง — รอ TTS (ADR-006)
- ซิงก์ข้ามเครื่อง / ปฏิทินออนไลน์ — ขัด local-first
- ให้ LLM แยกประโยคยาก — รอ LLM (ADR-007) · รอยต่อเตรียมไว้แล้ว
