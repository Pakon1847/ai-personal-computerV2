## 1. ปัญหาที่แก้ และใครใช้

งานในเว็บที่ทำซ้ำหลายคลิก (เปิดเมนู → เลือกคุณภาพ 1080p · เปิดหน้าสุ่มของวิกิ · กดภาษาอังกฤษ) ยังสั่งด้วยเสียงไม่ได้ ·
การ์ด 0046 เพิ่มคำสั่งได้แค่ "พูดว่าอยากได้อะไร" ให้ Claude เดาปุ่มเอง (Claude ไม่เห็นหน้าเว็บจริง) →
**ให้ผู้ใช้ทำให้ดูหนึ่งครั้ง ระบบจดว่ากดอะไร แล้ว Claude เขียนเป็นคำสั่งเสียงที่ทนกว่าการจดตรง ๆ**

มุมวิจัย: Programming by Demonstration (Cypher, *Watch What I Do*, MIT Press 1993 · ต้องตรวจอ้างอิงก่อนใส่เล่ม) + LLM ช่วยสรุปตัวเลือกปุ่มให้ทนต่อหน้าเว็บที่เปลี่ยน

## 2. ออกแบบ

**บันทึก (โค้ด · ในเบราว์เซอร์ของผู้ช่วย):**
1. "จำขั้นตอนนี้" / "เริ่มบันทึก" (พูดหรือปุ่ม) ขณะเปิดเว็บที่คุมได้ → ฝังตัวบันทึก (`Page.addScriptToEvaluateOnNewDocument` + ทันที) → แถบบนจอ "กำลังบันทึก · พูด 'เสร็จแล้ว' เมื่อจบ"
2. ตัวบันทึกจดใน `sessionStorage` ของแท็บ (อยู่ข้ามการเปลี่ยนหน้าในเว็บเดียวกัน · ตัวต่อเบราว์เซอร์ตอนนี้ไม่รับเหตุการณ์จากหน้าเว็บ จึงไม่ต้องแก้ cdp.py):
   - **คลิก:** ลักษณะของปุ่ม (tag · id · data-testid · aria-label · role · ข้อความบนปุ่ม ≤ 40 ตัวอักษร · เส้นทาง CSS) · **ไม่จดตำแหน่งบนจอ**
   - **คีย์ลัด:** เฉพาะตอนไม่ได้อยู่ในช่องพิมพ์ (key + Shift/Ctrl/Alt)
   - **ไม่จดเด็ดขาด:** ตัวอักษรที่พิมพ์ · ค่าในช่องกรอก · คลิกในช่องรหัสผ่าน/ฟอร์มชำระเงิน (H1 H3)
3. "เสร็จแล้ว ตั้งชื่อว่า …" → อ่านบันทึก → การ์ดแสดงขั้นที่จดเป็นภาษาคน ("คลิกปุ่ม 'การตั้งค่า' → คลิก '1080p'") → "ให้ Claude ทำเป็นคำสั่ง … ไหม"

**Claude เขียน (forge · คำขอ = ชื่อคำสั่ง + ขั้นที่จด + ชื่อเว็บ · ไม่มีข้อมูลอื่น):**
- ตัวเลือกปุ่มที่ทนกว่า (aria-label / data-testid ก่อนเส้นทาง CSS ยาว ๆ) · คำพูดภาษาไทยแบบอื่น 2–3 แบบ
- ได้สกิลประจำเว็บแบบเดิม (การ์ด 0046) **+ คำสั่งหลายขั้น** `- เลือกความละเอียดสูงสุด → คลิก A แล้ว คลิก B` (≤ 5 ขั้น · ทำทีละขั้น · ขั้นไหนหาปุ่มไม่เจอ = หยุดแล้วบอก ไม่ข้ามไปขั้นถัดไป)
- ตัวตรวจเดิมทั้งหมด (คำเสี่ยงต้องยืนยันก่อน · ห้ามตัวเลือกรหัสผ่าน/ชำระเงิน) + คนอนุมัติก่อนติดตั้ง

**ทำไมไม่จดแล้วเล่นซ้ำตรง ๆ:** เส้นทาง CSS ที่จดได้ (`div:nth-child(3) > button`) พังเมื่อหน้าเว็บขยับ · Claude เลือกคุณลักษณะที่มีความหมาย → วัดเทียบกัน (L3)

## 3. ข้อมูล
