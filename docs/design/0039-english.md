# การ์ดออกแบบ 0039: รองรับภาษาอังกฤษ (หน้าจอ · คำตอบ · เสียง) คู่กับภาษาไทย

- **สถานะ:** **Pakon อนุมัติเกณฑ์ระยะ A (A1–A3) + หน้าเข้าสู่ระบบแสดงสองภาษา (2026-10-18 "ใช้ตามนี้")** · **Pakon เลือกขอบเขตครบ A–D (2026-10-18)** · ลำดับ: ติดตั้งรุ่นแก้บั๊กก่อน แล้วเริ่มระยะ A · เกณฑ์ในหัวข้อ 8 ยังเป็นร่าง (ยืนยันก่อนเริ่มแต่ละระยะ) · ระยะ D ต้องมีการ์ดย่อยของตัวเองก่อนเขียนโค้ด ·
  ผู้ช่วยแจ้งความเสี่ยงแล้ว: ครบ A–D ≈ ทำงานภาษาไทยทั้งโปรเจกต์ซ้ำ · ร่าง 2026-10-18 · Pakon ขอ "ทั้งระบบต้องรองรับภาษาอังกฤษได้ทั้งหมด รวมทั้งคำพูด"
- **ข้อกำหนดที่อ้าง:** BRIEF หัวข้อ 1 ("ใช้ภาษาไทยเป็นหลัก") · BRIEF 5.6 (เสียง) · ADR-006 (TTS) · ADR-014 (ไลเซนส์) · H4 H5 H6 H9

## 1. ปัญหาที่แก้ และใครใช้

คนที่ไม่ถนัดภาษาไทย (หรือพูดไทยปนอังกฤษ) ใช้เครื่องได้ทั้งหน้าจอ คำตอบ และเสียง · ผู้ใช้หลักยังเป็นคนไทย → ภาษาไทยต้องไม่แย่ลง

## 2. สภาพตอนนี้ (สำรวจโค้ด 2026-10-18)

| ส่วน | ตอนนี้ | งานถ้าจะรองรับอังกฤษ |
|---|---|---|
| ข้อความหน้าจอ QML | ภาษาไทยเขียนตายตัว **514 ข้อความ / 40 ไฟล์** · ไม่มีระบบแปล (ไม่มี qsTr/QTranslator) | ทำระบบเลือกภาษา + แปลทุกข้อความ |
| ข้อความจาก Python (การ์ด คำตอบ ข้อผิดพลาด) | ภาษาไทยตายตัว **~4,000 ข้อความ / 152 ไฟล์** (นับรวมข้อความในเทสต์/วัดผลบางส่วน) | แปลเฉพาะที่ผู้ใช้เห็น |
| ตัวแปลคำสั่งแบบกฎ (สกิล 22 โมดูล: คำสั่งเครื่อง นัด เว็บ ปฏิทิน วันหยุด ถามเวลา …) | regex ภาษาไทยทั้งหมด | เขียนกฎภาษาอังกฤษใหม่ทุกตัว + ชุดวัดใหม่ทุกการ์ด (H9) |
| แชทกับ AI ในเครื่อง (Gemma) | โมเดลหลายภาษา · system prompt ภาษาไทย | สั่งให้ตอบตามภาษาของผู้ใช้ · วัดคุณภาพคำตอบอังกฤษ |
| ถอดเสียง (คีย์ลัด) | Zipformer **ไทยล้วน** + hotwords ไทย | ต้องมีโมเดลอังกฤษ หรือโมเดลหลายภาษา · ยังไม่รู้ว่าแบบไหนพอบน Pi (ต้องวัด) |
| ถอดเสียง (ปุ่มไมค์ในแชท) | whisper.cpp บังคับ `-l th` | whisper รองรับอังกฤษอยู่แล้ว · ต้องเลือกภาษา/ตรวจภาษาอัตโนมัติ |
| อ่านออกเสียง | Piper `th_TH-tsync2-medium` (ไทยล้วน) | เพิ่มเสียงอังกฤษของ Piper · ตรวจไลเซนส์น้ำหนักโมเดลก่อน (ADR-014) |

## 3. แบ่งเป็นระยะ (แต่ละระยะอนุมัติ/วัดแยก · ทำระยะถัดไปเมื่อระยะก่อนผ่าน)

| ระยะ | ทำอะไร | ขนาดงาน (ประมาณ · ไม่แน่นอน) |
|---|---|---|
| **A. หน้าจอ + คำตอบ** | สวิตช์ภาษาในหน้าตั้งค่า (ต่อบัญชี · ค่าเริ่มต้นไทย) · แปลข้อความหน้าจอและการ์ดที่ผู้ใช้เห็น · AI ตอบภาษาเดียวกับที่ผู้ใช้พิมพ์ | ใหญ่ (หลายวัน) · เสี่ยงต่ำ |
| **B. อ่านออกเสียงอังกฤษ** | เพิ่มเสียง Piper อังกฤษ · เลือกเสียงตามภาษาของข้อความ | กลาง · ต้องตรวจไลเซนส์ + วัดความหน่วง/RAM บน Pi |
| **C. พิมพ์คำสั่งภาษาอังกฤษ** | กฎภาษาอังกฤษสำหรับคำสั่งหลัก (เปิดแอป · เสียง · นัด/เตือน · ถามเวลา/นัด · ค้นเว็บ) | ใหญ่ · ต้องมีชุดวัดอังกฤษที่ไม่เห็นโค้ดทุกสกิล |
| **D. พูดคำสั่งภาษาอังกฤษ** | โมเดลถอดเสียงอังกฤษ (หรือหลายภาษา) ทางคีย์ลัด + ปุ่มไมค์ | ใหญ่ที่สุด · เสี่ยงสูง (RAM ความเร็ว ความแม่น · ต้องเทียบโมเดลบน Pi ใหม่ทั้งชุด) |

**ความเห็นของผู้ช่วย (ติตรง ๆ):** ทำครบ A–D เท่ากับทำงานภาษาไทยที่ใช้เวลามาทั้งโปรเจกต์ซ้ำอีกรอบ (ตัวแปลกฎ 22 โมดูล + ชุดวัด + เสียง) ·
วันส่งเล่มยังไม่แน่นอน และยังมีงานค้างจากตรวจทั้งระบบ (image microSD · แบต RTC · ซ้อมสาธิต · ติดตั้งรุ่นใหม่) ·
แนะนำทำ **A + B ก่อน** (เห็นผลชัด เสี่ยงต่ำ อธิบายกรรมการได้) แล้วเขียน C–D เป็นงานต่อยอดในบทที่ 5 · ถ้าต้องการ C ให้เลือกเฉพาะคำสั่งหลักไม่กี่ตัว

## 4. ข้อมูล

เก็บแค่ค่าภาษาที่เลือกในไฟล์ตั้งค่าเดิมของบัญชี (`~/.config/aipc/ui.json`) · ไม่เก็บอะไรเพิ่ม · ข้อความแปลอยู่ในโค้ด (ไม่ใช่ข้อมูลผู้ใช้)

## 5. รอยต่อ

- ระยะ A: ฟังก์ชันเดียวคืนข้อความตามภาษา (เช่น `tr("key")` ทั้ง QML และ Python) · ค่าภาษามาจาก UiSettings
- ระยะ B: `tts.speak(text)` เลือกเสียงจากภาษาของข้อความ (ตัวอักษรไทยหรือไม่ = โค้ด ไม่เดา · H6)
- ระยะ C–D: ตัวแปลแต่ละสกิลรับข้อความอังกฤษได้ · คืนชนิดคำสั่งเดิม (ไม่เปลี่ยนทางที่ทำงาน)

## 6. กรณีที่ต้องคิดไว้ก่อน

พูด/พิมพ์ไทยปนอังกฤษ ("เปิด YouTube") ต้องยังไปทางไทยเหมือนเดิม · ข้อความที่ยังไม่ได้แปลต้องแสดงภาษาไทย ไม่แสดงช่องว่าง ·
วันที่/เวลา: ไทยใช้ พ.ศ. · อังกฤษใช้ ค.ศ. · หลายบัญชีเลือกภาษาต่างกันได้ · หน้าเข้าสู่ระบบ (ก่อนรู้ว่าเป็นใคร) ใช้ภาษาอะไร = ยังไม่รู้ (เสนอ: สองภาษา)

## 7. ต้นทุนบน Pi 5

- A: ~0 RAM/CPU · ดิสก์ ~0
- B: เสียง Piper อังกฤษ 1 เสียง = ดิสก์และ RAM ระดับเดียวกับเสียงไทยที่ใช้อยู่ (ต้องวัดจริง · ยังไม่รู้ตัวเลข)
- C: ~0 (กฎล้วน)
- D: ยังไม่รู้ · โมเดลถอดเสียงตัวที่สองอาจกิน RAM/CPU เท่าตัวเดิม · ต้องวัดบน Pi ก่อนตัดสิน
