## 1. ปัญหาที่แก้ และใครใช้

คนทั่วไปใช้ 5 บริการนี้ทุกวัน แต่ตอนนี้เครื่องเปิดได้แค่ Gmail ด้วยคำสั่ง ไม่มีปุ่มกด ·
และคำสั่งที่พิมพ์ (`xdg-open` → Chromium ปกติ) กับคำสั่งเสียง (เบราว์เซอร์ของผู้ช่วย) ใช้**คนละโปรไฟล์** = ต้องเข้าสู่ระบบ 2 รอบ ·
ผู้ใช้: ทุกบัญชี · วันสอบ: กดปุ่มหรือพูด "เปิดเฟซบุ๊ก" → "เลื่อนลง" → "ย้อนกลับ"

- `BrowserController.openSite(key) -> bool` (ปุ่ม) · ทางพิมพ์และขั้น "เปิดเว็บ" ของสกิล (`open_url`) → เบราว์เซอร์ของผู้ช่วยตัวเดียวกัน ·

- QML: หน้าแรกเพิ่มแถว "แอปที่ใช้บ่อย" 6 ปุ่ม (YouTube · Facebook · Instagram · Gmail · ปฏิทิน · ไดรฟ์) ไอคอนทั่วไป + ชื่อ **ไม่ใช้โลโก้ของบริษัท** (เครื่องหมายการค้า/ไลเซนส์) ·
  หน้าตั้งค่าเพิ่ม "บัญชีเว็บในเครื่องนี้": ข้อความ 2 บรรทัด (ใส่รหัสในหน้าของบริการเอง ระบบไม่เห็นรหัส · ใช้เครื่องร่วมหรือจะคืนเครื่องให้กดปุ่มนี้) + ปุ่ม

## 6. กรณีที่ต้องคิดไว้ก่อน

- **Google/Facebook ไม่ยอมให้เข้าสู่ระบบในเบราว์เซอร์ที่ถูกควบคุม** ("เบราว์เซอร์หรือแอปนี้อาจไม่ปลอดภัย") — **ยังไม่รู้** ว่าเบราว์เซอร์ของผู้ช่วย
  (เปิดด้วย `--remote-debugging-pipe`) โดนไหม · หาคำตอบ: ข้อ 8.0 ก่อนเขียนโค้ด · ถ้าโดนบล็อก: บริการนั้นเปิดด้วยเบราว์เซอร์ปกติ
  และคำสั่งเสียงเลื่อน/ย้อนกลับใช้กับบริการนั้นไม่ได้ (เขียนในเล่มตามจริง)
- **ประโยคชน:** "เพิ่มนัดในปฏิทิน…" มีคำว่า "นัด" → ไม่ใช่คำสั่งตอนนี้อยู่แล้ว (LATER_WORDS) · "ไดรฟ์" กับ "ไฟล์" · "เปิดเสียง" กับ "เปิดเฟส…" → เทสต์ทุกคู่
- **หลายผู้ใช้:** โปรไฟล์อยู่ใน home ของแต่ละคน · ออกจากระบบเครื่อง = เบราว์เซอร์ปิด แต่การเข้าสู่ระบบเว็บยังจำไว้ (ตั้งใจ เหมือนคอมทั่วไป) · ลบบัญชีเครื่อง = หายทั้งหมด (มีแล้ว)
- **หลอกกล้องหน้าเข้าเครื่องได้ = เข้าบัญชีเว็บที่ค้างไว้ได้** (ความเสี่ยงเดิมใน THREAT_MODEL ขยายจาก Gmail เป็น 5 บริการ) → แก้ข้อความใน THREAT_MODEL · ข้อความในหน้าตั้งค่า · เดโมใช้บัญชีทดสอบ
- **"เข้าลิงก์แรก" บนฟีด Facebook** อาจเปิดลิงก์ที่ไม่คาด (ฟีดไม่มีลำดับผลค้นหา) → ข้อจำกัด
- **ไม่มีเน็ต:** หน้าเว็บขึ้นข้อผิดพลาดของบริการเอง · ปุ่มยังเปิดเบราว์เซอร์ได้
- **RAM:** Facebook/Instagram หนัก + AI ในเครื่อง → วัด (ข้อ 8.3)

## 7. ต้นทุนบน Pi 5

โค้ดเรา ~0 · ไม่มีโปรเซสใหม่ (Chromium ตัวเดิม) · RAM ของหน้าเว็บ: **ยังไม่รู้** → วัดข้อ 8.3 · ดิสก์: แคชของโปรไฟล์ (บันทึกขนาดหลังทดสอบ) ·
เรียก LLM 0 ครั้ง · ทางส่งออกใหม่จากโค้ดเรา: ไม่มี (ผู้ใช้เปิดเว็บเอง · สมุดบันทึกสิ่งที่ส่งออกไม่เปลี่ยน) · dependency ใหม่: ไม่มี

## 9. ไม่ทำในรอบนี้

- ดึงหรือให้ AI อ่านเนื้อหา Facebook/Instagram — ไม่มี API สำหรับบัญชีส่วนตัว (Instagram ปิด 4 ธ.ค. 2024) · ข้อตกลง Meta 3.2.3
- Gmail/Drive แบบดึงข้อมูลเข้าเครื่องหรือให้ AI สรุป — ต้องใช้ OAuth: โหมด Testing ต้องเข้าสู่ระบบใหม่ทุก 7 วัน · มีหน้าเตือน "แอปยังไม่ได้รับการตรวจสอบ" ·
  ผู้ใช้ต้องตั้งค่า Google Cloud เอง = **คนทั่วไปทำไม่ได้** · กุญแจบัญชีอยู่บน microSD ที่ไม่เข้ารหัส = **ไม่ปลอดภัย** → บทที่ 5
- แจ้งเตือนจากบริการ · โพสต์หรือส่งข้อความด้วยเสียง · จัดการรหัสผ่านเว็บ · โลโก้บริษัท
- ค้นในจีเมล/ไดรฟ์ด้วยเสียง ("หาอีเมลจากธนาคาร") — คำว่า "หา…" ชนกับค้นไฟล์ในเครื่องและค้นเว็บ ต้องออกแบบกฎแยก → รอบหน้า
