## 1. ปัญหาที่แก้ และใครใช้

| # | ปัญหา | หลักฐาน |
|---|---|---|
| ก | ถามข่าวในบทสนทนาที่ Claude เคยตอบแล้ว · AI ในเครื่องตอบว่า "ไม่มีข้อมูลสด" ยาว 183 ตัวอักษร → **ไม่ส่งต่อ** (กฎยอมแพ้ ≤ 160) | [T6 2026-10-08](../benchmarks/2026-10-08-t6-new-pi5/README.md) |
| ข | บันทึกส่งออกเขียน `ok: false` ทั้งที่สกิลติดตั้งได้ · ผู้ใช้เห็นในหน้า "สิ่งที่ส่งออก" ว่าล้ม | T6 ข้อ 5 · [cloud e2e](../benchmarks/2026-10-05-cloud-e2e-pi5/README.md) ข้อ 2 |

| ง | การแก้สกิลตามคำติ ("ไม่ใช่แบบนี้") ทดสอบกับ Claude ปลอมเท่านั้น | auto-skill "ยังไม่ได้ทดสอบ" |
| จ | ชุดสอบไฮบริดเดิมถามทีละข้อ ไม่มีบทสนทนาต่อเนื่อง = ไม่เคยวัดกรณี ก | [exam hybrid](../benchmarks/2026-10-06-exam-hybrid-gemma/README.md) |

**ข สาเหตุ (อ่านโค้ด 2026-10-12):** `forge.Proposal.ok` = ผ่าน "ทดลองเส้นทาง" กับตัวคัดสกิล **แบบกฎ** ด้วย ·
แต่แอปติดตั้งเมื่อไฟล์ผ่านประตูตรวจ (`userskills.gate`) ไม่ได้ดู `ok` · `app._skill_forge` เขียน `ok=p.ok` ลงบันทึกส่งออก ·
cloud e2e ได้ `attempts 1 · errors []` และ `run.py` ไม่ส่ง `check` → ไม่มีรอบแก้ → `ok: false` มาจากทดลองเส้นทางแน่นอน (ข้อไหนไม่รู้ เพราะไม่ได้บันทึก)

### ส่วน 1: ส่งต่อคำถาม (ชุด H1 · `tests/data/hybrid_h1.json` · 40 กรณี)

ทางเดียวกับแอป: กฎคำสั่งเครื่อง (`route_ai_first`) → AI ในเครื่องพร้อม ask-cloud + create-skill + สกิล → ส่งต่อเมื่อเลือก ask-cloud หรือ `local_gave_up` → Claude จริง

| # | เกณฑ์ | ผ่านเมื่อ |
|---|---|---|
| 1.1 | คำถามข้อมูลสด (L · 16 กรณี) ถูกส่งต่อ | ≥ 15/16 **และ** กรณีที่มีบทสนทนาก่อนหน้าซึ่ง Claude เคยตอบ ≥ 7/8 |
| 1.2 | คำถามที่ AI ในเครื่องควรตอบเอง (K · 16) ถูกส่งต่อทั้งที่ไม่ควร | ≤ 2/16 |
| 1.3 | สั่งงาน/สกิล (S · 8) ถูกส่งไป Claude | 0/8 |
| 1.4 | ข้อที่ส่งต่อ Claude ตอบสำเร็จ (`ok`) | ≥ 95% · เวลา Claude มัธยฐานรายงาน |
| 1.5 | บันทึกส่งออกตรงกับที่ส่งจริง (ใช้ `app._cloud_client` + ledger ชั่วคราว) | ทุกครั้ง |
| 1.6 | ไม่ถอยบนชุดสอบเดิม (คำนวณกฎใหม่จากคำตอบเดิมใน `gemma4-e2b-p3.json` · ไม่รันโมเดลใหม่) | ข้อมูลสด 12/12 ยังจับได้ · ข้อที่ไม่ควรส่งเพิ่มขึ้น ≤ 1 |

รายงานคู่: กฎเดิม vs กฎใหม่ บนคำตอบ **ชุดเดียวกัน** ของ AI ในเครื่อง (กฎดูข้อความหลังตอบ จึงเทียบได้ตรง)

### ส่วน 2: สกิลที่ Claude สร้างทำตามที่ขอ (ชุด H2 · `tests/data/skill_intent_h2.json` · 10 คำขอ)

ทางเดียวกับแอป: forge (sonnet + ประตูตรวจ) → ติดตั้งลงโฟลเดอร์ชั่วคราว → สั่งประโยคเดิมอีกครั้ง → ทำงาน

| # | เกณฑ์ | ผ่านเมื่อ |
|---|---|---|
| 2.1 | ติดตั้งได้ | ≥ 9/10 |
| 2.2 | **ทำตามที่ขอ**: สกิลสั่งเครื่อง = ชุดคำสั่ง (ไม่นับ "บอก:") ตรงกับที่เขียนไว้ก่อนทุกข้อ ไม่ขาดไม่เกิน · สกิลงานภาษา = รันบน Gemma กับข้อความทดสอบแล้วผ่านตัวตรวจที่เขียนไว้ก่อน | ≥ 8/10 |
| 2.3 | สั่งประโยคเดิมอีกครั้ง → เรียกสกิลใหม่ | ≥ 8/10 |
| 2.4 | แก้ตามคำติด้วย Claude จริง (3 คำขอที่กำหนดคำติ + ผลที่ต้องเปลี่ยนไว้ก่อน) | ≥ 2/3 |
| 2.5 | บันทึกส่งออกของการสร้างสกิล `ok` = Claude สร้างไฟล์ที่ผ่านตัวตรวจได้ | ตรงกับที่ติดตั้งได้ทุกครั้ง |

## 9. ไม่ทำในรอบนี้

- คำตอบผิดแบบมั่นใจของ AI ในเครื่อง (ชุดสอบ G01 เงินทอน · G17 วันในสัปดาห์) ไม่ส่งต่อเพราะ AI ไม่รู้ว่าผิด · ไม่มีตัวตรวจที่เชื่อถือได้ → ข้อจำกัด
- ให้คนตรวจความถูกของคำตอบ Claude (งานค้างเดิม 16 ข้อ · Pakon ตัดสิน 15 ต.ค.)
- เปลี่ยนสิ่งที่ส่งออก หรือโมเดลของ Claude

## 10. ผลและสิ่งที่เปลี่ยนจากแผน (2026-10-12)

- **ไม่ได้แก้กฎยอมแพ้** (แผนเดิมข้อ ก): ชุดพัฒนา D1 ชี้ว่าต้นเหตุคือ AI ในเครื่องเห็นเนื้อหาของ Claude แล้วลอก/แต่งข้อมูลสดตาม ไม่ใช่ความยาว ·
  คำตอบยาวที่ขึ้นต้นว่า "ไม่มีข้อมูลสด" ใน D1 เป็นความรู้ที่ตอบต่อถูกแล้ว → แก้ที่ `ChatController._for_local` (ส่งแค่ป้าย) + ตอบแค่ป้าย = ส่งต่อ
- H1 รอบแรกใช้ไม่ได้ (tunnel หลุด) · รันใหม่ทั้งชุดด้วยโค้ดระบบเดิม · L05 (คำตอบ "ไม่ทราบ" 178 ตัวอักษร) พลาดทั้งสองรอบ → ข้อจำกัด ไม่ปรับกฎ (H9)
