# การ์ดออกแบบ 0024: สั่งเว็บด้วยเสียงโดยไม่ใช้เมาส์

- **สถานะ:** สร้างบนสาขาแล้ว · ไม่ผ่านเกณฑ์ข้อ 2 · ข้อ 7 รอ Pakon · สร้างบนสาขา `feature/0024-voice-browser` · **ไม่ติดตั้งบน Pi และไม่รวมเข้า master จนกว่าจะผ่านเกณฑ์ข้อ 8 และ Pakon อนุมัติ** (หยุดเพิ่มฟีเจอร์ตั้งแต่ 9 ต.ค. · STATUS)
- **ที่มา:** Pakon 2026-10-13 ~02:00 "อยากได้การสั่งงานด้วยเสียงคือไม่ต้องมีเมาส์ก็สามารถคลิกได้ เช่น สั่งเปิด google แล้วสั่งเสียงว่าค้นหาราคาทองหน่อยเข้าลิ้งค์แรก ก็เข้าลิ้งค์แรกให้เลย บอกย้อนกลับก็ย้อนกลับให้เลย" ·
  เลือก "ทำต่อแยกจากแอป" · ตอบคำถามออกแบบ 4 ข้อ (หัวข้อ 2)
- **ข้อกำหนดที่อ้าง:** การ์ด 0019 (เสียง: whisper.cpp + piper · ข้อ 9–10 แตะครั้งเดียวหยุดเองเมื่อเงียบ) · การ์ด 0004 (เซสชัน labwc) · BRIEF H3 (ไฟไมค์) · H9 (ประกาศเกณฑ์ก่อนวัด)

## 1. ปัญหาที่แก้ และใครใช้

ตอนนี้ต้องคลิกปุ่มไมค์ในแอป แล้วกดส่งเอง และสั่งอะไรในหน้าเว็บไม่ได้เลย (ค้นหา เข้าลิงก์ ย้อนกลับ ต้องใช้เมาส์) ·
ผู้ใช้: คนที่ไม่อยากหรือใช้เมาส์ไม่สะดวก และกรรมการที่ดูการสาธิต

## 2. สิ่งที่ Pakon เลือก (2026-10-13)

| คำถาม | คำตอบ |
|---|---|
| เริ่มฟังยังไง | **กดปุ่มคีย์บอร์ด 1 ปุ่ม** (ใช้ได้แม้ Chromium เต็มจอ) แล้วพูด · เงียบ 1 วิ หยุดเอง (กลไกเดิมของ 0019 ข้อ 10) |
| ถอดเสร็จแล้ว | **ทุกคำสั่งทำทันที** ไม่ต้องกดส่ง (เปลี่ยนจาก 0019 ข้อ 9 ที่ให้ดูก่อนส่ง · เฉพาะทางคีย์ลัด · ปุ่มไมค์ในแอปคงเดิม) |
| ลิงก์แรก | **อันแรกที่เห็นบนจอ** รวมโฆษณา |
| คำสั่ง | ค้นหา … · เข้าลิงก์แรก/ที่ N · ย้อนกลับ · ไปข้างหน้า · โหลดใหม่ · เลื่อนลง/ขึ้น · ปิดแท็บ · กลับไปแอป |

ผู้ช่วยตีความเพิ่ม (Pakon เปลี่ยนได้): งานที่ลบของ (เช่น ยกเลิกนัด) **ยังขึ้นการ์ด "ใช่ไหม"** เหมือนเดิม แต่ตอบด้วยเสียง "ใช่" / "ไม่" ได้ (ไม่ต้องใช้เมาส์)

## 3. ออกแบบ

```
F9 (labwc keybind · ทั้งเครื่อง) → aipc-voice-key (sh: echo > FIFO ใน $XDG_RUNTIME_DIR/aipc/)
  → VoiceController เริ่มฟัง (เสียง "ติ๊ก") → เงียบ 1 วิ → whisper.cpp ถอด
  → browse.parse(ข้อความ) ─ เป็นคำสั่งเว็บ → BrowserControl (CDP ทาง pipe) → พูดผลสั้น ๆ (piper)
                          ├ "ใช่"/"ไม่" และมีการ์ดรอยืนยัน → ตอบการ์ดนั้น
                          └ อื่น ๆ → ส่งเข้าแชทเหมือนพิมพ์แล้วกดส่ง (สกิล / AI ในเครื่อง / Claude ตามเดิม)
```

- **คุมเบราว์เซอร์:** แอปเปิด Chromium เองด้วย `--remote-debugging-pipe` (Chrome DevTools Protocol ทาง fd 3/4) ·
  **ไม่เปิดพอร์ตเครือข่าย** โปรแกรมอื่นในเครื่องและบัญชีอื่นคุมเบราว์เซอร์นี้ไม่ได้ (พอร์ต 9222 ใครในเครื่องก็ต่อได้) ·
  โปรไฟล์แยก `~/.local/share/aipc/browser` (Chromium 136+ ไม่ยอมให้คุมโปรไฟล์หลัก) → ล็อกอินเว็บในเบราว์เซอร์ผู้ช่วยแยกจาก Chromium ปกติ
- **ค้นหา:** Google (`/search?q=`) · **Google ขอยืนยันว่าไม่ใช่บอต (`/sorry/`) → ค้นด้วย Bing แทนและพูดบอก** ·
  พบตอนสำรวจ 2026-10-13: IP ฮอตสปอตมือถือ (CGNAT) โดน Google ขอยืนยันแล้วแม้เปิดหน้าแรกแล้วพิมพ์เอง · Bing / DuckDuckGo ปกติ
- **ลิงก์ที่ N:** หน้าผลค้นหา Google/Bing/DuckDuckGo = หัวข้อผลค้นหา (รวมโฆษณา) เรียงจากบนลงล่าง · หน้าอื่น = ลิงก์ที่มองเห็นในจอ เรียงจากบนลงล่าง ซ้ายไปขวา
- **กลับไปแอป:** ย่อหน้าต่างเบราว์เซอร์ (`Browser.setWindowBounds` minimized) · คำสั่งเว็บครั้งถัดไปเปิดคืน
- **ไม่ใช้ LLM** ในการแปลคำสั่งเว็บ (กฎ · เร็ว · ทดสอบได้ครบ) · ประโยคที่ไม่ใช่คำสั่งเว็บไปทางเดิมของแอป

## 4. ข้อมูล

โปรไฟล์เบราว์เซอร์ใน home ของผู้ใช้ (คุกกี้ ประวัติเว็บ) · ลบพร้อมบัญชี (ลบบัญชีลบ home ทั้งหมด) · ไม่เก็บเสียง (0019 เดิม: ถอดเสร็จลบไฟล์)

## 5. รอยต่อ

- `aipc.skills.browse.parse(text) -> BrowseCommand | None` (`kind`: search · open · back · forward · reload · scroll · close · app · `query` · `n` · `direction`)
- `aipc.browser.cdp.PipeClient` · `aipc.browser.control.BrowserControl.run(cmd) -> Result(ok, say, detail)`
- QML: `voice.handsFree` · `voice.heardHandsFree(text)` → `WorkspacePage.voiceCommand(text)`

## 6. กรณีที่ต้องคิดไว้ก่อน

ไม่มีเน็ต → บอก "ต่อเน็ตไม่ได้" · ผู้ใช้ปิดหน้าต่างเบราว์เซอร์เอง → pipe ปิด → เปิดใหม่ครั้งหน้า ·
ไม่มีผลค้นหา/ลิงก์ที่ N เกินจำนวน → พูดบอกจำนวนที่มี · ออกจากระบบ → แอปปิดเบราว์เซอร์ผู้ช่วย ·
ถอดเสียงผิดเป็นคำสั่งเว็บ → งานเว็บทุกอย่างย้อนได้ (ย้อนกลับ) · ถอดผิดเป็นงานลบ → ยังมีการ์ดยืนยัน

## 7. ต้นทุนบน Pi 5

Chromium เปิดอยู่แล้วตามปกติ (+ ~300–500 MB ต่อโปรไฟล์) · ถอดเสียง ~2 วิต่อประโยค (whisper · 4 เธรด) · ไม่เรียก LLM สำหรับคำสั่งเว็บ

## 8. การทดสอบ และเกณฑ์ผ่าน (ประกาศก่อนสร้าง · 2026-10-13 · ผู้ช่วย)

**โมเดลที่ใช้:** ถอดเสียง Thonburian Whisper distill-small (f16 · whisper.cpp) · อ่านออกเสียง Piper `th_TH-tsync2-medium` (ใช้ตอบผล และใช้สร้างเสียงทดสอบ V3) ·
แปลคำสั่งเว็บ = กฎ (ไม่มีโมเดล) · ประโยคที่ไม่ใช่คำสั่งเว็บไปทางเดิม (Gemma 4 E2B ในเครื่อง / Claude)

**ชุดข้อมูล** (ผู้ช่วยเขียน = ไม่อิสระเต็มที่ · เขียนก่อนเขียนตัวแปล · commit ก่อนรัน):
- V1 `tests/data/browse_v1.json` ชุดพัฒนา · ใช้ปรับกฎ
- V2 `tests/data/browse_v2.json` ชุดทดสอบ · คนละถ้อยคำกับ V1 · ข้อความแบบที่ whisper ถอด (ไม่มีวรรคตอน มีคำลงท้าย) · มีประโยคที่ **ไม่ใช่** คำสั่งเว็บ (เช่น "ค้นหาไฟล์รายงาน" "ย้อนกลับไปดูนัดเมื่อวาน" "เปิดเสียง")
- V3 = ประโยค V2 ที่เป็นคำสั่ง → Piper พูด → whisper ถอด (บน Pi) → ตัวแปล (เสียงสังเคราะห์ ไม่ใช่เสียงคน = จุดอ่อน)

| # | เกณฑ์ | ผ่านเมื่อ |
|---|---|---|
| 1 | ตัวแปลบน V2 (ข้อความ) | คำสั่งเว็บถูกทั้งชนิดและค่า ≥ 95% **และ** ประโยคที่ไม่ใช่คำสั่งเว็บ ถูกจับผิดเป็นคำสั่งเว็บ 0 ข้อ |
| 2 | เสียงจริงจนจบ V3 (Piper → whisper → ตัวแปล บน Pi) | ถูก ≥ 80% · บันทึกทุกข้อที่พลาดพร้อมข้อความที่ถอดได้ |
| 3 | เบราว์เซอร์จริงบน Pi (Chromium บน labwc แบบไม่มีจอ · เว็บจริง) | ชุดขั้นตอน 12 ขั้น (ค้นหา → ลิงก์ 1 → ย้อนกลับ → ลิงก์ 2 → ย้อนกลับ → ไปข้างหน้า → โหลดใหม่ → เลื่อนลง → เลื่อนขึ้น → ปิดแท็บ → ค้นหาใหม่ → กลับไปแอป) ผ่าน 12/12 ใน 3 รอบติดกัน · ตรวจด้วย URL/scrollY จริง ไม่ใช่ข้อความที่ระบบบอก |
| 4 | ปลอดภัย | ระหว่างเบราว์เซอร์ผู้ช่วยเปิด ไม่มีพอร์ต TCP ที่ Chromium ฟัง (`ss -ltnp`) |
| 5 | เวลา | หลังพูดจบ → หน้าเว็บเริ่มเปลี่ยน ≤ 5 วิ (มัธยฐาน · รวมถอดเสียง) |
| 6 | ไม่กระทบของเดิม | เทสต์ทั้งชุดผ่าน · ทางพิมพ์ไม่เปลี่ยน (ตัวแปลใช้เฉพาะทางคีย์ลัด) → ผลชุดสอบ/H1–H3 ไม่ต้องวัดซ้ำ |
| 7 | คนจริง | Pakon พูดชุดขั้นตอนข้อ 3 บนเครื่องจริงด้วยเสียงตัวเอง · บันทึกผลตามจริง (ผู้ช่วยทำแทนไม่ได้) |

ไม่ผ่านข้อใด = ไม่ติดตั้ง · บันทึกผลทุกรอบ รวมรอบที่ใช้ไม่ได้
