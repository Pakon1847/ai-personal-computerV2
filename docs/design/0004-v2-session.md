# การ์ดออกแบบ 0004: หลัง login เข้าหน้าจอ V2 เลย ไม่ใช่เดสก์ท็อปของ Pi

- **สถานะ:** อนุมัติแล้ว 2026-09-24 (Pakon) · สร้างแล้ว ติดตั้งบน Pi 4 แล้ว · ผ่านบน Pi 4: รีบูต 3 ครั้ง, รหัสผิด/ถูกผ่าน greetd, ไม่มีแถบงาน Pi, ล่มแล้วเปิดใหม่, "ออก" กลับหน้า Login · **รอ Pakon ทดสอบที่ตัวเครื่อง:** พิมพ์รหัสในหน้า Login, กดปุ่ม "ออก", เปิดยูทูบแล้ว Alt+Tab · Pakon สั่ง 2026-09-24 "ไม่ต้องการให้ผู้ใช้ใช้ Desktop ของ Pi อยากให้เข้าของผมเอง"
- **ข้อกำหนดที่อ้าง:** BRIEF หัวข้อ 7 (แผนผัง: labwc → AIPC Shell) · BRIEF 5.7 (Shield/Lock ใช้ ext-session-lock บน labwc) · DESIGN.md H2 H3 H4 H5 · การ์ด 0003 (greetd)

## 1. ปัญหาที่แก้ และใครใช้

ตอนนี้ใส่รหัสถูกแล้ว greetd เปิด `labwc-pi` = เดสก์ท็อปของ Raspberry Pi (แถบงาน ไอคอน เมนู) ไม่ใช่ระบบของเรา
ผู้ใช้ทุกคนที่เข้าเครื่องต้องเห็น Shell ของ V2 ทันที และไม่มีทางหลุดไปเดสก์ท็อปของ Pi

## 2. หลักการที่ใช้ตัดสิน

| หลักการ | ใช้ยังไง |
|---|---|
| H2 ไม่ทิ้งงานเงียบ ๆ | หน้าจอ V2 ล่ม → เปิดใหม่เอง · ล่มซ้ำ 3 ครั้งใน 1 นาที → จบเซสชันกลับหน้า Login (ไม่ปล่อยจอดำ) |
| H3 ความเป็นส่วนตัว | "ออก" = จบเซสชันจริง (ปิดทุกโปรเซสของผู้ใช้) ไม่ใช่แค่สลับไปหน้า Login ภายในแอปแล้วเซสชันยังค้าง |
| H4 เหมาะกับ Pi | ไม่เปิดแถบงาน/ตัวจัดการไฟล์/พื้นหลังของ Pi = RAM น้อยลง |
| H5 ความจริง | ในเซสชันจริงไม่มีแถบโหมดพัฒนา และไม่มีหน้า Login ซ้อนในแอป (login จริงผ่าน greetd แล้ว) |
| BRIEF หัวข้อ 7 | ใช้ labwc ต่อ เพราะ Shield/Lock ต้องใช้ ext-session-lock ของ labwc และสกิล 4 ต้องเปิดเบราว์เซอร์เป็นหน้าต่างซ้อนได้ |

## 3. ทางเลือก

| ทางเลือก | ข้อดี | ข้อเสีย |
|---|---|---|
| ก. เซสชันเป็น `cage` + หน้าจอ V2 (แบบตู้ kiosk เหมือนหน้า Login) | ง่ายที่สุด เบาที่สุด | cage แสดงได้ทีละหน้าต่าง · สกิล 4 เปิดยูทูบแล้ว **กลับมาหน้า V2 ไม่ได้** · cage ไม่มี ext-session-lock → ทำ Shield/Lock ตาม BRIEF ไม่ได้ |
| **ข. labwc ด้วยค่าตั้งของเราเอง ไม่มีเดสก์ท็อป Pi (เลือก)** | ตรง BRIEF หัวข้อ 7 · เปิดเบราว์เซอร์ซ้อนแล้วกลับมาได้ · รองรับ Shield/Lock ภายหลัง | ต้องเขียนค่าตั้ง labwc ของเรา (autostart + ปิดคีย์ลัดที่หลุดออกไปได้) |
| ค. ใช้เดสก์ท็อป Pi แล้วเปิด V2 เต็มจอทับ | ทำไว้แล้ว (`install-ui.sh`) | ผู้ใช้ยังหลุดไปเดสก์ท็อป Pi ได้ — ไม่ตรงคำสั่ง |

## 4. ความสัมพันธ์กับชิ้นส่วนอื่น

- **พึ่ง:** greetd + หน้า Login (การ์ด 0003, ทำงานบน Pi 4 แล้ว) · labwc (มีใน OS แล้ว) · แอปที่ `/opt/aipc-v2`
- **มีคนพึ่ง:** Shield/Lock (เฟส 2) · สกิล 4 (เปิดแอป/เว็บเป็นหน้าต่างใน labwc) · การเตือนนัดหมาย (รันในเซสชัน) · Logout ล้าง cache (BRIEF 5.1)
- **ชั้น:** ชั้น 4 (หน้าจอ) ในเซสชันของผู้ใช้ · ยังรันตรรกะในโปรเซสเดียวกับหน้าจอเหมือนเดิม (DESIGN.md หัวข้อ 2)

```
greetd → หน้า Login (ผ่าน PAM) → aipc-session (ผู้ใช้คนนั้น)
                                    └ labwc -C /opt/aipc-v2/scripts/pi/session/labwc
                                        └ -S aipc-shell-loop (ตัวนี้จบ = labwc จบ)
                                            └ python -m aipc.ui --session --fullscreen
                                               (ล่ม → เปิดใหม่ · ล่ม 3 ครั้ง/นาที → labwc --exit)
                                        กด "ออก" → labwc --exit → กลับหน้า Login
```

## 5. ข้อมูล

ไม่เก็บอะไรใหม่ · ค่าตั้ง labwc เป็นของระบบ อยู่ที่ `/opt/aipc-v2/scripts/pi/session/labwc/` (root เป็นเจ้าของ ผู้ใช้แก้ไม่ได้)

## 6. รอยต่อ

- `aipc.ui --session` — โหมดเซสชันจริง: เริ่มที่ Shell · ไม่มีหน้า Login/สมัครในแอป · ไม่มีแถบโหมดพัฒนา · Ctrl+Alt+Q ปิดใช้ · ปุ่ม "ออก" เรียก `SessionController.logout()`
- `SessionController.logout()` (Python) → รัน `labwc --exit` (จบเซสชัน greetd จะกลับหน้า Login เอง) · ทดสอบด้วยตัวรันปลอม
- `scripts/pi/session/aipc-session` — คำสั่งเซสชันที่ greetd เรียก (แทน `/usr/bin/labwc-pi`)
- `install-greeter.sh --session v2` เปลี่ยนคำสั่งเซสชันใน config.toml (สำรองไฟล์เดิมเหมือนเดิม · `--rollback` ใช้ได้เหมือนเดิม)

## 7. กรณีที่ต้องคิดไว้ก่อน

- หน้าจอ V2 ล่มตอนเริ่ม (เช่น import พัง) → วนเปิด 3 ครั้งแล้วจบเซสชัน → กลับหน้า Login · ไม่ค้างจอดำ
- คีย์ลัดของ labwc ที่เปิด terminal/เมนู → ค่าตั้งของเราไม่มีคีย์เหล่านั้น (เหลือแค่สลับหน้าต่าง Alt+Tab ไว้กลับจากเบราว์เซอร์)
- ผู้ใช้ปิดหน้าต่าง V2 เอง → ถือเป็นล่ม → เปิดใหม่
- ทางเข้าสำรองสำหรับ Pakon (ผู้พัฒนา): SSH และ Ctrl+Alt+Fn+2 ยังใช้ได้ · เดสก์ท็อป Pi ยังติดตั้งอยู่ เพียงไม่ถูกเลือก
- ผู้ดูแลต้องการเดสก์ท็อป Pi จริง ๆ → `install-greeter.sh --session /usr/bin/labwc-pi` (ไม่ลบ ไม่ถอนอะไร)
- ตัวแปรสภาพแวดล้อมที่ labwc ต้องการเมื่อเริ่มจาก greetd: ใช้ค่าเดียวกับ `/usr/bin/labwc-pi` (WLR_DRM_FORCE_LIBLIFTOFF, pixman ถ้าไม่มี MMU) · ผ่านบน Pi 4 แล้ว
- พิมพ์ไทย: แป้น us,th สลับด้วย Alt+Shift (ค่าตั้งใน `labwc/environment`) · **ยังไม่ได้ทดสอบพิมพ์จริง**

## 8. ต้นทุนบน Pi

labwc เปล่า + หน้าจอ V2 แทนเดสก์ท็อป Pi เต็มชุด (แถบงาน, pcmanfm, ฯลฯ) → RAM น่าจะ**ลดลง** แต่ **ยังไม่รู้ตัวเลข** → วัด RAM รวมของเซสชันทั้งสองแบบบน Pi 4 · ไม่เรียก LLM

## 9. การทดสอบ และเกณฑ์ผ่าน (ประกาศก่อนสร้าง)

- เทสต์: `--session` เริ่มที่ Shell, ไม่มีแถบโหมดพัฒนา, Ctrl+Alt+Q ไม่ปิดแอป, "ออก" เรียก logout (ตัวรันปลอม)
- เทสต์สคริปต์วนเปิด: ล่ม 3 ครั้งใน 60 วินาทีแล้วเลิก (รันด้วยคำสั่งปลอม)
- บน Pi 4: รหัสถูก → เห็น Shell ของ V2 ภายใน 10 วินาที ไม่เห็นแถบงานของ Pi · กด "ออก" → กลับหน้า Login · kill หน้าจอ V2 → เปิดใหม่เอง · รีบูต 3 ครั้งผ่านทุกครั้ง · สั่ง "เปิดยูทูบ" แล้ว Alt+Tab กลับมาได้
- ภาพหน้าจอเป็นหลักฐานใน `docs/benchmarks/` หรือแนบในรายงาน
