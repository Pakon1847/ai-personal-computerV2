# การ์ดออกแบบ 0007 (ย้อนหลัง): โครงหน้าจอ V2 — QML วาด Python ตัดสิน

- **สถานะ:** การ์ดย้อนหลัง · โค้ดสร้างก่อนมีกติกา "การ์ดก่อนโค้ด" (2026-09-23) · เขียน 2026-09-24 เพื่อบันทึกเหตุผลสำหรับบทที่ 3 · **รอ Pakon ทบทวน**
- **ข้อกำหนดที่อ้าง:** BRIEF 5.1 (Login/สมัคร), 5.7 (ขนาดตัวอักษร 100–200%, ธีม), หัวข้อ 7 ข้อ 1 (หน้าจอแยกจากตรรกะ) · DESIGN.md H3 H4 H5 H7 · การ์ดที่ต่อยอด: 0002 (หน้าตารอบ 2), 0003/0004 (Login จริง/เซสชัน), 0006 (ใบหน้า)

## 1. ปัญหาที่แก้ และใครใช้

ผู้ใช้ทุกคนของเครื่องต้องมีหน้าจอเดียวที่เปิดเครื่องแล้วเข้าได้เลย (Login → Shell) ใช้ภาษาไทย อ่านง่ายบนจอ Pi
และกรรมการต้องแยกได้ว่าส่วนไหนทำงานจริง ส่วนไหนยังไม่มี

## 3. ทางเลือก (ที่พิจารณาตอนสร้าง)

| ทางเลือก | ข้อดี | ข้อเสีย |
|---|---|---|
| ก. เว็บ (Chromium kiosk + HTML) | ทำหน้าตาง่าย เครื่องมือเยอะ | Chromium กิน RAM หลายร้อย MB · ต้องมีเซิร์ฟเวอร์/พอร์ตในเครื่อง |
| **ข. Qt Quick (QML) + PySide6 (เลือก)** | RAM หน้าจอในเซสชันจริง ~172 MB (Pi 4) · เรียก Python ตรงไม่ต้องเปิดพอร์ต · มีโหมด offscreen ให้เทสต์อัตโนมัติ | ต้องเรียน QML · Qt ใหญ่ (แก้ด้วย PySide6-Essentials) |
| ค. GTK/Tk | เบา | ทำหน้าตาตามบอร์ดออกแบบยาก · ภาษาไทยและการปรับขนาดตัวอักษรทั้งระบบทำยาก |

## 6. รอยต่อ

- Python → QML: `Property` (อ่าน) + `Signal changed` · QML → Python: `Slot` เท่านั้น
- โหมดเปิด: `--greeter` (หน้า Login จริง ผู้ใช้ `_greetd`) · `--session` (หลัง login เริ่มที่ Shell) · `--dev`/`--demo-scan` (เครื่องพัฒนา มีแถบส้ม)

## 7. กรณีที่ต้องคิดไว้ก่อน

- ไฟล์ค่าหน้าจอเสีย → ค่าเริ่มต้น (มีเทสต์) · ตัวอักษร 200% → หน้าเลื่อนได้ ไม่ทับ/ตัด (การ์ด 0002)
- โหมด greeter ห้ามมีทางลัดโหมดพัฒนา/สาธิต (`app.py` ปิดทิ้งเมื่อ `real`)
- อ่านค่าเครื่องไม่ได้ (เช่นบนวินโดวส์) → "ไม่รู้" ไม่ใช่ "ปกติ"

## 8. ต้นทุนบน Pi

(Pi 4) RAM หน้าจอในเซสชันจริง ~172 MB + labwc ~95 MB (วัดครั้งเดียว) · เปิดถึงเฟรมแรก median 1.86 วิ ([ผล](../benchmarks/2026-09-24-pi4-ui-start-shell.md)) · ตัวเลขจริงต้องวัดบน Pi 5
