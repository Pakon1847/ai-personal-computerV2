# การ์ดออกแบบ 0059: มองจอแล้วพูดได้เลย (ฟังตลอดเวลาที่มองจอ) · มีปุ่มเปิด-ปิด

- **สถานะ:** ร่าง (2026-10-23 · รอ Pakon อนุมัติ) · ต่อจากการ์ด 0058
- **ข้อกำหนดที่อ้าง:** การ์ด 0058 (visiond `facing` · ผลขั้น 0) · การ์ด 0051 (presence) · BRIEF 5.6 (คีย์ลัด = สั่งงาน)

## 1. ปัญหาที่แก้ และใครใช้

Pakon (2026-10-23): "ฟังตลอดเวลาที่มองจอ แต่ทำปุ่มให้เปิด-ปิดได้" · ไม่ต้องกด F9 ทุกคำสั่ง · ผู้ใช้ที่นั่งหน้าจอและสั่งด้วยเสียงบ่อย

## 3. ออกแบบ

1. **ปุ่มเปิด-ปิด:** แถบด้านบน (กดครั้งเดียว) + ตั้งค่า + พูด "เปิดโหมดมองแล้วพูด" / "ปิดโหมดมองแล้วพูด" · จำค่าไว้ข้ามการเข้าระบบ
2. **ระหว่างเปิด:** ตัวเฝ้าขอ visiond `facing` ต่อเนื่อง (ขอใหม่ทุก ≤ 20 วิ) ·
   หันเข้าจอ ≥ 0.5 วิ → เปิดไมค์ (ติ๊กเบา ๆ + กล่องคำสั่งเสียง) → ทางเดียวกับกด F9 (ตัวจับจุดจบ 0056 · ตัดเมื่อหันออก 0058) ·
   จบคำสั่ง → รอ 1 วิ แล้วฟังรอบใหม่ถ้ายังมองจออยู่
3. **กันสั่งเอง:** ไม่ได้ยินเสียงพูด 5 วิ = ปิดไมค์ รอจนหันออกแล้วหันกลับ · ประโยคที่ไม่ใช่คำสั่ง = เงียบ ·
   กำลังอ่านออกเสียง/เล่นเสียง = ไม่ฟัง (ไม่ให้ไมค์ได้ยินลำโพง)
4. **กล้องชนกัน:** visiond ใช้กล้องทีละงาน → ระหว่างเปิดโหมดนี้ ตัวตรวจ presence (ล็อกเมื่อไม่มีคน · การ์ด 0051) ใช้ "ไม่เห็นหน้า" จากสตรีมเดียวกันแทน
   (ไม่ตรวจว่าเป็นเจ้าของ) · ล็อกตามเวลายังทำงาน · จอล็อกขึ้น = หยุดโหมดนี้ (กล้องให้จอล็อกใช้ · การ์ด 0055)

## 4. ข้อมูล

ค่าตั้ง `look_to_talk` (bool) ใน ui.json · ไม่เก็บอะไรเพิ่ม

## 6. กรณีที่ต้องคิดไว้ก่อน

มองจอแต่คุยกับคนข้าง ๆ (ความเสี่ยงหลัก → ทำเฉพาะคำสั่งที่รู้จัก) · ทีวีในห้องพูดชื่อคำสั่ง · หลายคนหน้าจอ · ห้องมืด (ไม่เห็นหน้า = ไม่ฟัง) ·
ออกจากระบบ/จอล็อก = ปิดกล้องทันที · visiond ไม่ตอบ = ปิดโหมดเอง + บอกครั้งเดียว

## 7. ต้นทุนบน Pi 5 (จากขั้น 0 ของ 0058 · ต้องวัดซ้ำแบบต่อเนื่อง)

ตัวหาหน้า ~0.5 คอร์ **ตลอดเวลาที่เปิดโหมด** · YouTube + ตัวหาหน้า = 1.94 คอร์ (48.5%) · อุณหภูมิขึ้น ~4°C ใน 30 วิ (71.9 → 75.7°C) ·
ไมค์+ตัวถอดเสียงเฉพาะตอนมองจอ · RAM ~0
