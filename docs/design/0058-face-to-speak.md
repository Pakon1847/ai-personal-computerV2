# การ์ดออกแบบ 0058: ฟังคำสั่งเสียงเฉพาะตอนหันหน้าเข้าจอ

- **สถานะ:** อนุมัติแล้ว (2026-10-23, Pakon "0058 … ถ้าไม่ [หนักไป] ผมก็อนุมัติ" · เงื่อนไข = ต้นทุน CPU ข้อ G4) · สาขา `feature/0058-face-to-speak` (ต่อจาก `test/0056-0057`)
- **ข้อกำหนดที่อ้าง:** การ์ด 0056 (ไมค์ · ผลวัดหันข้าง) · การ์ด 0055 (visiond ใช้กล้องระหว่างล็อก) · การ์ด 0051 (presence)

## 1. ปัญหาที่แก้ และใครใช้

Pakon (2026-10-23): กด F9 แล้วหันไปพูดกับคนอื่น → ไม่อยากให้ระบบเอาไปทำคำสั่ง ·
**วัดแล้ว** (ไมค์ Leviosa Max · cardioid): หันข้างเสียงเบาลง ≤ 4.5 dB · ประตูใกล้ไมค์ (10 dB) ตัดได้ 0/5 → ใช้ความดังแยกไม่ได้ ([ผล](../benchmarks/2026-10-23-mic-near/README.md))

## 2. หลักการที่ใช้ตัดสิน

| หลักการ | ใช้ยังไง |
|---|---|
| H3 | ตั้งค่า "ฟังเฉพาะตอนหันหน้าเข้าจอ" ค่าเริ่มต้นปิด · กล้องเปิดเฉพาะช่วงฟังคำสั่ง · ไม่เก็บภาพ |
| H4 | ใช้ YuNet ที่ visiond โหลดอยู่แล้ว · ไม่เพิ่มโมเดล/dependency · วัด CPU (G4) |
| H5 | ไม่เห็นหน้า/กล้องใช้ไม่ได้ = บอกตรง ๆ และทำงานแบบเดิม (ไม่ปิดเสียงทั้งหมดเงียบ ๆ) |
| H6 H7 | visiond บอกแค่ "หัน/ไม่หัน/ไม่เห็นหน้า" · กฎตัดสินในโค้ด Listener |

## 3. ออกแบบ

1. **visiond คำขอใหม่ `facing`** (เจ้าของเซสชันเท่านั้น · แบบเดียวกับ `watch`): ทุก ~0.2 วิ ส่ง `{"face": bool, "facing": bool}` ·
   facing = มีหน้า และ |yaw| ≤ 30° (ค่าเริ่ม · ตั้งจากชุดพัฒนาที่จอ) · ใช้ `quality.estimate_pose` (ค่าคร่าว ๆ จาก 5 จุดของ YuNet) · ไม่เทียบว่าเป็นเจ้าของ (เร็ว ประหยัด)
2. **Listener:** เริ่มฟัง (F9) → เปิด `facing` คู่กัน · กฎ:
   - ช่วงพูดที่ "ไม่หัน" ต่อกัน ≥ 0.5 วิ หลังเริ่มพูด = จบคำสั่งตรงนั้น (ส่วนที่พูดตอนหันเข้าจอยังทำ)
   - ทั้งประโยคไม่หันเข้าจอเลย = ไม่ทำ · "หันมาที่จอแล้วพูดใหม่"
   - กล้องใช้ไม่ได้ / visiond ไม่ตอบ / มืด = ทำงานแบบเดิม + บอกครั้งเดียว "ตรวจการหันหน้าไม่ได้"
3. **presence ปล่อยกล้องระหว่างฟัง** (visiond ใช้กล้องทีละงาน · แบบการ์ด 0055)
4. **ตั้งค่า:** "ฟังคำสั่งเสียงเฉพาะตอนหันหน้าเข้าจอ" (ต้องลงทะเบียนใบหน้าไม่จำเป็น · ใช้แค่หาหน้า)

## 4. ข้อมูล

ไม่เก็บอะไร · ภาพอยู่ใน visiond (หน่วยความจำ) ระหว่างฟังเท่านั้น

## 5. รอยต่อ

`client.facing(on_seen, stop, seconds)` · `Listener(..., facing=None)` (ตัวเปิด/ปิด) · `UiSettings.faceToSpeak`

## 6. กรณีที่ต้องคิดไว้ก่อน

หลายคนหน้าจอ (มีหน้าไหนหันเข้าก็นับ) · ใส่แว่น/แสงย้อน · กล้องถูกจอล็อกใช้อยู่ (ล็อกแล้วไม่มีคีย์ลัด) · F9 ตอนกล้องกำลังสแกนหน้าเข้าเครื่อง

## 7. ต้นทุนบน Pi 5

- **ประมาณ (ยังไม่ได้วัด):** เฉพาะช่วงฟัง (~3–8 วิต่อคำสั่ง) · YuNet อย่างเดียว ~5 ภาพ/วิ ·
  เทียบกับผลวัดเดิม YuNet 2 ภาพ/วิ + SFace ทุก 2 วิ = 10.7% ของ 1 คอร์ ([presence-b](../benchmarks/2026-10-06-presence-b/README.md)) → คาด ~20–30% ของ 1 คอร์ (≈ 5–8% ของทั้งเครื่อง 4 คอร์) ระหว่างฟังเท่านั้น
- RAM: ~0 (visiond โหลดโมเดลอยู่แล้ว) · ดิสก์ 0 · LLM 0 · ตอนไม่ได้ฟัง = 0
