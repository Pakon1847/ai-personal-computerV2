# การ์ดออกแบบ 0010: ลงทะเบียนใบหน้าแบบเห็นหน้าตัวเอง + 5 ท่า (ตรง ซ้าย ขวา เงย ก้ม)

- **สถานะ:** อนุมัติ 2026-09-24 (Pakon) · กำลังสร้าง
- **ข้อกำหนดที่อ้าง:** BRIEF 5.1 ข้อ 5 (ลงทะเบียนหลายท่า), 5.7 (ใช้ง่าย) · การ์ด 0005 (แกนใบหน้า), 0006 (ทางเลือก ค. ที่ตัดไว้) · DESIGN.md H3 H4 H5 H7 H9

## 1. ปัญหาที่แก้ และใครใช้

ตอนนี้ผู้ใช้ลงทะเบียนโดยไม่เห็นภาพตัวเอง มีแค่ข้อความบอก → ไม่รู้ว่าหน้าอยู่ในกรอบไหม หันพอหรือยัง
(ทดสอบจริงครั้งแรกหมดเวลา 20 วิโดยไม่สำเร็จ · [ผลการ์ด 0006](../benchmarks/2026-09-24-card0006-pi4/README.md))
ผู้ใช้: ทุกคนที่ลงทะเบียนใบหน้า · กรรมการ: เห็นระบบใบหน้าทำงานบนจอ

## 2. หลักการที่ใช้ตัดสิน

## 4. ความสัมพันธ์กับชิ้นส่วนอื่น

- **พึ่ง:** `vision.pipeline.enroll` (เพิ่มท่า up/down) · `vision.quality.estimate_pose` (มี pitch แล้ว) · `ui/face.py FaceController` (การ์ด 0006)
- **มีคนพึ่ง:** การทดสอบกับคนจริง ≥ 5 คน ([face-protocol](../evaluation/face-protocol.md)) · อนาคต: ให้หันตามคำสั่งแบบสุ่มใช้เป็น PAD แบบ active ได้ (ไม่ทำรอบนี้)
- **ชั้น:** ชั้น 4 (ภาพ/ตัวนับ) + แกนใบหน้า (การแบ่งท่า) · รันในโปรเซสหน้าจอเหมือนการ์ด 0006

## 5. ข้อมูล

- **ไม่มีข้อมูลใหม่บนดิสก์** · แม่แบบยังเป็นเวกเตอร์เดียวใน `FaceStore` เดิม
- ท่าที่เข้าแม่แบบกำหนดใน config: `template_poses` ค่าเริ่มต้น `["front", "left", "right"]` · เปลี่ยนได้หลังผลวัดข้อ 8 เท่านั้น
- log การลงทะเบียน (**ไฟล์แยก `face-enroll.log`** — แก้ระหว่างสร้าง: `report.py` อ่าน `face-scans.log` โดยถือว่าทุกบรรทัดเป็นการสแกน): ผล, เวลา, ท่าที่ได้/ขาด, **เหตุผลที่พบบ่อยสุดเมื่อไม่สำเร็จ** (ปิดช่องที่เจอในการ์ด 0006) · ไม่มีภาพ ไม่มี embedding

## 6. รอยต่อ

```text
pipeline.enroll(frames, per_pose=2, progress, poses=("front","left","right","up","down"),
                template_poses=("front","left","right")) -> Template | Rejected
    แบ่งท่า: |yaw|,|pitch| ≤ 8° = ตรง · หันอย่างเดียว = ซ้าย/ขวา · ก้มเงยอย่างเดียว = เงย(pitch<0)/ก้ม(pitch>0)
             หันและก้มเงยพร้อมกัน = ไม่นับ (ท่ากำกวม)
    progress(ผลเฟรม, counts, preview) · preview = ภาพย่อกลับซ้ายขวา (numpy) + กรอบหน้า (สัดส่วน 0–1)

FaceController (เพิ่ม):
    Property: previewSerial (int, เพิ่มทุกภาพใหม่ · 0 = ไม่มีภาพ), faceBox (x,y,w,h สัดส่วน), currentPose (ท่าที่ให้ทำตอนนี้)
    posesDone: {"front","left","right","up","down"} → จำนวน
    ImageProvider "face": คืนภาพล่าสุดในหน่วยความจำ · ไม่มีภาพ = ภาพว่าง
QML: Image { source: "image://face/" + face.previewSerial; cache: false } + วงรีนำทาง + ลูกศรท่าปัจจุบัน + แถบ 5 ท่า
```

ลำดับท่าที่บอก: ตรง → ซ้าย → ขวา → เงย → ก้ม (บอกท่าถัดไปที่ยังไม่ครบ) · ได้ท่าก่อนลำดับก็นับ

## 7. กรณีที่ต้องคิดไว้ก่อน

- กล้องหลุด / ยกเลิก / "ออก" → หยุด ล้างภาพ ไม่บันทึก (เหมือนการ์ด 0006) · เทสต์ว่าหลังจบ ImageProvider คืนภาพว่าง
- ทำครบ 3 ท่าที่เข้าแม่แบบ แต่เงย/ก้มไม่ได้ภายในเวลา → **ยังสำเร็จ** (เงย/ก้มไม่ได้เข้าแม่แบบอยู่แล้ว) แต่ log ว่าขาดท่าไหน · ถ้าผลวัดให้ใส่เงย/ก้มในแม่แบบ ค่อยเปลี่ยนเป็นบังคับ
- คนใส่แว่น/แสงย้อน → คำแนะนำจาก quality gate เดิม
- เวลาหมด: 20 → **40 วิ** (5 ท่า)
- หน้า Login (`--greeter`) → ไม่มี FaceController ที่ทำงาน ไม่มีภาพ (เหมือนเดิม)

## 8. ต้นทุนบน Pi และการทดสอบ / เกณฑ์ผ่าน (ประกาศก่อนสร้าง)

**เทสต์อัตโนมัติ (วินโดวส์ + Pi 4):**
- แบ่งท่าจากจุดหน้าสังเคราะห์: ตรง/ซ้าย/ขวา/เงย/ก้ม/กำกวม ถูกทุกกรณี
- แม่แบบใช้เฉพาะ `template_poses` · เงย/ก้มขาด = ยังสำเร็จ + log ว่าขาด
- ImageProvider: มีภาพระหว่างลงทะเบียน · ว่างหลังจบ/ยกเลิก/กล้องหลุด · **ไม่มีไฟล์ภาพเกิดขึ้นใน home หรือ temp** (ตรวจโฟลเดอร์ก่อน/หลัง)
- log ไม่สำเร็จมีเหตุผล · QML โหลดทุกสถานะไม่มี warning

**บน Pi 4 กับ Pakon (ใช้ตัวบันทึกแบบการ์ด 0006):**

| เกณฑ์ | ค่า |
|---|---|
| ลงทะเบียนครบ 5 ท่า | ≤ 45 วิ ในความพยายามแรก |
| ภาพสดขณะลงทะเบียน | ≥ 5 ภาพ/วิ (นับจาก previewSerial) · นาฬิกาไม่ค้าง |
| RAM สูงสุดขณะลงทะเบียน | ไม่เกินการ์ด 0006 (385 MB) + 30 MB |
| สแกน 10 ครั้งหลังลงทะเบียน | รู้จัก ≥ 9 (เท่าเดิม) |

**การทดลอง 3 ท่า vs 5 ท่า (ตัดสินข้อ 1 ของ Pakon):** เครื่องมือ terminal `camera enroll --compare`
ลงทะเบียน 5 ท่าครั้งเดียว → สร้างแม่แบบ 2 แบบ **ในหน่วยความจำ** (3 ท่า, 5 ท่า) → สแกน 10 ครั้ง ให้คะแนนกับทั้งสองแบบ → log เฉพาะคะแนน (ไม่เก็บ embedding)
- ใส่เงย/ก้มในแม่แบบ **เฉพาะเมื่อ** แบบ 5 ท่า รู้จักไม่น้อยกว่า และคะแนนเฉลี่ยไม่ต่ำกว่าแบบ 3 ท่า · ทดสอบกับ Pakon ก่อน ถ้าได้คนเพิ่ม ≥ 3 คนจะตัดสินจากทุกคน
- ข้อจำกัดที่ต้องเขียนในเล่ม: 1–3 คน ไม่พอสรุปทั่วไป

**ผลระหว่างสร้าง (2026-09-24):** Pi 4 ภาพ LFW แทนกล้อง: ภาพสด 6.9 ภาพ/วิ · เพิ่ม 7.2 ms/เฟรม ([ผล](../benchmarks/2026-09-24-card0010-pi4-synthetic/README.md)) ·
ภาพตรวจ 2 ธีม ([ภาพ](../benchmarks/2026-09-24-card0010-shots/README.md)) · แก้ระหว่างสร้าง: ซ้าย/ขวาเดิมนับตามมุมกล้อง → ตามมุมผู้ใช้ ·
log การลงทะเบียนเป็นไฟล์แยก · **ยังไม่ได้:** ทดสอบกับคนจริง (ต้องอัปเดต `/opt/aipc-v2` ก่อน)

## 9. ไม่ทำในรอบนี้

- ภาพสดที่หน้า Login (ต้องมี visiond ก่อน)
- บันทึกภาพหรือวิดีโอใด ๆ
- สั่งท่าแบบสุ่มเพื่อกันภาพปลอม (PAD แบบ active) — ต่อยอดได้ภายหลัง
- แก้ RAM ไม่ลดกลับหลังใช้กล้อง (เจอในการ์ด 0006) — แยกเป็นงานแก้บั๊ก ทำก่อนการ์ดนี้เพื่อให้วัด RAM ข้อ 8 ได้ถูก
