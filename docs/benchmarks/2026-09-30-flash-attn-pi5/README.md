# Flash attention ทำให้ AI ในเครื่องช้าลงเมื่อคำขอยาว · Pi 5 · 2026-09-30

**ที่มา:** ตอนวัด "ใครเขียนสกิลได้" คืน 2026-09-30 Typhoon สร้างข้อความได้แค่ 1.2–1.9 token/วิ
ในคำขอยาว 1,800–2,700 token แต่ตอนตอบคำถามไทย 30 ข้อ (คำขอ ≤ 150 token) ได้ 4.2–4.4 token/วิ
ตรวจแล้วว่าไม่ใช่ swap (major fault 1 ครั้งใน 5 วิ, ไม่มีการอ่านดิสก์) และไม่ใช่การบังคับรูป JSON (ไม่บังคับก็ช้าเท่ากัน)

## ผล (llama-bench · Typhoon2.5-Qwen3-4B Q4_K_M · 3 thread · 2 รอบต่อค่า)

| flash attention | คำขอว่าง (tg32) | มีคำขอ 2,048 token ก่อนหน้า (tg32 @ d2048) |
|---|---|---|
| ปิด (`-fa 0`) | 4.61 ± 0.03 tok/s | **3.68 ± 0.00 tok/s** |
| เปิด (`-fa 1`) | 4.75 ± 0.03 tok/s | **2.01 ± 0.01 tok/s** |

- คำสั่ง: `llama-bench -m models/typhoon2.5-qwen3-4b-q4_k_m.gguf -t 3 -p 0 -n 32 -d 0,2048 -fa 0,1 -r 2`
- llama.cpp `86ea01d` (build บน Pi 5) · ค่าเริ่มต้นของ llama-server คือ `--flash-attn auto` ซึ่งเลือกเปิดบนเครื่องนี้
- อุณหภูมิ 62.6°C ก่อนวัด → 75.7°C หลังวัด · `throttled=0xe0000` (เคยถูกจำกัดความเร็วตั้งแต่บูต · ไม่ได้ถูกจำกัดขณะวัด)
- **ระดับหลักฐาน:** วัดบน Pi 5 จริงด้วย llama-bench แต่ไม่ผ่าน `aipc.bench` (ไม่มี warm-up/5 รอบ/เช็ก throttle ทุกรอบ) →
  ใช้ตัดสินค่าตั้งได้ ต้องวัดซ้ำด้วย `aipc.bench` ก่อนใช้ตัวเลขในเล่ม

## ผลต่อระบบ

- แอปส่งรายการสกิล (~1,000 token) ไปกับทุกข้อความ และแชทที่คุยยาวสะสมประวัติ → เจอผลนี้ทุกครั้ง
- แก้: `scripts/pi/session/aipc-llm-start` ใส่ `-fa "${FLASH_ATTN:-off}"` (เปลี่ยนได้ใน `/etc/aipc/llm.conf`) ·
  `scripts/pi/measure-llm.sh` ใช้ `-fa off` ให้วัดด้วยค่าเดียวกับแอป
- ผลวัดเก่าที่รันแบบ `auto` (การเลือกสกิล 2026-09-29/30: มัธยฐาน 9.2–9.6 วิ/ข้อ) น่าจะเร็วขึ้น · **ยังไม่ได้วัดซ้ำ**
