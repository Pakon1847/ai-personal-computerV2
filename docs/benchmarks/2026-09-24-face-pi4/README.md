# เวลาและ RAM ของระบบใบหน้าบน Pi 4 (การ์ด 0005 ข้อ 8)

- **วันที่:** 2026-09-24 · **commit:** `2899e75` · **คำสั่ง:** `python -m aipc.vision.bench <LFW 120 คนแรก> --limit 200 --rounds 5`
- **ฮาร์ดแวร์:** Raspberry Pi 4 Model B Rev 1.4, 4 GB · trixie aarch64 · Python 3.13.5 · OpenCV 5.0.0 · **(Pi 4) — ไม่ใช่ระดับ 4**
- **สภาพเครื่อง:** อุณหภูมิ 63.8 → 72.1 °C ระหว่างวัด · `throttled = 0` (ไม่ลดความเร็ว) · warm-up 1 รอบไม่นับ
- ค่าดิบ: `bench.json`

## เวลาต่อเฟรม (200 ภาพ × 5 รอบ = 1,000 ครั้งต่อขั้น)

| ขั้น | median (ms) | p95 (ms) |
|---|---|---|
| ตรวจหน้า (YuNet) | 14.6 | 17.3 |
| quality gate | 1.2 | 1.5 |
| PAD (MiniFASNet ×2) | 11.1 | 14.1 |
| align | 0.8 | 0.9 |
| embedding (SFace) | 60.2 | 80.5 |
| **รวมต่อเฟรม** | **88.2** | **113.3** |

โหลดโมเดลทั้งหมด 612 ms (ครั้งเดียวตอนเริ่ม)

## RAM (VmHWM ของโปรเซส)

ก่อนโหลดโมเดล 88.7 MB (Python + OpenCV + numpy + ภาพทดสอบ) → หลังโหลดและรันครบ **217.3 MB** ·
ส่วนที่เพิ่มจากโมเดล ≈ 129 MB → อยู่ในงบของ BRIEF (0.1–0.3 GB)

## อ่านผลยังไง

- การสแกนจริงใช้ 3–5 เฟรม → ส่วนประมวลผลประมาณ 0.26–0.44 วิ บน **Pi 4** · ยังไม่รวมเวลาเปิดกล้อง/รอให้ได้เฟรมคุณภาพผ่าน
  → เทียบเกณฑ์ BRIEF (median ≤ 1.5 วิ ทั้งกระบวนการ) ต้องวัดกับกล้องจริงบน **Pi 5** ถึงจะนับได้
- ขั้นที่หนักสุดคือ SFace (68% ของเวลา) · ถ้าต้องเร็วขึ้น ทำที่นี่ก่อน
- ภาพจากไฟล์ (LFW) ไม่ใช่กล้อง · เวลา detect ขึ้นกับขนาดภาพ (LFW 250×250 · กล้องจริงใหญ่กว่า → detect ช้ากว่านี้)
