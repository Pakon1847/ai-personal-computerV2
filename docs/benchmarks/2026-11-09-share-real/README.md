## คำถาม/ทำไมต้องวัด

เทสต์เดิมใช้เซิร์ฟเวอร์และ KV จำลอง · ต้องรู้ว่าบน Cloudflare จริงส่ง/รับได้ตรงทุกไบต์ และการจำกัดจำนวนครั้งกันการเดาเลขได้จริง

## ชุดทดสอบ

สกิลดี 20 ตัวแรกที่ส่งได้จาก `tests/data/skill_guard_*s1.json` (ชุดวัดของการ์ด 0074 · เรียงตามชื่อไฟล์ · ตัดตัวที่มีคำต้องห้ามหรือเกินขนาด) · ไม่ได้เขียนใหม่เพื่อการวัดนี้ · เลขที่เดา = สุ่มด้วย `secrets`

## สิ่งที่วัด

Cloudflare Worker `server/share-worker/worker.mjs` + KV จริง (แผนฟรี) · ไคลเอนต์ `aipc.skills.share` รันจากโน้ตบุ๊กของ Pakon เครื่องเดียว IP เดียว · ไม่วัดความเร็ว

ที่อยู่เซิร์ฟเวอร์อ่านจากตัวแปร `AIPC_SHARE_URL` ไม่บันทึกในผล

## วิธีนับ

| เรื่อง | ผ่าน | ไม่ผ่าน |
|---|---|---|
| R1 ต่อสกิล | ฝากได้เลข และรับกลับตรงทุกไบต์ | ฝากไม่ได้ · รับไม่ได้ · ไบต์ไม่ตรง |
| H3 เดา | ทุกครั้งที่ใส่เลขจริง (ลำดับที่ 5,000 และ 9,999) ไม่ได้สถานะ 200 และทั้งรอบไม่มีสถานะ 200 | มีสถานะ 200 แม้ครั้งเดียว |
| H3 หมดอายุ | เกิน 24 ชั่วโมงแล้วเลขเดิมตอบไม่พบ | ยังได้ไฟล์ |

รายงานตามจริงเพิ่ม: จำนวนแต่ละสถานะ HTTP · ลำดับแรกที่ถูกบล็อก · จำนวนครั้งที่ไม่ถูกบล็อก (KV อัปเดตไม่พร้อมกันทุกจุด จึงอาจเกิน 10 ได้) · ถ้าเดาไม่ครบ 10,000 เพราะหมดเวลา ให้เขียนว่าไม่ครบ

ก่อนรอบจริงลองเครื่องมือ 1 ครั้งด้วยไฟล์ทดลอง (`probe`) ไม่นับเป็นผล · รอบจริงรันครั้งเดียว

## เกณฑ์ (ลอกจากการ์ด)

- **R1** สกิลดี 20 ตัว ส่งด้วยเลขแล้วรับกลับตรงทุกไบต์ 20/20
- **H3** เดารหัส 10,000 ครั้งจากเครื่องเดียว → ถูกบล็อกก่อนเจอ · รหัสเก่ากว่า 24 ชม. ใช้ไม่ได้

## ทำซ้ำ

```bash
AIPC_SHARE_URL=<ที่อยู่> PYTHONPATH=src python -m aipc.spikes.share_real probe
AIPC_SHARE_URL=<ที่อยู่> PYTHONPATH=src python -m aipc.spikes.share_real run
AIPC_SHARE_URL=<ที่อยู่> PYTHONPATH=src python -m aipc.spikes.share_real expiry   # หลัง 24 ชั่วโมง
```

### จุดที่ต้องบอกตามจริง

1. **การเดาผ่านไปถึงเซิร์ฟเวอร์ 29 ครั้ง ไม่ใช่ 10 ครั้งตามที่ตั้งไว้ (2.9 เท่า).** ไม่ผิดเกณฑ์ที่ประกาศไว้ และประกาศไว้ล่วงหน้าแล้วว่าอาจเกิน แต่ขีดจำกัดจริงเมื่อยิงพร้อมกันหลวมกว่าที่ออกแบบ · สาเหตุที่น่าจะเป็นคือ KV อัปเดตไม่พร้อมกันทุกจุดบวกกับยิง 4 thread พร้อมกัน แต่ **รอบนี้ไม่ได้ทดลองแยกสาเหตุ จึงยังไม่พิสูจน์** · ไม่ได้วัดกรณียิงทีละครั้ง
2. **ชนะการเดา 0 จาก 10,000 ไม่ได้แปลว่าเดาไม่ได้เลย.** สิ่งที่รอบนี้พิสูจน์คือ "เมื่อถูกบล็อกแล้ว แม้ใส่เลขที่ถูกก็ไม่ได้ไฟล์" · ถ้าเลขที่ถูกอยู่ใน 29 ครั้งแรก เซิร์ฟเวอร์จะตอบไฟล์ตามปกติ
3. **ทดสอบจาก IP เดียว.** การจำกัดนับต่อ IP จึงไม่ได้วัดกรณีผู้โจมตีใช้หลาย IP
4. **ที่อยู่เซิร์ฟเวอร์เปลี่ยนกลางรอบ.** หลังฝากตัวที่ 1–9 และจบ H3 แล้ว Pakon เปลี่ยน subdomain ของบัญชี (เอาชื่อบัญชีออกจากที่อยู่สาธารณะ) ที่ราว 12:47 UTC · ตัววัดเดิมถูกหยุดก่อนจะบันทึกความผิดพลาดเทียม · เพิ่มโหมด `resume` (`3e3ba61`) แล้วทำต่อจากตัวที่ 10 ที่ที่อยู่ใหม่ · Worker และ KV เป็นชุดเดิม · ตัวที่ 1–9 จึงฝากผ่านที่อยู่เก่าแต่รับกลับผ่านที่อยู่ใหม่ · ไม่ได้รันชุดทดสอบซ้ำ
5. **ก่อนรอบจริงเครื่องมือลองไม่ผ่านก่อน.** `probe` แรกได้ `403 error code: 1010` เพราะ Cloudflare ปฏิเสธชื่อเริ่มต้นของ Python-urllib ซึ่งเซิร์ฟเวอร์จำลองจับไม่ได้ · แก้ที่ `04d0257` (เทสต์เห็น fail ก่อน) แล้ว `probe` ผ่าน จึงเริ่มรอบจริง · นี่คือบั๊กจริงที่พบเพราะวัดกับของจริง
