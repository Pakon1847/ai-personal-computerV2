**อ่านผล**
- **AI ในเครื่อง (Typhoon 4B) เขียนสกิลไม่ได้เลย** แม้ได้ข้อผิดพลาดกลับไปแก้: ส่วนหัวไม่ปิด `---`, ใส่ `worker: llm` ให้สกิลสั่งเครื่อง,
  ใช้ขั้นตอนนอกรายการ ("ปิดเสียงเครื่อง", "อ่านข้อความที่ผู้ใช้พิมพ์มา"), เรียกเว็บเป็นแอป, ไฟล์ยาวเกิน 8,000 ไบต์ ·
  คำตอบดิบทุกครั้งอยู่ใน `typhoon25-4b/author.json` → **แนวคิด "Claude เขียน · AI ในเครื่องใช้" มีหลักฐานรองรับ**
- Claude ไม่ผ่านแค่เกณฑ์ชุด 58 ข้อ (เสีย 3 · เกณฑ์ ≤ 2) · 1 ใน 3 ("ช่วยแปลป้ายนี้เป็นไทย…") ก็พลาดในรอบของ Typhoon ที่ไม่ได้เพิ่มสกิลเลย →
  น่าจะเป็นความแกว่งของ AI ตัวเลือก (temperature 0.6) · อีก 2 ข้อจริง: สกิล `formal-thai` แย่งประโยคของ `letter-writer` และ `translate`
  → **ต้องมีขั้นตรวจการแย่งประโยคด้วยตัวเลือกสกิลแบบ AI ก่อนติดตั้ง** (ตอนนี้ `forge.trial` ใช้กฎคำสำคัญ)
- ประโยคที่พลาด 3 ใน 5 ข้อ (s3 "ขอดูแผนที่หน่อย", "เปิดแผนที่ให้ที" · s5 "เข้าโหมดจัดไฟล์") ถูก **ตัวแปลคำสั่งเครื่อง** จับไปก่อน AI เห็น
  (เป็นเรื่องการออกแบบของแอป ไม่ใช่สกิลของ Claude)

## สิ่งที่พบระหว่างวัด (แก้แล้วในโค้ด · ยังไม่ติดตั้งบน Pi)

1. **flash attention ช้าบน Pi 5 เมื่อคำขอยาว** (2.01 เทียบ 3.68 tok/s ที่ 2,048 token) → `-fa off` ([ผล](../2026-09-30-flash-attn-pi5/README.md))
2. **แคชคำขอของ llama-server ค่าเริ่มต้น 8 GB → OOM kill** หลังใช้ราว 2 ชม. (07:09 · anon 6.1 GB) → `-cram 512` ในแอป
3. **KillUserProcesses** ปิดงานยาวที่เริ่มจาก SSH → ใช้ `systemd-run` · **AI ของเซสชันผู้ใช้รันซ้อนกับตัววัด → swap เต็ม** (รอบแรกใช้ไม่ได้)
4. **Pi ร้อน 84–86°C แม้พัดลม 8,400 รอบ/นาที** และถูกลดความเร็ว (`throttled=0xe0008`, 2.15 GHz) → ตรวจ Active Cooler

## รอบที่ทิ้ง (เก็บ log บน Pi · ไม่ใช้ตัดสิน)

- `typhoon25-4b-grammar-aborted`: บังคับรูป JSON + AI ของเซสชันซ้อน (swap เต็ม) · 2 ข้อ ไม่ผ่านทั้งคู่ · 1.5–1.9 tok/s
- `typhoon25-4b-fa-auto-aborted`: ไม่บังคับรูป แต่ flash attention auto · 1 ข้อ ไม่ผ่าน · 1.2–1.9 tok/s
- รอบที่ใช้: ไม่บังคับรูป · `-fa off` · 3 thread · ctx 8192 · temperature 0.6 · อุณหภูมิ 57–86°C (มีช่วงถูกลดความเร็ว → เวลาอาจช้ากว่าเครื่องที่ระบายความร้อนดี)
