# ข้อกำหนดรูปแบบไฟล์สกิล (สำหรับผู้เขียนชุดทดสอบ · คัดจากเอกสารของโปรเจกต์ ไม่ใช่โค้ด)

ระบบ: ผู้ช่วย AI ภาษาไทยบน Raspberry Pi 5 · ผู้ใช้หลายคน (แต่ละคนมีโฟลเดอร์ของตัวเอง) · AI ในเครื่อง (Gemma 4 E2B) + Claude บนคลาวด์เมื่อผู้ใช้เปิด · สกิลของผู้ใช้มาได้ 3 ทาง: Claude สร้างให้แล้วติดตั้งอัตโนมัติ · นำเข้าจากไฟล์ .md · (อนาคต) แชร์จากเพื่อน

## 1. ส่วนประกอบและรูปแบบไฟล์ (จาก docs/SKILLS.md)

## Skill หนึ่งตัวประกอบด้วยอะไร

| ส่วน | ตัวอย่าง (สกิลแปล) | ทำไมต้องมี |
|---|---|---|
| ชื่อ + คำอธิบายสั้น | "แปลไทย ↔ อังกฤษ" | ตัวเลือก Skill ใช้คำอธิบายนี้ตัดสินว่าจะใช้สกิลไหน |
| ตัวอย่างคำขอ | "แปลประโยคนี้เป็นอังกฤษ", "translate this" | ใช้คัดสกิลก่อนถาม LLM และใช้เป็นชุดทดสอบ |
| คำสั่งถึงโมเดล (prompt) | สั้นที่สุดที่ทำงานได้ | prompt ยาว = รอนานก่อนคำแรก (BRIEF 5.4) |
| Action ที่อนุญาต | ไม่มี | สกิลเรียกได้เฉพาะ Action ใน allow-list (BRIEF 5.6) |
| สิทธิ์ที่ขอ | ไม่มี | แสดงให้ผู้ใช้เห็นก่อนติดตั้ง |
| ผู้ทำงานหลัก | LLM | บอกว่าใช้ LLM หรือโค้ดทำเอง |

**หลักการเลือก "ผู้ทำงานหลัก":** งานที่ต้องการความถูกต้องแน่นอน (วันเวลา การนับ การสั่งเครื่อง) ให้ **โค้ดทำเอง**
ใช้ LLM เฉพาะงานภาษาที่โค้ดทำไม่ได้ · โมเดลเล็กบน Pi ผิดง่ายและช้า จึงใช้ให้น้อยที่สุดเท่าที่จำเป็น

### ไฟล์สกิล: `.md` 1 ไฟล์ = 1 สกิล

```markdown
---
id: start-work
name: เริ่มวันทำงาน
description: เปิดอีเมลและลดเสียง สำหรับเริ่มงานตอนเช้า
keywords: เริ่มงาน, เริ่มวันทำงาน
examples:
  - เริ่มวันทำงาน
  - เริ่มงานได้เลย
  - เปิดของที่ใช้ทำงาน
permissions: run_actions
---
# เริ่มวันทำงาน          ← ข้อความนอก "## ขั้นตอน" และ "## คำสั่งให้ AI" เป็นคำอธิบายให้คนอ่าน

## ขั้นตอน                ← โค้ดทำตามทีละข้อ ไม่ใช่ให้ AI อ่านแล้วทำ
1. เปิดเว็บ gmail
2. ปรับเสียง 30
```

- **ขั้นตอนที่เขียนได้:** `เปิดเว็บ <ชื่อในรายการ หรือ https://…>` (`https://…` ใช้ได้เฉพาะสกิลในตัว · สกิลของผู้ใช้ = เฉพาะชื่อในรายการ) · `เปิดแอป <ชื่อ>` · `เปิดหน้า <ชื่อ>` · `ปรับเสียง <0–100>` ·
  `เพิ่มเสียง/ลดเสียง <1–100>` · `ปิดเสียง` · `เปิดเสียง` · `บอก: <ข้อความ>` · `ถาม AI: <คำสั่ง>` (ขั้นสุดท้ายเท่านั้น ·
  ส่งข้อความที่ผู้ใช้พิมพ์ไปกับคำสั่งนี้) · บรรทัดที่ไม่รู้จัก = ไฟล์โหลดไม่ได้ทั้งไฟล์ พร้อมบอกเลขบรรทัด
- **สกิลงานภาษา:** `worker: llm` + `needs: llm` + หัวข้อ `## คำสั่งให้ AI` (= prompt · ≤ 1,200 ตัวอักษร)
- **สกิลที่ทำงานด้วยโค้ดของระบบ** (นัดหมาย · สั่งเครื่อง · ถามเครื่อง): มีแค่ส่วนหัว พฤติกรรมอยู่ใน Python
- ขั้นตอนที่สั่งเครื่องต้องขอ `permissions: run_actions` เอง · มีขั้นที่แตะเครื่อง = การ์ดแสดงทุกขั้นแล้วถามยืนยันครั้งเดียว
  (ป้ายความเสี่ยง = ขั้นที่เสี่ยงสูงสุด) · ทำตามลำดับ · ขั้นไหนไม่สำเร็จหยุดตรงนั้นและบอกว่าเหลือกี่ขั้นที่ไม่ได้ทำ
- ตัวตรวจเดิมใช้กับไฟล์ .md ทุกข้อ (คำอธิบาย ≤ 200 ตัวอักษร · สิทธิ์ในรายการ · ห้ามอ้างว่าใช้กับทุกเรื่อง · ตัวอย่าง ≥ 3) ·
  id ซ้ำในโฟลเดอร์เดียวกัน = โหลดไม่ได้
- ขั้นตอนเพิ่มเติม: `บอกนัดวันนี้` · `บอกนัดพรุ่งนี้` · `บอกนัดสัปดาห์นี้` (อ่านนัดในเครื่อง · ต้องขอสิทธิ์ `read_agenda`)
- ชื่อที่ใช้กับ `เปิดเว็บ` (ชื่อในรายการ): youtube · gmail · google · wikipedia · maps · calendar · drive · docs · news · netflix · spotify · viu · iqiyi · wetv · disney · หรือ `https://…` (เฉพาะสกิลในตัว)
- ชื่อที่ใช้กับ `เปิดแอป`: browser · filemanager · terminal
- ชื่อที่ใช้กับ `เปิดหน้า`: workspace (ผู้ช่วย AI) · calendar (ปฏิทิน) · files (ไฟล์ของฉัน) · skills (Skill) · privacy · health (สุขภาพเครื่อง) · settings (ตั้งค่า)
- สิทธิ์ที่ขอได้ (`permissions:` คั่นด้วย , ): run_actions (สั่งงานเครื่องตาม Action ที่อนุญาต) · read_machine_status (อ่านสถานะเครื่อง) · write_notes (เขียนไฟล์ในโฟลเดอร์ ~/โน้ต) · write_reminders (เขียนไฟล์นัดหมาย) · camera_capture (ใช้กล้องเมื่อผู้ใช้กดถ่าย) · read_agenda (อ่านนัดและปฏิทินในเครื่อง) · page_actions (กดคีย์ลัด/ปุ่มในเว็บที่สกิลระบุ)
- ช่องอื่นในส่วนหัวที่มี: `worker:` (code · llm · code+llm · stt+llm · camera+vlm) · `needs:` (llm · stt · vlm · camera) · `keywords:` · `version:` · `author:`

## 2. สกิลประจำเว็บ (จากการ์ด 0046 · 0066 · 0069)

**ไฟล์สกิลประจำเว็บ** (Claude เขียนผ่าน forge · คนอนุมัติ · ข้อมูล ไม่ใช่โค้ด):

```
---
id: youtube-voice
name: สั่ง YouTube ด้วยเสียง
description: สั่งเดินหน้า ถอยหลัง คำบรรยาย และกดไลก์บน YouTube ด้วยเสียง   ← ต้องมี (≤ 200 ตัวอักษร · แสดงในหน้าตรวจ)
site: youtube            ← ใช้เมื่อหน้าที่เปิดอยู่ในเบราว์เซอร์ของผู้ช่วยเป็นเว็บนี้ (เทียบโดเมนในโค้ด)
permissions: page_actions
---
## คำสั่ง
- เดินหน้าสิบวิ | ข้ามไปสิบวิ → กดคีย์ l
- ถอยหลังสิบวิ → กดคีย์ j
- เปิดคำบรรยาย | ปิดคำบรรยาย → กดคีย์ c
- กดไลก์ → คลิก button[aria-label^="like this video"]
- ยกเลิกสมัครสมาชิก → คลิก … · ยืนยันก่อน      ← คำสั่งที่ย้อนไม่ได้/แตะบัญชี ต้องมี "ยืนยันก่อน"
```

**ขั้นตอนใหม่ (allow-list · โค้ดทำ · H6):**
1. `กดคีย์ <คีย์>` — คีย์ลัดของเว็บ (ตัวอักษร ตัวเลข ลูกศร Space Enter Esc + Shift/Ctrl) · ไม่พิมพ์ข้อความลงช่องใด
2. `คลิก <ตัวเลือก CSS>` — กดปุ่มที่ตัวเลือกเขียนตายตัวในไฟล์ · หาไม่เจอ = บอกตามจริง ไม่กดอย่างอื่นแทน (H5 H8) · ไม่อ่านเนื้อหาหน้าเว็บมาเป็นคำสั่ง
3. ทั้งสองแบบทำงานได้เฉพาะเมื่อโดเมนของหน้าที่เปิดอยู่ตรงกับ `site:` ของสกิล
4. `examples:` (ถ้ามี) ต้องเป็นคำพูดของคำสั่งในหัวข้อ `## คำสั่ง` (หรือส่วนหนึ่งของคำพูดนั้น) หรือคำสั่งเว็บที่ระบบรู้จัก · ตัวอย่างที่เป็นงานอื่น = ไม่รับ (การ์ด 0074 รอบ 3)
5. เว็บบัญชี Google (gmail · calendar · drive · docs) ยังไม่รับสกิลประจำเว็บ (การ์ด 0064 หัวข้อ 9)
(ไม่ทำในรอบนี้: พิมพ์ข้อความลงช่อง · ล็อกอิน · ซื้อ/จ่ายเงิน)

**เส้นทางเสียง:** หน้าเว็บที่เปิดอยู่มีสกิลประจำเว็บ → เทียบคำพูดกับคำสั่งของสกิลนั้นก่อน (ตรง = ทำ · ใกล้เคียง = "หมายถึง … ใช่ไหม" · การ์ด 0045) ·
คำสั่งในสกิลเข้าคำใบ้ของตัวถอดเสียง (ทาง 0028)

> **เปลี่ยนตอนสร้าง (2026-10-21 · เจอตอนอ่านไฟล์ที่ Claude เขียน):** คำพูด 22/90 ชนคำสั่งเดิมของระบบ และคีย์ `k`/`Space` เป็นปุ่มสลับ
> ("เล่นต่อ" ตอนเล่นอยู่ = หยุด) → **คำสั่งของระบบ (เบราว์เซอร์ · เครื่อง · แอป · สกิลโค้ด) มาก่อน** · สกิลประจำเว็บตรงเป๊ะมาก่อนทางที่ AI เดา (นัด · งานภาษา) ·
> ใกล้เคียง/ถามเพิ่มเข้าสกิล อยู่ในทาง "ไม่รู้จัก" · เหตุผล: คำเดียวกันทำแบบเดิมทุกเว็บ · ของเดิมไม่เปลี่ยน (W6) · หยุด/เล่นของระบบไม่สลับ
> **เพิ่มคำสั่งด้วยเสียง:** สกิลในเครื่อง (youtube-voice · spotify-voice) ไม่ถูกแก้ · คำสั่งที่เพิ่มไปอยู่ในสกิลของผู้ใช้ประจำเว็บนั้น 1 ไฟล์ (ครั้งแรกสร้าง · ครั้งต่อไปแก้รุ่น)

**ไม่รู้จัก → ถามเพิ่มเข้าสกิล:** อยู่ในเว็บที่มีสกิล + คำพูดไม่ตรงอะไร → การ์ด "เพิ่มคำสั่ง “…” ให้สกิล YouTube ไหม (ส่งให้ Claude)" →
"ใช่" = forge ทางแก้สกิล (id เดิม) → ตัวตรวจ → การ์ดอนุมัติ → ติดตั้ง → ครั้งหน้าใช้ได้ · ยังไม่มีสกิลของเว็บนั้น = "สร้างสกิลสั่ง <เว็บ> ด้วยเสียงไหม"

**สร้างสกิลเว็บอื่น:** "สร้างสกิลสั่ง Netflix ด้วยเสียง" (พิมพ์หรือพูด) → forge สร้างสกิลประจำเว็บแบบเดียวกัน (Claude รู้คีย์ลัดของเว็บดัง ๆ) · เว็บนอกรายการ = https://… ที่เขียนตายตัว

## 3. ความปลอดภัย (คำถามที่กรรมการจะถาม)

- ตัวเลือก CSS / คีย์ ที่ Claude เขียน = ข้อมูลจากภายนอก → ตัวตรวจ (รูปแบบ · ห้าม `javascript:` · ห้ามตัวเลือกช่องรหัสผ่าน/ชำระเงิน) + คนอนุมัติก่อนติดตั้ง (H8 · ADR-011)
- คำสั่งที่มีคำเสี่ยง (ลบ ยกเลิก ซื้อ จ่าย ส่ง โพสต์ สมัคร ออกจากระบบ) ตัวตรวจบังคับ "ยืนยันก่อน" · สิทธิ์ `page_actions` ใหม่ ระบบล็อกแบบการ์ด 0043
- ไม่ให้ AI อ่านหน้าเว็บแล้วตัดสินใจกดเอง (ต่างจาก 0025)


เพิ่มเติม (การ์ด 0066 · 0069):
- `- <คำพูด> → ทำคำสั่ง <ประโยคคำสั่งของระบบ>` = ใช้คำสั่งเว็บ/เครื่องที่ระบบมีอยู่แล้ว 1–3 คำสั่ง (เช่น เปิดเว็บ เปิดแอป ย้อนกลับ ไปหน้าถัดไป โหลดใหม่ ปิดแท็บ เลื่อน เต็มจอ หยุด/เล่นสื่อ ข้ามโฆษณา) · ไม่ส่งข้อความออก ไม่ปิดทุกแท็บ
- `- <คำพูด> → กดปุ่มที่เขียนว่า <ป้ายบนปุ่ม>|<ป้ายอื่น>` = ระบบหาปุ่มที่มองเห็นและมีป้ายตรงนั้นในหน้าจริง

## 4. ข้อกำหนดเรื่อง Skill (จาก BRIEF หัวข้อ 5.8 และ 5.6 ข้อ 6)

#### Skill

**ต้องมี**

1. นิยาม Skill ใน v1 (ไม่มีโค้ดรันเอง — ADR-011): manifest (ชื่อ, เวอร์ชัน, ผู้สร้าง, คำอธิบายที่ AI ใช้เลือก, ตัวอย่างงาน, สิทธิ์ที่ขอ, โมเดลที่ต้องใช้ local/cloud) + คำสั่ง/แม่แบบ + เรียกได้เฉพาะ Action ใน allow-list
2. **AI เลือก Skill เอง** ผู้ใช้ไม่ต้องเลือก โดยเลือกจาก Skill ที่ติดตั้งและเปิดใช้แล้ว **ภายในสิทธิ์ที่บัญชีนั้นอนุญาตไว้แล้ว** · แสดงป้าย "ใช้ Skill: …" พร้อมเหตุผลสั้น ๆ และผู้ใช้เปลี่ยนหรือยกเลิกได้ · ถ้า Skill ต้องการสิทธิ์ใหม่ (ออกเน็ต, ใช้ Cloud, เขียนไฟล์นอกโฟลเดอร์ที่อนุญาต) ต้องขออนุญาตก่อน · ไม่มั่นใจ → ถาม หรือทำโดยไม่ใช้ Skill
3. เนื้อหาของ Skill ที่นำเข้านับเป็นเนื้อหาจากภายนอกตาม 5.6 ข้อ 6 (Skill ที่ไม่มีโค้ดก็ยังแทรกคำสั่งผ่าน prompt ได้) · คำอธิบายที่ใช้เลือกจำกัดความยาว และตรวจการอ้างขอบเขตกว้างเกิน (เช่น "ใช้กับทุกคำขอ") เพื่อไม่ให้ Skill เดียวยึดทุกบทสนทนา
4. AI แนะนำ Skill ใหม่ได้ แต่การนำเข้า/ติดตั้งต้องผ่านหน้าตรวจ: สิทธิ์ที่ขอ (และสิทธิ์ที่เพิ่มจากเวอร์ชันเดิม), ผลตรวจอัตโนมัติ (schema, ขนาด, รูปแบบต้องห้าม), ผู้สร้างและลายเซ็น, ทดลองรันด้วยตัวอย่าง → ผู้ใช้อนุมัติ (โหมดใช้ร่วมกัน: ผู้ดูแลกำหนดได้ว่าต้องให้ผู้ดูแลอนุมัติ) · ไม่ติดตั้งอัตโนมัติ
5. สร้าง ทดลอง (มีชุดตัวอย่าง input และผลที่คาดหวัง) และแชร์ได้ (ส่งออกเป็นแพ็กเกจที่ลงลายเซ็นและไม่มีข้อมูลส่วนตัวติดไป)

**ควรมี**

- ตัวเลือก Skill ที่ประหยัดสำหรับโมเดลเล็ก: กรองด้วย embeddings/คำสำคัญให้เหลือไม่เกิน 3 ตัว แล้วให้ LLM ตัดสิน (โมเดล 1–4B เลือกเครื่องมือพลาดได้บ่อยกว่าโมเดลใหญ่ ต้องวัด)
- เวอร์ชัน ปิดใช้ และย้อนเวอร์ชัน Skill ได้
- Skill ที่มีโค้ด (หลังเฟส 6): รันใน sandbox เช่น bubblewrap + seccomp, ไม่มีเน็ตเป็นค่าเริ่มต้น, จำกัด CPU/RAM, เห็นเฉพาะโฟลเดอร์ที่อนุญาต

**เกณฑ์ผ่าน**

- ชุดประเมินการเลือก Skill ≥ 100 คำขอภาษาไทย (รวมกรณีที่ไม่ควรใช้ Skill) → ความแม่นยำ top-1 ≥ **[ต้องกรอก]**% ต่อโมเดล · ใช้ Skill ที่ต้องการสิทธิ์ที่ยังไม่อนุญาตโดยไม่ถาม = 0 ครั้ง
- Skill ทดสอบที่พยายามอ่าน home ของคนอื่น ออกเน็ต เรียก Action นอก allow-list หรือแทรกคำสั่งผ่านเนื้อหา → ถูกปฏิเสธหรือต้องยืนยัน และบันทึกให้ผู้ใช้เห็น
