# SFace int8 เทียบ fp32 (การ์ด 0005 ข้อ 8) — ทดลอง

- **วันที่:** 2026-09-24 · **commit:** `cbdcffa` (bench) · `aef8703` (LFW int8)
- **คำถาม:** SFace เป็นขั้นที่หนักสุดบน Pi (68% ของเวลา) · รุ่น int8 ของ OpenCV Zoo เล็กกว่า 4 เท่า — เร็วขึ้นไหม เสียความแม่นยำเท่าไร

## ผล

| | fp32 (ใช้อยู่) | int8 |
|---|---|---|
| ขนาดไฟล์ | 37 MB | 9.9 MB |
| LFW มาตรฐาน 10-fold (เครื่องพัฒนา) | **99.35% ± 0.37%** | 99.17% ± 0.53% |
| embedding ต่อเฟรม **(Pi 4)** median / p95 | **57.5 / 58.3 ms** | 184.3 / 185.3 ms |
| รวมต่อเฟรม **(Pi 4)** median | **84.0 ms** | 210.4 ms |
| RAM โปรเซส **(Pi 4)** | 217 MB | 145 MB |

สภาพเครื่อง (Pi 4): 70–74 °C หลังวัด · `throttled = 0` · 200 ภาพ LFW × 5 รอบ + warm-up 1 รอบ · ค่าดิบ `bench-*.json`

## ข้อสรุป

**ใช้ fp32 ต่อ** · int8 บน Pi 4 **ช้ากว่า 3.2 เท่า** แม้ไฟล์เล็กกว่า · ประหยัด RAM ได้ 72 MB แต่ RAM ไม่ใช่ปัญหา (อยู่ในงบ BRIEF อยู่แล้ว)

สาเหตุที่คาดไว้ (**ยังไม่ได้พิสูจน์**): OpenCV DNN (5.0, graph engine ใหม่) ไม่มี kernel int8 ที่ปรับสำหรับ ARM →
ต้องแปลงกลับเป็น float ระหว่างคำนวณ · ต้องวัดซ้ำบน **Pi 5** (Cortex-A76 มีคำสั่ง dot-product ของ int8 ที่ Pi 4 ไม่มี)
ก่อนตัดสินขั้นสุดท้าย

**บทเรียนสำหรับเล่ม:** "โมเดลเล็กกว่า" ไม่ได้แปลว่า "เร็วกว่า" บนเครื่องปลายทาง → ต้องวัดบนเครื่องจริง (H4, H9)
