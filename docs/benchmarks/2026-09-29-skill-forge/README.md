# Claude ("พี่ใหญ่") สร้างสกิลให้ AI ในเครื่อง · 2026-09-29

ความต้องการของอาจารย์ข้อ 2–3 ([ข้อเสนอ 2026-09-29 หัวข้อ 11](../../reviews/2026-09-29-feature-proposal.md)) ·
เครื่องมือ `python -m aipc.skills.forge` (`src/aipc/skills/forge.py`) · แม่แบบคำขอ `src/aipc/skills/forge_prompt.md` ·
**ระดับ 3** (เครื่องพัฒนาวินโดวส์ · Claude บน Cloud · ยังไม่ได้ลองให้ AI ในเครื่องใช้สกิลเหล่านี้บน Pi 5)

## วิธีเรียก (ตามกติกาความปลอดภัยของ forge.py)

`claude -p --output-format json --tools "" --permission-prompts none --no-session-persistence --max-budget-usd 1.00` ·
รันจากโฟลเดอร์ว่าง · คำขอส่งทาง stdin · Claude Code 2.1.284 · บัญชี subscription ที่มีอยู่ (แบบ ก. · Pakon ตัดสิน) ·
โมเดลตามค่าเริ่มต้นของบัญชี = `claude-opus-5-5` · Claude เห็นเฉพาะคำขอ + รายชื่อสกิล/เว็บ/แอป/หน้าที่ระบบมี

## ผล

| สกิล | คำขอ (ย่อ) | รอบ | เวลา | ตัวตรวจ | ควรเรียก | ไม่ควรเรียก | แย่งสกิลเดิม | ค่าใช้จ่ายอ้างอิง |
|---|---|---|---|---|---|---|---|---|
| `summarize-text` สรุปข้อความเป็นข้อ | สรุปข่าว ประกาศ อีเมลยาวเป็นข้อ ๆ | 1 | 34 วิ | ผ่าน | 10/10 | 6/6 | 0 | ~0.088 USD |
| `letter-writer` ร่างจดหมาย/อีเมล | ลาป่วย ขอเลื่อนส่งงาน ขอบคุณ ถึงอาจารย์/หัวหน้า | 1 | 38 วิ | ผ่าน | 10/10 | 6/6 | 0 | ~0.098 USD |

- "ควรเรียก" = ตัวอย่างในไฟล์ (4) + ประโยคที่ Claude เสนอ (6) ผ่านตัวคัดสกิลจริง · "แย่งสกิลเดิม" = ตัวอย่างของสกิลเดิม 4 ตัว
  ที่เปลี่ยนไปเข้าสกิลใหม่หลังเพิ่ม · ค่าใช้จ่ายเป็นราคาอ้างอิงที่ Claude Code รายงาน (บัญชี subscription ไม่ได้จ่ายเพิ่ม)
- ประโยคทดสอบที่ Claude เสนอเอง **ยังไม่ใช่ชุดวัดที่เป็นกลาง** · ต้องวัดซ้ำกับชุดประโยคทดสอบเส้นทางที่เขียนแยก (งานข้อ ④)
- ไฟล์ที่ได้ + รายงานเต็ม: `summarize-text.md`, `summarize-text.report.json`, `letter-writer.md`, `letter-writer.report.json`
- ติดตั้งเป็นสกิลของระบบใน `src/aipc/skills/builtin/` (ผู้ช่วยอ่าน prompt แล้วติดตั้งตามที่ Pakon สั่ง "ทำทุกอย่าง" · ลบได้)
  · เทสต์ทั้งชุดหลังติดตั้ง 442 ผ่าน รวมชุดประโยคนัดหมาย 40 ข้อที่ยังไปถูกสกิล

## ข้อสังเกตที่ Claude ชี้มาเอง (ใช้ในเล่ม)

- ข้อความที่ผู้ใช้วางมาให้สรุปอาจมีคำบอกวันเวลา หรือคำอย่าง "เครื่อง" "พื้นที่" → ตัวคัดสกิลอาจส่งไปสกิลนัดหมาย/ถามเครื่องก่อน ·
  ควรให้ผู้ใช้ขึ้นต้นด้วย "สรุป..." · ตรงกับจุดอ่อนของการเลือกสกิลด้วยคำสำคัญ (งานข้อ ④: ชุดทดสอบ + คะแนนเท่ากันให้ถาม)
- เลี่ยงคำสั้นอย่าง "ลา" ที่ชนคำอื่นแบบ substring และเลี่ยงคำวันเวลา
- ทั้งสอง prompt บังคับรูปแบบคำตอบและห้ามแต่งข้อมูล (จดหมายเว้นช่อง [ชื่อผู้ส่ง] [วันที่] แทนการเดา)

## ยังไม่ได้

คุณภาพคำตอบจริงของ AI ในเครื่องเมื่อใช้ 2 สกิลนี้ (ต้องมีโมเดลบน Pi 5 · ชุดคำถามไทยมีหมวด "เขียน" 5 ข้อ และ "สรุป" 3 ข้อ) ·
เวลาถึงคำแรกเมื่อสรุปข้อความยาว
