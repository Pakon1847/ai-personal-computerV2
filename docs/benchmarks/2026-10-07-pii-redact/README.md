# กรองข้อมูลส่วนตัวก่อนส่ง Claude · ประกาศก่อนวัด 2026-10-07

ที่มา: Pakon เลือกข้อ 2 จากรายการสถาปัตยกรรมใหม่ (2026-10-07) · แนวคิด privacy-conscious delegation:
PAPILLON (Li et al., NAACL 2025 · arXiv:2410.17127) ให้โมเดลในเครื่องเขียนคำถามใหม่ก่อนส่งโมเดลบน Cloud ·
**ของเราใช้กฎ (H6) ไม่ใช้ LLM เขียนใหม่** เพราะ Pi 5 อ่าน prompt ราว 22 token/วิ และกฎตรวจสอบได้ว่าทำอะไร ·
ปัญหาเดิม: ส่งต่อ Claude = ส่งคำถาม + ข้อความล่าสุดไม่เกิน 4 ข้อความแบบดิบ ([การ์ด 0016](../../design/0016-hybrid-cloud.md)) ·
ถ้าผู้ใช้เคยพิมพ์เบอร์โทร/เลขบัตรในแชท ข้อมูลนั้นออกไป Anthropic

## ทำอะไร

ก่อนส่งข้อความใด ๆ ไป Claude (ถาม Claude: คำถาม + บริบท · ขอสร้างสกิล: ข้อความคำขอ) โค้ดหาแล้วแทนที่:

| ชนิด | กฎ | แทนด้วย |
|---|---|---|
| เลขประจำตัวประชาชน | 13 หลัก (ติดกัน หรือคั่นด้วยขีด/เว้นวรรค) **และหลักตรวจสอบถูก** (mod 11) | `[เลขบัตรประชาชน]` |
| เลขบัตรเครดิต/เดบิต | 13–19 หลัก (คั่นด้วยขีด/เว้นวรรคได้) **และ Luhn ถูก** | `[เลขบัตร]` |
| อีเมล | `ชื่อ@โดเมน.สกุล` | `[อีเมล]` |
| เลขบัญชีธนาคาร | 10–12 หลัก (คั่นได้) **เมื่อมีคำว่า บัญชี / account / acc อยู่ก่อนหน้าไม่เกิน 20 ตัวอักษร** | `[เลขบัญชี]` |
| เบอร์โทรไทย | มือถือ 10 หลัก ขึ้นต้น 06/08/09 · บ้าน 9 หลัก ขึ้นต้น 02–07 · หรือ +66/66 แทน 0 · คั่นด้วยขีด/เว้นวรรค/จุดได้ | `[เบอร์โทร]` |

- **ไม่กรอง:** ชื่อคน · ที่อยู่ · วันเกิด (กฎที่แน่นอนทำไม่ได้) → เขียนเป็นข้อจำกัด
- AI ในเครื่องยังเห็นข้อความเดิม (กรองเฉพาะขาออก)
- บันทึกส่งออก (`outbound.json`) เก็บข้อความที่ส่งจริง (กรองแล้ว) + จำนวนที่ซ่อนต่อชนิด · **ไม่เก็บค่าจริง**
- "ทำไมได้คำตอบนี้" แสดงจำนวนที่ซ่อนก่อนส่ง เมื่อมีอย่างน้อย 1

## ชุดทดสอบ (เขียนและ commit ก่อนเขียนตัวกรอง)

`tests/data/pii_heldout.json` เขียนโดย `claude -p` ที่**ไม่เห็นกฎในตารางด้านบน** (ได้แค่ชื่อชนิดข้อมูล และให้เขียนข้อความแชทภาษาไทยแบบที่คนพิมพ์จริง ใช้ค่าสมมติเท่านั้น):

- **ชุด ก:** 40 ข้อความ · มีข้อมูลส่วนตัว 1–3 รายการต่อข้อความ · ระบุค่าที่ฝังไว้ทุกตัว
- **ชุด ข:** 40 ข้อความ · มีตัวเลขที่**ไม่ใช่**ข้อมูลส่วนตัว (ราคา วันที่ เวลา ปี พ.ศ. รหัสสินค้า เลขพัสดุ คะแนน เลขเวอร์ชัน ฯลฯ)
- เลขบัตรประชาชน/บัตรเครดิตที่ Claude เขียน: สคริปต์แก้**หลักสุดท้ายหลักเดียว**ให้ checksum ถูก (รูปแบบการคั่นคงเดิม) ก่อน commit ·
  เพื่อให้เป็นเลขที่ระบบจริงยอมรับ · ไม่มีเลขจริงของใคร
- ค่าใช้จ่ายสร้างชุด: บันทึกในหัวไฟล์

## เกณฑ์ (วัดครั้งเดียว · ไม่ปรับกฎแล้ววัดซ้ำกับชุดนี้ · ไม่ผ่านก็รายงาน)

| # | ตัวชี้วัด | ผ่านเมื่อ |
|---|---|---|
| 1 | ชุด ก: ค่าที่ฝังไว้ยังอยู่ในข้อความหลังกรอง | **0** · รายงานแยกต่อชนิด |
| 2 | ชุด ข: ข้อความที่ถูกแก้ทั้งที่ไม่มีข้อมูลส่วนตัว | ≤ 2 จาก 40 (5%) |
| 3 | ชุดสอบจบ 100 ข้อ (`tests/data/exam_questions.json`): คำถามที่ถูกแก้ | **0** (ชุดสอบไม่มีข้อมูลส่วนตัว · ถูกแก้ = เสียคำถาม) |
| 4 | บันทึกส่งออกไม่มีค่าจริง | เทสต์อัตโนมัติ: ส่งต่อ Claude (ตัวปลอม) ด้วยประวัติที่มีค่าจากชุด ก → ไม่มีค่าใดใน `outbound.json` และใน stdin ที่ส่งให้ `claude` |
| 5 | งานในเครื่องไม่เปลี่ยน | เทสต์อัตโนมัติ: ข้อความที่ส่งให้ AI ในเครื่องและที่เก็บในประวัติแชทเหมือนเดิม |

ข้อ 1–3 เป็นฟังก์ชันล้วน ไม่เรียก Claude (ไม่มีค่าใช้จ่าย) · ข้อ 3 รับประกันว่าคุณภาพชุดสอบไฮบริดไม่เปลี่ยน (ไม่มีคำถามใดถูกแก้)

## ข้อจำกัด (เขียนในเล่ม)

- กันเฉพาะรูปแบบในตาราง · ชื่อ ที่อยู่ วันเกิด และข้อมูลส่วนตัวที่เขียนเป็นคำ ("ศูนย์แปดหนึ่ง...") ยังออกไปได้
- ชุดทดสอบเขียนโดย Claude (ตระกูลเดียวกับผู้ช่วยที่เขียนกฎ) · N เล็ก (40 + 40) → บอกแนวโน้ม ไม่ใช่สถิติ (0/40 ≠ 0% · ขอบบนราว 3/40)
- ถ้าคำถามต้องใช้ค่าจริง (เช่น "เบอร์นี้ของใคร") Claude ตอบไม่ได้ (ตั้งใจ)
