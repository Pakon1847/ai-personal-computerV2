# ข้อเสนอ: ต่อกับมือถือ / iPad (2026-10-14 · รอ Pakon ตัดสิน · ยังไม่เขียนโค้ด)

ที่มา: Pakon 2026-10-14 "อยากเพิ่มเรื่องการเชื่อมต่อกับมือถือหรือ iPad แต่ยังไม่รู้จะทำยังไง" ·
สถานะโปรเจกต์: เลยวันหยุดเพิ่มฟีเจอร์ (9 ต.ค.) แล้ว · ส่งเล่มราว 22 ต.ค. · งานเสียง 0026 ยังเดินอยู่

## ก่อนอื่น: "ต่อกับมือถือ" แปลว่าอะไรได้บ้าง

คำนี้กว้างมาก แต่ละแบบเป็นงานคนละเรื่อง:

| แบบ | ผู้ใช้เห็นอะไร | ต้องทำ | ความเสี่ยงหลัก |
|---|---|---|---|
| 1. ดู/คุมจอ Pi จาก iPad (Raspberry Pi Connect หรือ wayvnc) | เปิดเบราว์เซอร์บน iPad แล้วเห็นจอ Pi ทั้งจอ | ตั้งค่า 0.5–1 วัน · แทบไม่เขียนโค้ด | ภาพจอผ่านเซิร์ฟเวอร์ของ Raspberry Pi ได้ (H3) · คนดูจากระยะไกลไม่อยู่หน้ากล้อง → ปิดบังเมื่อเจ้าของลุกไม่มีผล · ต้องเปิดสิ่งที่เราเพิ่งปิดไป |
| 2. มือถือเป็นไมค์/คีย์บอร์ดไร้สาย (สแกน QR → หน้าเว็บเล็ก ๆ กดพูด/พิมพ์) | มีปุ่มกดพูดบนมือถือ สั่งผู้ช่วยได้ | 3–5 วัน (คู่เครื่อง ใบรับรอง สิทธิ์ต่อผู้ใช้ เทสต์) | **ต้องเปิดพอร์ต** (เคยประกาศว่าไม่เปิด) · เบราว์เซอร์ยอมเปิดไมค์เฉพาะหน้า HTTPS → ต้องทำใบรับรองเอง · token หลุด = คนใน Wi-Fi เดียวกันสั่งเครื่องได้ |
| 3. ส่งการเตือนนัดไปมือถือ (ntfy) | มือถือเด้งเตือนนัด | 1–2 วัน | แบบคลาวด์ = ข้อความนัดออกนอกเครื่อง (H3) · แบบตั้งเองต้องเปิดพอร์ต |
| 4. ส่งไฟล์มือถือ↔Pi (LocalSend · Apache-2.0) | ส่งรูป/ไฟล์ข้ามเครื่อง | 0.5 วัน (แอปแยก ไม่ผูกกับผู้ช่วย) | เปิดพอร์ต · ระบบไม่ได้ต้องใช้ไฟล์จากมือถือ |
| 5. Bluetooth (หูฟัง/มือถือเป็นไมค์) | พูดผ่านหูฟังไร้สาย | ตั้งค่า | เสียงโหมดไมค์ของ Bluetooth คุณภาพต่ำ → ถอดภาษาไทยน่าจะแย่ลง (ยังไม่ได้วัด) |

ข้อเท็จจริงที่ตรวจแล้ว (แหล่ง): ไมค์ในเบราว์เซอร์ต้องเป็นหน้า HTTPS หรือ localhost ([MDN getUserMedia](https://developer.mozilla.org/en-US/docs/Web/API/MediaDevices/getUserMedia)) ·
Pi Connect แชร์จอได้บน Wayland และต้องมีบัญชี Raspberry Pi ID ([เอกสาร](https://www.raspberrypi.com/documentation/services/connect.html)) ·
wayvnc ใช้กับ compositor ตระกูล wlroots ไลเซนส์ ISC ([wayvnc](https://github.com/any1/wayvnc)) · LocalSend ไลเซนส์ Apache-2.0 มีรุ่น Linux arm64 ([repo](https://github.com/localsend/localsend))

**ยังไม่แน่ใจ (ต้องลองกับเครื่องจริง):** Pi Connect/wayvnc ใช้กับ labwc ที่เราตั้งค่าไว้ได้จริงไหม (คาดว่าได้ เพราะ labwc ใช้ wlroots) ·
Safari บน iPad ยอมเปิดไมค์กับใบรับรองที่ทำเองหรือเปล่า · ไลเซนส์ของ ntfy

- ภัยในโมเดลภัยคุกคาม (T1–T9) ยังไม่มีภัยจากเครือข่ายเลย → ถ้าเปิดทางเข้าจากมือถือ ต้องเพิ่มภัยใหม่ + ทดสอบให้ได้ก่อนส่งเล่ม

## คำแนะนำ (ฟันธง)

**ไม่สร้างตอนนี้ · เขียนเป็น "งานในอนาคต" ในบทที่ 5 พร้อมแบบร่างของแบบที่ 2** เพราะ:
1. เลยวันหยุดเพิ่มฟีเจอร์แล้ว และเหลือ 8 วัน งานเสียงยังไม่จบ
2. ทุกแบบที่มีประโยชน์ต้องเปิดพอร์ตหรือส่งข้อมูลออกนอกเครื่อง = กลับคำที่ประกาศไว้ และต้องมีผลทดสอบความปลอดภัยที่ทำไม่ทัน
3. แบบที่ง่ายที่สุด (แบบ 1) ขัด H3 และทำให้การปิดบังจอเมื่อเจ้าของลุกไม่มีความหมาย

แบบร่างสำหรับเล่ม (แบบที่ 2): คู่เครื่องด้วย QR บนจอที่ล็อกอินแล้ว → token ผูกกับบัญชีนั้น หมดอายุเมื่อออกจากระบบ ·
HTTPS ด้วยใบรับรองที่เครื่องออกเอง · รับเฉพาะวงฮอตสปอต · backend ตัดสินสิทธิ์ (H7) · เกณฑ์ทดสอบ: คำขอไม่มี token ถูกปฏิเสธ N/N ·
เวลาจากกดพูดถึงได้ข้อความเทียบไมค์ USB · ยกเลิกคู่เครื่องแล้วสั่งไม่ได้

**ถ้าแค่อยากโชว์จอบน iPad ตอนสาธิต:** เปิด Pi Connect ชั่วคราว เขียนกำกับว่าเป็น "เครื่องมือสาธิต ไม่ใช่ฟีเจอร์" และปิดก่อนทำ image microSD (ต้องถาม Pakon ก่อนเปิด · แตะระบบ)

**ถ้ากรรมการถาม:** "เราเลือกไม่เปิดพอร์ตเครือข่ายเลย เพื่อตัดภัยจากคนใน Wi-Fi เดียวกัน การต่อมือถือจึงเป็นงานในอนาคต
ซึ่งออกแบบไว้แล้วว่าต้องคู่เครื่องด้วย QR + token และใช้ HTTPS เพราะเบราว์เซอร์บังคับ HTTPS ถึงจะเปิดไมค์ได้"
