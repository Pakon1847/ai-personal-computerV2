## 2.1 ระบบงานเดิม

### 2.1.1 ลักษณะงานเดิม

ก่อนพัฒนาโครงงานนี้ การใช้ผู้ช่วย AI บนคอมพิวเตอร์ขนาดเล็กอย่าง Raspberry Pi มีลักษณะเป็นการใช้งานเครื่องคอมพิวเตอร์ทั่วไป กล่าวคือ ผู้ใช้เปิดเครื่องแล้วเข้าสู่เดสก์ท็อปของระบบปฏิบัติการ จากนั้นเปิดเบราว์เซอร์เพื่อใช้บริการผู้ช่วย AI หรือบริการเว็บต่าง ๆ แยกกันทีละโปรแกรม ระบบปฏิบัติการ Raspberry Pi OS รุ่นปัจจุบันใช้ฐาน Debian 13 และใช้ Wayland ร่วมกับ labwc เป็นตัวจัดการหน้าต่าง (compositor) [R2] แต่ไม่ได้มีผู้ช่วย AI ภาษาไทยที่ทำงานในเครื่องมาให้ [ต้องเติม: แหล่งอ้างอิงที่ตรวจแล้ว หากต้องการยืนยันว่า Raspberry Pi OS ไม่มีผู้ช่วย AI ติดมา]

### 2.1.2 วิธีการที่งานเดิมใช้ในปัจจุบัน

1. การถามคำถามหรือให้ AI ช่วยงานภาษา ผู้ใช้ส่งข้อความไปยังบริการ AI บน Cloud ผ่านเบราว์เซอร์หรือแอปพลิเคชัน ข้อความของผู้ใช้จึงถูกประมวลผลนอกเครื่อง [ต้องเติม: แหล่งอ้างอิงที่ตรวจแล้วเกี่ยวกับการประมวลผลของผู้ช่วย AI บน Cloud]
2. การเข้าสู่ระบบด้วยใบหน้าบน Linux มีซอฟต์แวร์อย่าง Howdy ซึ่งผู้พัฒนาเองเตือนว่าไม่ควรใช้เป็นวิธียืนยันตัวตนเพียงวิธีเดียว และระบุว่าการยืนยันด้วยใบหน้าแบบนี้ไม่ได้ปลอดภัยเท่ารหัสผ่าน [R33]
3. เมื่อหลายคนใช้เครื่องเดียวกัน ความปลอดภัยของข้อมูลขึ้นกับการที่ผู้ใช้จำได้ว่าต้องออกจากระบบก่อนลุกจากเครื่อง
4. การสั่งงานเครื่องหรือเว็บไซต์ทำด้วยเมาส์และคีย์บอร์ดเป็นหลัก

### 2.1.3 ข้อจำกัดของระบบเดิม

1. ผู้ใช้ควบคุมไม่ได้และตรวจย้อนหลังได้ยากว่าข้อมูลใดถูกส่งออกนอกเครื่อง
2. แบบจำลองภาษาที่ทำงานในเครื่องได้ต้องมีขนาดเล็ก เนื่องจาก Raspberry Pi 5 ใช้ CPU Arm Cortex-A76 4 แกน [R1] และงาน LLM ประมวลผลบน CPU ซึ่งทำให้เครื่องร้อนจนอาจถูกลดความเร็ว
3. แบบจำลองขนาดเล็กไม่มีข้อมูลสด และบางแบบจำลองไม่ได้ระบุว่ารองรับภาษาไทย เช่น Gemma 4 ระบุว่ารองรับมากกว่า 35 ภาษาแต่ไม่ระบุภาษาไทย [R10]
4. ข้อมูลใบหน้าเป็นข้อมูลชีวภาพซึ่งเป็นข้อมูลส่วนบุคคลที่มีความอ่อนไหวตามพระราชบัญญัติคุ้มครองข้อมูลส่วนบุคคล พ.ศ. 2562 มาตรา 26 [R31] การส่งหรือเก็บข้อมูลนี้นอกเครื่องจึงมีภาระทางกฎหมาย

### 2.1.4 ปัญหาของระบบเดิม

1. ผู้ใช้ที่ลืมออกจากระบบแล้วลุกจากเครื่อง ทำให้ผู้ใช้คนถัดไปเห็นงาน แชท และบัญชีเว็บที่เข้าสู่ระบบค้างไว้ เช่น Gmail หรือ YouTube
2. หากใช้ AI ในเครื่องเพียงอย่างเดียว คำถามที่ต้องใช้ข้อมูลสดจะตอบไม่ได้ ในการทดสอบของโครงงาน แบบจำลองในเครื่องตอบว่าไม่ทราบสำหรับคำถามข้อมูลสด 16 จาก 16 ข้อ
3. หากให้ LLM ทำงานที่ต้องถูกต้องแน่นอน เช่น การบอกที่มาของคำตอบ ผลอาจผิดได้ ในการทดสอบของโครงงาน AI ในเครื่องบอกที่มาของคำตอบที่ได้จาก Claude ผิด แม้จะเติมป้ายบอกที่มาให้แล้ว
4. การเพิ่มความสามารถใหม่ให้ผู้ช่วยต้องอาศัยผู้พัฒนาเขียนโค้ดเพิ่ม ผู้ใช้ทั่วไปเพิ่มเองไม่ได้

## 2.2 ทฤษฎีและงานที่เกี่ยวข้อง

### 2.2.1 Raspberry Pi 5 และ Raspberry Pi OS

Raspberry Pi 5 ใช้หน่วยประมวลผล Broadcom BCM2712 ซึ่งเป็น Arm Cortex-A76 แบบ 64 บิต 4 แกน ความถี่ 2.4 GHz พร้อมส่วนขยายสำหรับการเข้ารหัสลับ (cryptography extensions) ใช้หน่วยความจำ LPDDR4X-4267 ขนาด 1–16 GB และรับไฟ 5V/5A ผ่าน USB-C แบบ Power Delivery [R1]

<!-- ที่มา: docs/thesis/facts-ch2.md หัวข้อ 2.1 [R1] -->

Raspberry Pi OS รุ่น Trixie ใช้ฐาน Debian 13 ประกาศเมื่อวันที่ 2 ตุลาคม 2025 ใช้ Wayland ร่วมกับ labwc เป็น compositor และเปิดการใช้ zram เป็นพื้นที่สลับหน่วยความจำ (swap) เป็นค่าเริ่มต้น [R2] labwc รองรับโปรโตคอล ext-session-lock สำหรับล็อกหน้าจอ และ ext-idle-notify สำหรับแจ้งเมื่อไม่มีการใช้งาน จึงใช้ swaylock ล็อกหน้าจอ และ swayidle สั่งล็อกเมื่อไม่ได้ใช้งานได้ [R3]

<!-- ที่มา: docs/thesis/facts-ch2.md หัวข้อ 2.1 [R2] [R3] -->

เนื่องจากไม่มี GPU ที่ใช้ประมวลผล LLM งานของแบบจำลองภาษาจึงรันบน CPU ผ่าน llama.cpp และเครื่องอาจร้อนจนถูกลดความเร็ว จึงต้องใช้ Active Cooler และอ่านค่า `vcgencmd get_throttled` ทุกครั้งที่วัดผล

### 2.2.2 แบบจำลองภาษาขนาดเล็กบน CPU

GGUF เป็นรูปแบบไฟล์สำหรับเก็บแบบจำลองเพื่อใช้อนุมาน (inference) กับ GGML และโปรแกรมที่สร้างบน GGML โดยไฟล์เดียวมีข้อมูลทุกอย่างที่ต้องใช้รันแบบจำลอง [R21]

การลดความละเอียดของน้ำหนัก (quantization) แบบ k-quants ใน llama.cpp ซึ่ง Kawrakow เสนอและรวมเข้าโครงการเมื่อ 5 มิถุนายน 2023 จัดน้ำหนักแบบ Q4_K เป็น super-block ขนาด 8 บล็อก บล็อกละ 32 ค่า ใช้ scale และ min ขนาด 6 บิต ทำให้เฉลี่ย 4.5 บิตต่อน้ำหนัก และมีแบบผสม (quantization mix) เช่น `_M` ที่ใช้ความละเอียดต่างกันตามชนิดของ tensor [R22] โครงงานนี้ใช้แบบ Q4_K_M กับทุกแบบจำลอง

<!-- ที่มา: docs/thesis/facts-ch2.md หัวข้อ 2.2 [R21] [R22] · ADR-007 -->

llama-server เป็นเครื่องแม่ข่าย HTTP ของ llama.cpp ที่มี API แบบเดียวกับ OpenAI รับการเชื่อมต่อผ่าน Unix socket ได้เมื่อกำหนด `--host` เป็น path ที่ลงท้ายด้วย `.sock` และรองรับการเรียกฟังก์ชัน (function calling) เมื่อเปิด `--jinja` [R16] โครงงานจึงเชื่อมต่อหน้าจอกับ AI ผ่าน Unix socket และใช้การเรียกเครื่องมือให้ AI เลือกสกิล

<!-- ที่มา: docs/thesis/facts-ch2.md หัวข้อ 2.2 [R16] · ADR-008 -->

การทำงานของ LLM แบ่งเป็นขั้นอ่านข้อความนำ (prefill) และขั้นสร้างข้อความ (generation) บน CPU ของ Pi 5 ขั้นอ่านข้อความนำเป็นคอขวด โครงงานจึงใช้ system prompt สั้นและบันทึกแคชของข้อความนำลงดิสก์ เทคนิคเร่งความเร็วอื่นที่พิจารณา ได้แก่ speculative decoding ซึ่งใช้ตัวร่างที่ถูกกว่าเดาคำล่วงหน้าแล้วให้แบบจำลองหลักตรวจ โดยได้ผลลัพธ์เหมือนเดิม [R23] และ FlashAttention ซึ่งเป็นอัลกอริทึม attention ที่ลดการอ่านเขียนหน่วยความจำบน GPU [R24] เมื่อทดลองบน Pi 5 แบบ n-gram speculative ให้ความเร็วเพิ่มเพียง 1.04 เท่า และ FlashAttention ทำให้ขั้นสร้างข้อความช้าลง จึงไม่ใช้ทั้งสองเทคนิค

### 2.2.4 การจดจำใบหน้าและการตรวจใบหน้าปลอม

ระบบจดจำใบหน้าของโครงงานประกอบด้วย 3 ส่วน ได้แก่

1. ตรวจหาใบหน้าด้วย YuNet ซึ่งเป็นตัวตรวจหาใบหน้าแบบไม่ใช้ anchor (anchor-free) สำหรับอุปกรณ์ขนาดเล็ก มีพารามิเตอร์ 75,856 ตัว เล็กกว่าตัวตรวจขนาดเล็กอื่นประมาณ 5 เท่า [R25]
2. เปรียบเทียบใบหน้าด้วย SFace ซึ่งใช้ฟังก์ชันสูญเสีย sigmoid-constrained hypersphere loss เพื่อควบคุมแรงดึงภายในกลุ่มและระหว่างกลุ่มอย่างพอดี ลดการเรียนรู้เกิน (overfitting) [R26] ตัวอย่างของ OpenCV กำหนดว่าค่า cosine ตั้งแต่ 0.363 ขึ้นไปถือเป็นบุคคลเดียวกัน [R27] โครงงานใช้ค่านี้ทั้งในการเข้าสู่ระบบด้วยใบหน้าและการตรวจเจ้าของด้วยกล้อง
3. ตรวจใบหน้าปลอม (Presentation Attack Detection: PAD) ด้วย MiniFASNet จากโครงการ Silent-Face-Anti-Spoofing ซึ่งเป็น MobileFaceNet ที่ลดขนาดลงและใช้สเปกตรัมฟูเรียร์ช่วยในการฝึก [R28]

<!-- ที่มา: docs/thesis/facts-ch2.md หัวข้อ 2.4 [R25] [R26] [R27] [R28] · ค่า 0.363 ใช้ใน src/aipc/ui/presence.py -->

ชุดข้อมูล Labeled Faces in the Wild (LFW) มีภาพ 13,233 ภาพของบุคคล 5,749 คน ถ่ายในสภาพจริงที่ท่าทาง แสง อุปกรณ์ และฉากหลังแตกต่างกัน [R29] และมีโพรโทคอลมาตรฐาน 6,000 คู่แบ่งเป็น 10 ชุด ซึ่งโครงงานใช้ประเมินในบทที่ 5

ตัวชี้วัดของระบบชีวมิติตามมาตรฐาน ISO/IEC 19795-1:2021 ได้แก่ อัตราจับคู่ผิด (FMR) และอัตราไม่จับคู่ผิด (FNMR) สำหรับการเปรียบเทียบแบบ 1:1 และอัตรายอมรับผิด (FAR) กับอัตราปฏิเสธผิด (FRR) ในระดับระบบ [R32] ส่วนจุดที่ FAR เท่ากับ FRR เรียกว่าอัตราผิดพลาดเท่ากัน (EER) การทดสอบการตรวจใบหน้าปลอมกำหนดไว้ใน ISO/IEC 30107-3:2023 ซึ่งไม่ครอบคลุมการป้อนภาพปลอมเข้าทางอุปกรณ์โดยตรง [R30]

### 2.2.5 การยืนยันตัวตนและเซสชันบน Linux

1. PAM (Pluggable Authentication Modules) เป็นระบบยืนยันตัวตนแบบต่อโมดูล โมดูล `pam_exec` ใช้เรียกคำสั่งภายนอกได้ [R34] โครงงานใช้ `pam_exec` เชื่อมการสแกนใบหน้าเข้ากับขั้นตอนเข้าสู่ระบบ
2. greetd เป็นโปรแกรมจัดการการเข้าสู่ระบบที่มีขนาดเล็กและยืดหยุ่น สื่อสารกับหน้าเข้าสู่ระบบ (greeter) ผ่าน IPC แบบ JSON [R8] หน้า Login ของโครงงานทำงานเป็น greeter ของ greetd
3. ค่า `KillUserProcesses=` ของ systemd-logind กำหนดให้ปิดทุกโปรเซสในเซสชันเมื่อผู้ใช้ออกจากระบบ [R9]
4. โปรโตคอล ext-session-lock-v1 กำหนดให้ compositor หยุดแสดงผลและหยุดส่งอินพุตให้โปรแกรมปกติขณะล็อก และหากโปรแกรมล็อกหยุดทำงานระหว่างล็อก compositor ต้องไม่ปลดล็อก [R4] swaylock เป็นโปรแกรมล็อกหน้าจอที่ใช้โปรโตคอลนี้ [R6]
5. โปรโตคอล ext-idle-notify-v1 แจ้งเมื่อไม่มีการใช้งานครบเวลาที่ตั้ง และไม่ถือว่าไม่ได้ใช้งานหากมีตัวกันการพัก (idle inhibitor) เช่น ขณะเล่นวิดีโอ [R5] swayidle เป็นโปรแกรมจัดการการไม่ใช้งานบน Wayland [R7]

### 2.2.6 การรู้จำเสียงพูดและการสังเคราะห์เสียงภาษาไทย

Whisper เป็นแบบจำลองถอดเสียงที่ฝึกด้วยการกำกับแบบอ่อน (weak supervision) ด้วยข้อมูลขนาดใหญ่ [R41] Distil-Whisper ย่อขนาดแบบจำลองด้วยการกลั่นความรู้ (knowledge distillation) [R42] และ Thonburian Whisper เป็น Whisper ที่ปรับจูนและย่อขนาดสำหรับภาษาไทย [R43] ระบบใช้รุ่น distill-small ผ่าน whisper.cpp ส่วนการอ่านออกเสียงใช้ Piper ซึ่งเป็นเครื่องสังเคราะห์เสียงแบบโครงข่ายประสาทเทียมที่เร็วและทำงานในเครื่อง [R44] ร่วมกับเสียง `th_TH-tsync2-medium` ที่ใช้สัญญาอนุญาต CC BY-NC-SA 3.0 ซึ่งห้ามใช้เชิงพาณิชย์

### 2.2.7 ระบบไฮบริดกับ Claude Code และบริการภายนอก

คำสั่ง `claude -p` เป็นโหมดไม่โต้ตอบของ Claude Code ซึ่งอ่านข้อความนำ ทำงานจนจบ พิมพ์ผล แล้วออกจากโปรแกรม เมื่อใช้ `--output-format json` จะได้ค่าใช้จ่ายโดยประมาณ (`total_cost_usd`) และตัวเลือก `--bare` ข้ามการตั้งค่าและความจำของโปรแกรม แต่ไม่รองรับการเข้าสู่ระบบแบบสมาชิก [R39] โครงงานจึงไม่ใช้ `--bare` และรันคำสั่งจากโฟลเดอร์ว่างแทน ส่วนข้อมูลอากาศใช้ Open-Meteo ซึ่งใช้สัญญาอนุญาต CC BY 4.0 และกำหนดการใช้แบบฟรีไม่เกิน 10,000 ครั้งต่อวัน [R40]

### 2.2.8 สถิติสำหรับผลที่ไม่พบความผิดพลาด

เมื่อทดลอง n ครั้งแล้วไม่พบเหตุการณ์ที่ไม่ต้องการเลย ขอบบนของช่วงความเชื่อมั่น 95% ของอัตราจริงมีค่าประมาณ 3/n ซึ่งเรียกว่ากฎของสาม (rule of three) [R38] ตัวอย่างเช่น ผลการทดสอบการแทรกคำสั่ง (prompt injection) ที่สำเร็จ 0 จาก 30 ครั้ง ยังเข้ากันได้กับอัตราจริงสูงถึงประมาณ 10% โครงงานจึงไม่สรุปผลลักษณะนี้ว่าความเสี่ยงเป็นศูนย์

### 2.2.9 งานที่เกี่ยวข้อง

1. การส่งต่อระหว่างแบบจำลองราคาถูกกับราคาแพง FrugalGPT ของ Chen, Zaharia และ Zou (2023) ใช้การส่งต่อเป็นลำดับขั้น (cascade) [R17] Hybrid LLM ของ Ding และคณะ (2024) ใช้ตัวเลือกเส้นทาง (router) ตามความยากของคำถาม [R18] และ RouteLLM ของ Ong และคณะ (2024) ฝึกตัวเลือกเส้นทางจากข้อมูลความชอบ [R19] งานเหล่านี้ใช้ตัวเลือกที่ฝึกจากข้อมูล ขณะที่โครงงานนี้ให้แบบจำลองขนาดเล็กตัดสินใจเองผ่านการเรียกเครื่องมือ ร่วมกับกฎว่า "ตอบว่าไม่ทราบ = ส่งต่อ" จึงเปรียบเทียบตัวเลขกันโดยตรงไม่ได้ แต่ใช้แนวคิดเดียวกัน
2. การให้แบบจำลองขนาดใหญ่สร้างเครื่องมือให้แบบจำลองขนาดเล็กใช้ LATM ของ Cai และคณะ (2023) ให้แบบจำลองใหญ่สร้างเครื่องมือแล้วให้แบบจำลองที่ถูกกว่านำไปใช้ [R20] และ Voyager ของ Wang และคณะ (2023) สะสมคลังทักษะที่เพิ่มขึ้นเรื่อย ๆ [R48] ในโครงงานนี้ "เครื่องมือ" ที่ Claude สร้างคือไฟล์สกิล `.md` ที่ไม่มีโค้ด และต้องผ่านประตูตรวจก่อนติดตั้ง
3. การค้นเครื่องมือก่อนส่งให้ LLM RAG-MCP ของ Gan และ Sun (2025) [R46] และ Tool2Vec ของ Moon และคณะ (2024) [R47] คัดเลือกเครื่องมือที่เกี่ยวข้องก่อนส่งให้แบบจำลอง โครงงานนี้ใช้ TF-IDF ของกลุ่มตัวอักษร 2–3 ตัว (เนื่องจากภาษาไทยไม่เว้นวรรคระหว่างคำ) โดยไม่ใช้แบบจำลองเพิ่ม และส่งเฉพาะสกิลของผู้ใช้ 5 สกิลที่เกี่ยวข้องที่สุด
4. การแทรกคำสั่ง (prompt injection) Greshake และคณะ (2023) แสดงการแทรกคำสั่งทางอ้อมผ่านเนื้อหาภายนอก [R35] และ OWASP จัดให้เป็นความเสี่ยงอันดับ LLM01 ใน Top 10 for LLM Applications 2025 [R36] โครงงานป้องกันด้วยหลัก "ข้อมูลไม่ใช่คำสั่ง" (H8) การจำกัดการกระทำไว้ในรายการที่อนุญาต การไม่รันผ่าน shell และการยืนยันก่อนทำ
5. การใช้ LLM เป็นผู้ให้คะแนน Zheng และคณะ (2023) พบว่า LLM ที่ใช้ให้คะแนนมีความลำเอียงตามตำแหน่ง ความยาว และเข้าข้างคำตอบของตนเอง [R37] โครงงานจึงใช้ผลจาก LLM ผู้ให้คะแนนเป็นหลักฐานเสริมเท่านั้น ไม่ใช้แทนผู้ให้คะแนนที่เป็นคน
6. การเข้าสู่ระบบด้วยใบหน้าบน Linux Howdy เป็นซอฟต์แวร์เข้าสู่ระบบด้วยใบหน้าที่เตือนว่าไม่ควรใช้เป็นวิธียืนยันตัวตนเพียงวิธีเดียว [R33] โครงงานนี้เพิ่มการตรวจใบหน้าปลอม ให้รหัสผ่านใช้ได้เสมอ และให้ผู้ใช้เลือกเปิดเองเป็นรายบัญชี

### 2.2.10 เปรียบเทียบงานที่เกี่ยวข้องกับโครงงานนี้

ตารางที่ 2.2 เปรียบเทียบแนวทางของงานที่เกี่ยวข้องกับโครงงานนี้

| แนวทาง | งานที่เกี่ยวข้อง | วิธีของงานที่เกี่ยวข้อง | วิธีของโครงงานนี้ |
|---|---|---|---|
| ส่งต่อระหว่างแบบจำลอง | FrugalGPT [R17] · Hybrid LLM [R18] · RouteLLM [R19] | ตัวเลือกเส้นทางที่ฝึกจากข้อมูล | แบบจำลองในเครื่องตัดสินเองผ่านการเรียกเครื่องมือ ร่วมกับกฎ "ตอบว่าไม่ทราบ = ส่งต่อ" · บันทึกทุกข้อความที่ส่งออก |
| แบบจำลองใหญ่สร้างเครื่องมือ | LATM [R20] · Voyager [R48] | เครื่องมือหรือทักษะในรูปโค้ด | ไฟล์สกิล `.md` ที่ไม่มีโค้ด · ผ่านประตูตรวจหลายชั้นก่อนติดตั้ง |
| ค้นเครื่องมือก่อนส่งให้ LLM | RAG-MCP [R46] · Tool2Vec [R47] | ค้นด้วยเวกเตอร์หรือการค้นแบบเสริมการสร้าง | TF-IDF ของกลุ่มตัวอักษร 2–3 ตัว ไม่ใช้แบบจำลองเพิ่ม · ส่ง 5 สกิล |

| เข้าสู่ระบบด้วยใบหน้าบน Linux | Howdy [R33] | ใบหน้าผ่าน PAM โดยเตือนว่าไม่ควรใช้เพียงวิธีเดียว | ตรวจใบหน้าปลอม (MiniFASNet) · รหัสผ่านใช้ได้เสมอ · เปิดเองรายบัญชี · ไม่เก็บภาพ |
