> ไฟล์นี้ตอบว่า **ทำไม** ระบบออกแบบแบบนี้ และ **อะไรพึ่งอะไร** · ความต้องการอยู่ใน [BRIEF](BRIEF.md) ·
> สิ่งที่มีโค้ดแล้วอยู่ใน [ARCHITECTURE](ARCHITECTURE.md) · สถานะอยู่ใน [STATUS](STATUS.md)
>
> **กติกา:** ก่อนเริ่มฟีเจอร์ใหม่ ต้องมีการ์ดออกแบบใน `docs/design/` ตาม [TEMPLATE](design/TEMPLATE.md)
> ที่ตอบครบว่าใช้หลักการข้อไหน พึ่งชิ้นส่วนไหน และชิ้นส่วนไหนพึ่งมัน แล้ว Pakon อนุมัติก่อนเขียนโค้ด

## 1. หลักการตัดสินใจ (เมื่อขัดกัน ข้อที่เลขน้อยกว่าชนะ)

ข้อ 1–4 มาจาก BRIEF หัวข้อ 1 ตรง ๆ · ข้อ 5–9 คือหลักวิศวกรรมที่ใช้ทำให้ข้อ 1–4 เป็นจริงได้

| # | หลักการ | แปลว่าในทางปฏิบัติ | ตัวอย่างที่ใช้แล้วในโค้ด |
|---|---|---|---|
| **H1** | ความปลอดภัยและความทนทานของข้อมูลมาก่อนความเร็ว | เขียนไฟล์แบบ atomic · ไม่ปิด fsync · ห้ามขั้นตอนเสี่ยงทำเครื่องพัง | `ui/settings.py` บันทึกแบบ tmp → fsync → rename |
| **H2** | ไม่ทำงานของผู้ใช้หายโดยไม่แจ้ง | ทุกอย่างที่หายหรือทำไม่ทันต้องบอกผู้ใช้ | — (ยังไม่มีข้อมูลที่ต้องเก็บยาว) |
| **H3** | ความเป็นส่วนตัวเป็นค่าเริ่มต้น | ไม่เก็บภาพ/เสียงดิบ · ข้อมูลส่วนตัวอยู่ใน home ที่เข้ารหัสของเจ้าของ · ไม่ส่งออกเอง | ไฟล์ของฉันออกนอก home ไม่ได้ (`ui/files.py`) |
| **H4** | Local-first และพอดีกับ Pi 5 8GB | งานพื้นฐานใช้ได้ออฟไลน์ · เลือกทางที่ใช้ RAM/CPU/ดิสก์น้อยกว่า | PySide6-Essentials แทน PySide6 เต็ม |
| **H5** | ความจริงก่อนความสวย | ห้ามแสดงผลจำลองให้ดูเหมือนสำเร็จ · ส่วนที่ยังไม่มีต้องบอกว่ายังไม่มีและอยู่เฟสไหน | หน้า Login บอก "ระบบจดจำใบหน้ายังไม่พร้อม" · คำสั่งบนวินโดวส์ขึ้นว่า "จำลอง" |
| **H6** | งานที่ต้องถูกแน่นอนให้โค้ดทำ งานภาษาให้ LLM ทำ | วันเวลา การนับ การสั่งเครื่อง การตัดสินสิทธิ์ = โค้ด · LLM ใช้เฉพาะสิ่งที่โค้ดทำไม่ได้ | สั่งงานเครื่องไม่ผ่าน LLM (`skills/command.py`) |
| **H7** | ผู้ตัดสินสิทธิ์คือ backend ไม่ใช่หน้าจอ | หน้าจอตรวจเพื่อบอกผู้ใช้เร็ว ๆ เท่านั้น · backend ตรวจซ้ำเสมอ | Plan ที่รอยืนยันเก็บฝั่ง Python หน้าจอส่งกลับได้แค่ token |
| **H8** | ข้อมูลเป็นข้อมูล ไม่ใช่คำสั่ง | เนื้อหาไฟล์ ผลของ LLM และไฟล์สกิล ห้ามกลายเป็นคำสั่ง shell หรือ URL ที่ประกอบเอง | ไฟล์สกิลผ่านตัวตรวจ · Action อยู่ใน allow-list |
| **H9** | ทุกฟีเจอร์วัดผลได้ และตั้งเกณฑ์ก่อนสร้าง | การ์ดออกแบบต้องมีเกณฑ์ผ่านก่อนเขียนโค้ด · ตัวเลขประสิทธิภาพมาจาก Pi 5 เท่านั้น | `aipc.bench` ตัดสินระดับหลักฐานเอง |

**หลักเรื่องลำดับการสร้าง:** สร้างจากชิ้นที่ชิ้นอื่นพึ่ง (ฐาน) ไปหาชิ้นปลายทาง · ชิ้นปลายทางสร้างก่อนฐานได้
เฉพาะเมื่อ (ก) กำหนดรอยต่อ (interface) กับฐานไว้แล้ว และ (ข) บอกผู้ใช้ตรง ๆ ว่าฐานยังไม่มี (H5)

## 2. ชั้นของระบบ และความสัมพันธ์

```text
ชั้น 4  หน้าจอ (QML)                 วาดอย่างเดียว · ไม่ตัดสินอะไร
          │  เรียกผ่านวัตถุ Python (ตอนนี้) → ผ่าน Unix socket ไป Session Agent (เป้าหมาย)
ชั้น 3  Session Agent (ต่อผู้ใช้ 1 คน, รันด้วย UID ของผู้ใช้)
          ├ ตัวคัดสกิล + สกิล          ← ต้องใช้: LLM (ชั้น 2), ข้อมูลส่วนตัว (ชั้น 1)
          ├ ไฟล์ของฉัน แชท โน้ต นัดหมาย ← เก็บใน home ที่เข้ารหัสของผู้ใช้
          └ ตัวสั่ง Action              ← สิทธิ์เท่ากับผู้ใช้คนนั้น ไม่มากกว่า
ชั้น 2  บริการของระบบ (system user ของตัวเอง, ไม่มีเน็ต ยกเว้นที่ประกาศ)
          ├ authd      บัญชี นโยบาย      ← ต้องใช้: PAM, fscrypt (ชั้น 1)
          ├ visiond    เจ้าของกล้อง       ← ส่งออกเป็นเหตุการณ์เท่านั้น (ADR-015 คือข้อยกเว้นเดียว)
          ├ resourced  คิวงานหนัก RAM ร้อน ← ทุกงานหนักต้องผ่านตัวนี้ (H4)
          └ ai-workers llama-server / STT / TTS / VLM ← ไม่มีเน็ต · รีสตาร์ทตอน Logout
ชั้น 1  Raspberry Pi OS: Linux user ต่อบัญชี · home 0700 + fscrypt · systemd · PipeWire · RTC
ชั้น 0  ฮาร์ดแวร์: Pi 5 8GB · 27W · Active Cooler · RTC · กล้อง · ไมค์ · ลำโพง
```

**ตอนนี้มีจริงแค่บางส่วน:** ชั้น 4 (หน้าจอ), ชิ้นส่วนของชั้น 3 (ตัวคัดสกิล สกิล 4–5 ไฟล์ของฉัน) ที่ยัง **รันอยู่ในโปรเซสเดียวกับหน้าจอ**
และเครื่องมือตรวจชั้น 0–1 (`aipc.doctor`) · ชั้น 2 ยังไม่มีเลย

**สิ่งที่ต้องย้ายภายหลัง (บันทึกไว้เพื่อไม่ลืม):**
1. โค้ดใน `ui/backend.py` ที่เป็นตรรกะ (สกิล ไฟล์ การตรวจฟอร์ม) ต้องย้ายไป Session Agent เมื่อมี greetd/PAM
   ตอนนี้ทำงานได้เพราะหน้าจอรันด้วย UID ของผู้ใช้อยู่แล้ว แต่ BRIEF หัวข้อ 7 ต้องการให้หน้าจอกับตรรกะแยกโปรเซส
2. ตรรกะทั้งหมดเขียนเป็น Python ล้วนที่ไม่พึ่ง Qt (`aipc.skills`, `aipc.accounts`, `ui/files.py`) — ตั้งใจไว้เพื่อให้ย้ายได้โดยไม่ต้องเขียนใหม่
   `ui/backend.py` เป็นแค่ตัวแปลงให้ QML เรียกได้

## 3. ข้อมูลแต่ละอย่าง ใครเป็นเจ้าของ เก็บที่ไหน

| ข้อมูล | เจ้าของ | เก็บที่ | หลักการ |
|---|---|---|---|
| ค่าหน้าจอ (ธีม ขนาดตัวอักษร) | ผู้ใช้ | `~/.config/aipc/ui.json` | H1 atomic · H3 อยู่ใน home |
| ไฟล์ของผู้ใช้ | ผู้ใช้ | home ที่เข้ารหัส | H3 · ออกนอก home ไม่ได้ |
| นัดหมาย · โน้ต · ประวัติแชท (ยังไม่มี) | ผู้ใช้ | home ที่เข้ารหัส (ตัดสินที่เก็บใน ADR-004) | H1 H2 H3 |
| ไฟล์สกิลที่มากับเครื่อง | ระบบ | `src/aipc/skills/builtin/` (อ่านอย่างเดียว) | H8 ผ่านตัวตรวจเสมอ |
| ไฟล์สกิลที่ผู้ใช้ติดตั้ง (ยังไม่มี) | ผู้ใช้ | home ที่เข้ารหัส | H8 ถือเป็นเนื้อหาภายนอก |
| รายการ Action และสิทธิ์ | ระบบ | โค้ด (`skills/actions.py`, `skills/manifest.py`) | H7 H8 เพิ่มได้โดยแก้โค้ดเท่านั้น |
| ภาพกล้อง · เสียงไมค์ | — | หน่วยความจำเท่านั้น ไม่เก็บ | H3 |
| ผลวัด | โปรเจกต์ | `docs/benchmarks/` ใน git | H9 |

## 4. แผนผังการพึ่งพาของฟีเจอร์ (อะไรต้องมีก่อน)

```text
LLM บน Pi 5 (ROADMAP 0.7, ADR-007) ─┬─► สกิล 1 แปล
   ← เป็นศูนย์กลางที่มีคนพึ่งมากสุด   ├─► สกิล 2 จดโน้ต ◄── STT ภาษาไทย (0.10, ADR-005) ◄── ไมค์
                                     ├─► สกิล 3 นัดหมาย (เฉพาะประโยคที่ซับซ้อน)
                                     ├─► คุยทั่วไป · ตัวคัดสกิลรอบสุดท้าย · AI ช่วยสร้างสกิล
                                     └─► สกิล 5 เรียบเรียงคำ (ไม่จำเป็น)
ที่เก็บข้อมูลส่วนตัวถาวร (ADR-003/004) ─► สกิล 3 นัดหมาย · สกิล 2 โน้ต · ประวัติแชท · สกิลที่ผู้ใช้ติดตั้ง
เซสชันผู้ใช้จริง (greetd + PAM)  ────► การเตือนนัดหมายระหว่างใช้งาน · Logout ปิดโปรเซส
visiond + ADR-015 + VLM (0.11) ─────► สกิล 6 นี่คืออะไร
ลายเซ็นดิจิทัล + ตัวตรวจสกิล ─────────► แชร์สกิลข้ามเครื่อง
aipc.doctor (มีแล้ว) ────────────────► สกิล 5 · หน้าสุขภาพเครื่อง
allow-list + ตัวแปลคำสั่ง (มีแล้ว) ──► สกิล 4
```

**สิ่งที่แผนผังนี้บอก:**
- **LLM บน Pi 5 คือทางวิกฤต** — ฟีเจอร์ที่เหลือส่วนใหญ่รอตัวนี้ ต้องวัดให้เร็วที่สุดเมื่อได้ใช้ Pi 5
- **ที่เก็บข้อมูลส่วนตัวถาวรคือฐานที่สอง** — สกิลนัดหมาย โน้ต และประวัติแชท ต้องเก็บข้อมูลข้ามการเปิดปิดเครื่อง
  ต้องตัดสินก่อนว่าเก็บที่ไหนและเขียนแบบไหน ไม่งั้นแต่ละสกิลจะเก็บกันคนละแบบ
