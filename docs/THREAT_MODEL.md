# Threat model

> ย้ายมาจาก BRIEF หัวข้อ 3 เมื่อ 2026-09-23 · ไฟล์นี้คือที่เดียวที่นิยามภัย T1–T9

| ID | ภัย | ตัวอย่าง | การป้องกันหลัก |
|---|---|---|---|
| T1 | ผู้ใช้อื่นในเครื่องเดียวกัน | อ่านไฟล์/แชท/API Key/คุกกี้เบราว์เซอร์/คลิปบอร์ด/โปรเซส/`/tmp`/cache ของ AI worker ที่คนก่อนทิ้งไว้ | Linux user แยก, DB role + RLS, Logout ปิดโปรเซสและรีสตาร์ท AI workers, เข้ารหัสรายบัญชี |
| T2 | หลอกใบหน้าต่อหน้ากล้อง | รูปพิมพ์, รูปหรือวิดีโอบนมือถือ/แท็บเล็ต | PAD + นโยบายขั้นบันได + วัดผลแยกรายประเภทการโจมตี |
| T3 | คนอื่นนั่งแทนตอนเจ้าของลุก | เห็นแชท/ไฟล์ที่เปิดค้าง หรือบังกล้องแล้วพิมพ์ต่อ | ตรวจเจ้าของ 6 สถานะ + ปิดบัง/ล็อกด้วย ext-session-lock |
| T4 | ถอด microSD หรือขโมยไดรฟ์ backup | เอาไปอ่านบนเครื่องอื่น | เข้ารหัสรายบัญชี + เนื้อหาใน DB เข้ารหัส + backup เข้ารหัส + เก็บกุญแจแยก |
| T5 | Skill ที่นำเข้าเป็นอันตราย | ส่งข้อมูลออก, ลบไฟล์, แทรกคำสั่งผ่านเนื้อหาของ Skill | manifest สิทธิ์, ตรวจก่อนติดตั้ง, v1 ไม่มีโค้ดรันเอง, เนื้อหา Skill นับเป็นข้อมูลภายนอก |
| T6 | Prompt injection | เอกสาร/เว็บ/คำตอบ AI บอกให้ลบไฟล์ รันคำสั่ง หรือเปิด URL ที่แอบพาข้อมูลออก | allow-list ของ Action, ไม่มี shell, ต้องยืนยันเมื่อมีเนื้อหาจากภายนอก |
| T7 | ข้อมูลรั่วไป Cloud / API Key หลุด | สลับไป Cloud เงียบ ๆ เมื่อ local ช้า, คีย์ไปโผล่ใน log | บริการของเราออกเน็ตได้เฉพาะที่ประกาศ + consent ต่อคำขอ, เข้ารหัสคีย์, redaction |
| T8 | ไฟดับ / พื้นที่เต็ม / อุปกรณ์หลุด | DB เสีย, งานหาย | WAL + fsync เปิด, autosave, atomic write, โควตา, backup ที่ทดสอบ restore แล้ว |
| T9 | ป้อนภาพปลอมเข้าทางกล้อง (injection) | สลับ USB webcam เป็นอุปกรณ์ที่เล่นวิดีโอของเจ้าของ (เช่น capture dongle หรือบอร์ดที่ทำตัวเป็นกล้อง UVC) — ข้าม PAD แบบรูป/จอได้ทั้งหมด และอยู่นอกขอบเขตของ ISO/IEC 30107-3 (ดู CEN/TS 18099) | โหมดใช้ร่วมกันใช้กล้อง CSI ที่ยึดในเคส · จำอุปกรณ์กล้องที่ลงทะเบียน · กล้องถูกถอดหรือเปลี่ยน → ปิดการใช้ใบหน้าจนผู้ดูแลยืนยันด้วยรหัสผ่าน |

**นอกขอบเขต (ต้องบอกผู้ใช้ตรง ๆ):**

- หน้ากาก 3D หรือ deepfake ที่ทำมาเจาะจงคน, ฝาแฝดหรือคนหน้าคล้ายมาก, side-channel
- ผู้โจมตีที่ได้สิทธิ์ root หรือดัดแปลงฮาร์ดแวร์ (เช่น keylogger)
- **ผู้ดูแลที่ตั้งใจดัดแปลงระบบ:** ผู้ดูแลต้องเป็นคนที่ไว้ใจได้ การเข้ารหัสรายบัญชีกันได้เฉพาะการเปิดอ่านข้อมูลที่ล็อกอยู่ ไม่กันผู้ดูแลที่แก้ระบบเพื่อดักรหัสผ่านในการ Login ครั้งถัดไป
- ขโมยทั้งเครื่อง (บอร์ด + การ์ด) ของบัญชีที่เปิด "โหมดสะดวก"

**ความเสี่ยงที่ยอมรับในรุ่นนี้:** สมัครเสรีที่หน้า Login (Pakon 2026-09-29) — ใครเข้าถึงหน้า Login ก็สร้างบัญชีได้ (ไม่มีสิทธิ์ผู้ดูแล) · ใช้บัญชีนั้นเข้า SSH ได้ถ้าเปิด SSH แบบรหัสผ่าน · ไม่จำกัดจำนวน จึงทำพื้นที่เต็มได้ (T8) · รายละเอียดใน [การ์ด 0012 หัวข้อ 10](design/0012-real-signup.md)
· **PIN กู้คืนที่ตั้งเอง** (Pakon 2026-09-29): เดาได้ง่ายกว่ารหัสสุ่ม · ใครรู้ PIN ตั้งรหัสผ่านใหม่ให้บัญชีนั้นได้ · กันด้วยการหน่วงเมื่อผิด (ราว 30 ครั้ง/วัน) · ถ้าได้ไฟล์ hash ไป (T4) เดาออฟไลน์ได้ · [การ์ด 0012 หัวข้อ 11](design/0012-real-signup.md)

**การยืนยันด้วยใบหน้าไม่เทียบเท่ารหัสผ่าน** — แม้แต่ Howdy (face login ของ Linux) ก็เตือนว่าห้ามใช้เป็นวิธีเดียว
