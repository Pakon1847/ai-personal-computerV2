# Threat model

> ย้ายมาจาก BRIEF หัวข้อ 3 เมื่อ 2026-09-23 · ไฟล์นี้คือที่เดียวที่นิยามภัย T1–T9

| ID | ภัย | ตัวอย่าง | การป้องกันหลัก |
|---|---|---|---|
| T1 | ผู้ใช้อื่นในเครื่องเดียวกัน | อ่านไฟล์/แชท/API Key/คุกกี้เบราว์เซอร์/คลิปบอร์ด/โปรเซส/`/tmp`/cache ของ AI worker ที่คนก่อนทิ้งไว้ | Linux user แยก, DB role + RLS, Logout ปิดโปรเซสและรีสตาร์ท AI workers, เข้ารหัสรายบัญชี |
| T2 | หลอกใบหน้าต่อหน้ากล้อง | รูปพิมพ์, รูปหรือวิดีโอบนมือถือ/แท็บเล็ต | PAD + นโยบายขั้นบันได + วัดผลแยกรายประเภทการโจมตี |
| T3 | คนอื่นนั่งแทนตอนเจ้าของลุก | เห็นแชท/ไฟล์ที่เปิดค้าง หรือบังกล้องแล้วพิมพ์ต่อ | ตรวจเจ้าของ 6 สถานะ + ปิดบัง/ล็อกด้วย ext-session-lock |
| T4 | ถอด microSD หรือขโมยไดรฟ์ backup | เอาไปอ่านบนเครื่องอื่น | เข้ารหัสรายบัญชี + เนื้อหาใน DB เข้ารหัส + backup เข้ารหัส + เก็บกุญแจแยก |
| T5 | Skill ที่นำเข้าเป็นอันตราย | ส่งข้อมูลออก, ลบไฟล์, แทรกคำสั่งผ่านเนื้อหาของ Skill | manifest สิทธิ์, ตรวจก่อนติดตั้ง, v1 ไม่มีโค้ดรันเอง, เนื้อหา Skill นับเป็นข้อมูลภายนอก |
| T6 | Prompt injection | เอกสาร/เว็บ/คำตอบ AI บอกให้ลบไฟล์ รันคำสั่ง หรือเปิด URL ที่แอบพาข้อมูลออก | allow-list ของ Action, ไม่มี shell, ต้องยืนยันเมื่อมีเนื้อหาจากภายนอก |
| T7 | ข้อมูลรั่วไป Cloud / API Key หลุด | สลับไป Cloud เงียบ ๆ เมื่อ local ช้า, คีย์ไปโผล่ใน log | บริการของเราออกเน็ตได้เฉพาะที่ประกาศ + consent ต่อคำขอ, เข้ารหัสคีย์, redaction |
| T8 | ไฟดับ / พื้นที่เต็ม / อุปกรณ์หลุด | DB เสีย, งานหาย | WAL + fsync เปิด, autosave, atomic write, โควตา, backup ที่ทดสอบ restore แล้ว |
| T9 | ป้อนภาพปลอมเข้าทางกล้อง (injection) | สลับ USB webcam เป็นอุปกรณ์ที่เล่นวิดีโอของเจ้าของ (เช่น capture dongle หรือบอร์ดที่ทำตัวเป็นกล้อง UVC) — ข้าม PAD แบบรูป/จอได้ทั้งหมด และอยู่นอกขอบเขตของ ISO/IEC 30107-3 (ดู CEN/TS 18099) | โหมดใช้ร่วมกันใช้กล้อง CSI ที่ยึดในเคส · จำอุปกรณ์กล้องที่ลงทะเบียน · กล้องถูกถอดหรือเปลี่ยน → ปิดการใช้ใบหน้าจนผู้ดูแลยืนยันด้วยรหัสผ่าน |

**นอกขอบเขต (ต้องบอกผู้ใช้ตรง ๆ):**

- หน้ากาก 3D หรือ deepfake ที่ทำมาเจาะจงคน, ฝาแฝดหรือคนหน้าคล้ายมาก, side-channel
- ผู้โจมตีที่ได้สิทธิ์ root หรือดัดแปลงฮาร์ดแวร์ (เช่น keylogger)
- **ผู้ดูแลที่ตั้งใจดัดแปลงระบบ:** ผู้ดูแลต้องเป็นคนที่ไว้ใจได้ การเข้ารหัสรายบัญชีกันได้เฉพาะการเปิดอ่านข้อมูลที่ล็อกอยู่ ไม่กันผู้ดูแลที่แก้ระบบเพื่อดักรหัสผ่านในการ Login ครั้งถัดไป
- ขโมยทั้งเครื่อง (บอร์ด + การ์ด) ของบัญชีที่เปิด "โหมดสะดวก"

**ความเสี่ยงที่ยอมรับในรุ่นนี้:** สมัครเสรีที่หน้า Login (Pakon 2026-09-29) — ใครเข้าถึงหน้า Login ก็สร้างบัญชีได้ (ไม่มีสิทธิ์ผู้ดูแล) · ใช้บัญชีนั้นเข้า SSH ได้ถ้าเปิด SSH แบบรหัสผ่าน · ไม่จำกัดจำนวน จึงทำพื้นที่เต็มได้ (T8) · รายละเอียดใน [การ์ด 0012 หัวข้อ 10](design/0012-real-signup.md)
· **PIN กู้คืนที่ตั้งเอง** (Pakon 2026-09-29): เดาได้ง่ายกว่ารหัสสุ่ม · ใครรู้ PIN ตั้งรหัสผ่านใหม่ให้บัญชีนั้นได้ · กันด้วยการหน่วงเมื่อผิด (ราว 30 ครั้ง/วัน) · ถ้าได้ไฟล์ hash ไป (T4) เดาออฟไลน์ได้ · [การ์ด 0012 หัวข้อ 11](design/0012-real-signup.md)

· **ไฮบริดส่งออกอัตโนมัติ (T7 · การ์ด 0016/0017 · Pakon 2026-09-30):** บัญชีที่เข้าสู่ระบบ Claude Code แล้ว ส่งคำถาม + บริบท ≤ 4 ข้อความไป Anthropic โดยไม่ถามทีละครั้ง
(แทน "consent ต่อคำขอ" ในตาราง) · ส่งคำขอสร้างสกิลไป Anthropic · ส่งชื่อเมือง/พิกัดไป Open-Meteo · ไม่ส่งไฟล์ นัด ใบหน้า ชื่อบัญชี ·
ทุกครั้งบันทึกตามตัวอักษรใน `~/.local/share/aipc/outbound.json` (0600) · ปิดได้ด้วยสวิตช์ Claude ในหน้าตั้งค่า (เพิ่ม 2026-10-05 `2ae642b`) · ไม่เข้าสู่ระบบ Claude · หรือ `AIPC_CLOUD=0` ·
การเชื่อมต่ออื่นของตัว Claude Code อยู่นอกการควบคุมของเรา · รายละเอียดและ T6 แบบใหม่: [ร่างข้ออ้างรอบ 4](reviews/2026-10-05-claims-hybrid.md)

· **AI ในเครื่องต่อเน็ตไม่ได้ด้วยกลไกของ OS (2026-10-07):** llama-server สร้างได้แค่ Unix socket (seccomp) และอยู่ใน network namespace ที่มีแค่ loopback →
แชทและเนื้อหาไฟล์ที่ AI อ่าน ส่งออกผ่านโปรเซสนี้ไม่ได้แม้ถูก prompt injection หรือมีช่องโหว่ (T6/T7) · หน้าจอยังต่อเน็ตได้ (3 ทางที่ประกาศ) ·
Piper/whisper/ตัวตรวจด้วยกล้องยังไม่ถูกจำกัด · [ผล](benchmarks/2026-10-07-llm-netsandbox-pi5/README.md)

· **ตัวอ่านออกเสียงส่ง telemetry ไป Microsoft (พบใน T6 แบบใหม่ 2026-10-08 · แก้แล้ว `7f7a179`):** onnxruntime 1.30.0 ที่ Piper ใช้ ต่อ `*.events.data.microsoft.com` เองเมื่อโหลดโมเดล (ตั้งแต่ติดตั้งเสียง 2026-10-01 · ไม่รู้เนื้อหาที่ส่ง) · `disable_telemetry_events()` ไม่ช่วย → ตัวสังเคราะห์รันเป็น user service ที่ต่อเน็ตไม่ได้แบบเดียวกับ AI ในเครื่อง · [ผล](benchmarks/2026-10-08-t6-new-pi5/README.md) · บทเรียน: ไลบรารีที่ไม่ต้องใช้เน็ตก็ต่อออกได้ → ตัวช่วยใดที่ไม่ต้องใช้เน็ตควรถูกห้ามที่ OS ไม่ใช่เชื่อการตั้งค่าของไลบรารี

· **บัญชีเว็บในเบราว์เซอร์ (Pakon เลือก 2026-10-06):** Chromium ไม่ใช้ keyring (`--password-store=basic` · `scripts/pi/install-browser.sh`) เพราะเข้าด้วยใบหน้าแล้ว keyring ไม่ถูกปลดและหน้าต่างถามรหัสไปอยู่ด้านหลัง → คุกกี้/รหัสผ่านเว็บ (Gmail · Facebook · Instagram · Google Calendar/Drive ตามปุ่มแอปที่ใช้บ่อย · การ์ด 0031) ไม่ได้เข้ารหัสด้วยรหัสผ่านเข้าเครื่อง · บัญชีอื่นยังอ่านไม่ได้ (home 0700) แต่**ถอด microSD ไปอ่านได้** (T4) และ**คนที่หลอกกล้องเข้าเครื่องได้จะเข้าบัญชีเว็บที่ login ค้างได้ด้วย** · กู้รหัสด้วย PIN = ล้าง login keyring ของบัญชีนั้น (เข้ารหัสด้วยรหัสเก่า) ·
  **ลดความเสี่ยง (การ์ด 0031):** ปุ่ม "ออกจากบัญชีเว็บทั้งหมด" ในหน้าตั้งค่า ลบโปรไฟล์เบราว์เซอร์ของผู้ช่วย (`~/.local/share/aipc/browser`) ของคนที่กด ·
  ไม่ลบของเบราว์เซอร์ปกติ (ทางสำรองเมื่อเบราว์เซอร์ของผู้ช่วยไม่ว่าง) → ถ้าเคยเข้าสู่ระบบในเบราว์เซอร์นั้น ต้องออกจากระบบเอง · เดโมใช้บัญชีทดสอบ

· **ลิงก์ลับของปฏิทิน Google (การ์ด 0014 · Pakon อนุมัติ 2026-10-15):** ลิงก์ "ที่อยู่ลับในรูปแบบ iCal" = กุญแจ**อ่าน**ปฏิทินของคนนั้น · เก็บใน `~/.config/aipc/gcal-link.json` (0600 · ไม่เข้ารหัส) และสำเนานัดใน `~/.cache/aipc/gcal-events.json` · บัญชีอื่นอ่านไม่ได้ (home 0700) แต่**ถอด microSD ไปอ่านได้** (T4) → เห็นนัดทั้งหมด แต่**แก้/ลบนัดไม่ได้** · ผู้ใช้กด "รีเซ็ต" ใน Google แล้วลิงก์เก่าใช้ไม่ได้ · เครื่องรับเฉพาะลิงก์ของ `calendar.google.com` (กันการใส่ลิงก์ให้เครื่องไปดึงที่อื่น) · ทุกครั้งที่ดึงบันทึกในสมุดบันทึกสิ่งที่ส่งออกโดยไม่มีลิงก์ · ชื่อนัดจาก Google เป็นข้อมูลภายนอก (H8) แสดงเป็นข้อความ ไม่ส่งให้ AI

· **หน้าต่างเชื่อมต่อ Claude บนจอ (การ์ด 0021 หัวข้อ 10 · Pakon เลือก 2026-10-08):** ปุ่ม "เชื่อมต่อที่เครื่องนี้" เปิด `lxterminal` ที่รันคำสั่งตายตัว (ติดตั้ง Claude Code แล้วรัน `claude` ให้เข้าสู่ระบบ) · ระหว่างหน้าต่างเปิด ผู้ใช้พิมพ์คำสั่งผ่านโหมด `!` ของ Claude Code ได้ = **ได้ shell ของบัญชีตัวเอง** · สิทธิ์เท่ากับ SSH ด้วยรหัสผ่านของบัญชีนั้น (เปิดอยู่แล้ว) ไม่ได้สิทธิ์บัญชีอื่นหรือ root (บัญชีที่สมัครไม่อยู่กลุ่ม sudo · T12) · หน้าจอที่ไม่มีเทอร์มินัลไม่เคยเป็นเส้นกั้นความปลอดภัยของระบบ · **ผู้ใช้เปิดเทอร์มินัลได้อยู่แล้ว** ด้วยการพิมพ์ "เปิดเทอร์มินัล" (สกิล 4 สั่งงานเครื่อง · `lxterminal.desktop` อยู่ในรายการแอปของ `aipc/skills/actions.py`) = shell ของบัญชีตัวเอง · สกิลที่ Claude สร้างเปิดเทอร์มินัลไม่ได้ (`AUTO_DENY_APPS` · ช่องทางรันคำสั่ง) · ยืนยันบน Pi 5 2026-10-08 (Pakon สั่งแล้วเข้า Claude Code ในเทอร์มินัลได้)

**การยืนยันด้วยใบหน้าไม่เทียบเท่ารหัสผ่าน** — แม้แต่ Howdy (face login ของ Linux) ก็เตือนว่าห้ามใช้เป็นวิธีเดียว
