# Testing

## เทสต์ของโค้ด (ระดับ 3)

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
.\.venv\Scripts\python.exe -m ruff check .
.\.venv\Scripts\python.exe -m ruff format --check .
```

บน Pi ใช้ `./.venv/bin/python` · ทั้งสามคำสั่งต้องผ่านก่อน commit

**เทสต์ผ่าน = โค้ดทำตามที่เขียนไว้** ไม่ได้แปลว่าฟีเจอร์ทำงานบน Pi 5 (ดูระดับหลักฐานใน [STATUS](STATUS.md))

เทสต์ต้องล็อก *กฎ* ไม่ใช่ล็อกข้อความ เช่น `test_pi4_is_never_level4` ล็อกกฎว่าผลจาก Pi 4 ขึ้นระดับ 4 ไม่ได้
ถ้าวันหนึ่งมีคนแก้โค้ดจนกฎนี้พัง เทสต์จะแดงทันที

## ตรวจฮาร์ดแวร์ก่อนวัดทุกครั้ง

```bash
./.venv/bin/python -m aipc.doctor          # ดูผล (อ่านอย่างเดียว ไม่แก้อะไร)
./.venv/bin/python -m aipc.doctor --save   # เก็บผลเป็นหลักฐานใน docs/benchmarks/
```

ผลแต่ละข้อเป็น ผ่าน / เตือน / ไม่ผ่าน / **ไม่รู้** · "ไม่รู้" = อ่านค่าไม่ได้ ไม่ได้แปลว่าผ่าน
ข้อไฟเลี้ยงถ้าเป็น "ไม่ผ่าน" (เคยไฟตกตั้งแต่บูต) ห้ามวัดประสิทธิภาพจนกว่าจะแก้และรีบูต

## วิธีวัดประสิทธิภาพ (BRIEF หัวข้อ 9)

ใช้เครื่องมือ `aipc.bench` เสมอ อย่าจับเวลาด้วยมือ เพราะเครื่องมือบังคับกติกาให้เอง

```bash
# ดูสภาพเครื่อง (อ่านอย่างเดียว ไม่แก้อะไร)
./.venv/bin/python -m aipc.bench machine

# จับเวลาคำสั่ง: warm-up 1 รอบ + วัด 5 รอบ (ค่าต่ำสุดที่ยอมให้ตั้ง)
./.venv/bin/python -m aipc.bench run --topic llm-load \
    --meta threads=4 --file models/model.gguf -- <โปรแกรม> <พารามิเตอร์> ...
```

ผลจะอยู่ที่ `docs/benchmarks/` สามไฟล์ ชื่อ `YYYY-MM-DD-<เครื่อง>-<topic>`

| ไฟล์ | มีอะไร |
|---|---|
| `.csv` | ค่าดิบทุกรอบ รวม warm-up: เวลา, อุณหภูมิก่อน/หลัง, get_throttled หลังแต่ละรอบ |
| `.json` | ทุกอย่างแบบเครื่องอ่าน: สภาพเครื่อง, commit, sha256 ของไฟล์, สรุป, คำตัดสิน |
| `.md` | สรุปให้คนอ่าน + **คำตัดสินว่าใช้เป็นหลักฐานระดับ 4 ได้ไหม** + ช่องให้เขียนหมายเหตุ |

### เครื่องมือตัดสินให้เองว่าผลชุดนี้ "ใช้ได้" ไหม

ได้ระดับ 4 ต่อเมื่อครบทุกข้อ:

1. วัดบน Pi 5 (อ่านจาก `/proc/device-tree/model`)
2. ไม่มีไฟตก/ร้อนเกินระหว่างวัด (อ่าน `vcgencmd get_throttled` หลังทุกรอบ)
3. อ่านค่า get_throttled ได้จริง — อ่านไม่ได้ ≠ ไม่มีปัญหา
4. ไม่มีไฟล์ค้างแก้ใน git ตอนวัด — ผลต้องผูกกับ commit

### ก่อนวัดต้องทำเอง (เครื่องมือตรวจแทนไม่ได้)

- ต่อ Active Cooler และอะแดปเตอร์ 27W
- ปิดโปรแกรมอื่นที่ไม่เกี่ยว
- เขียนในหมายเหตุของ `.md`: รุ่น SD/SSD, สิ่งผิดปกติที่เห็น

### อ่าน p95 ให้ถูก

p95 คำนวณแบบ nearest-rank (หยิบค่าที่วัดได้จริง ไม่ประมาณ) · **วัด 5 รอบ p95 = ค่าที่แย่ที่สุด**
ถ้าอยากให้ p95 มีความหมายมากกว่า "ค่าแย่สุด" ต้องวัด ≥ 20 รอบ (`--runs 20`)

### ห้ามเขียนทับ

ถ้าวันเดียวกันวัด topic เดิมซ้ำ เครื่องมือจะปฏิเสธ ให้ตั้ง topic ใหม่ เช่น `llm-load-t3` —
ผลเก่าคือหลักฐาน แม้จะเป็นผลที่ไม่ผ่าน
