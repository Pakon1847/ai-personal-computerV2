# Skill ชุดแรก (6 ตัว) — ข้อกำหนด

> เลือกโดย Pakon เมื่อ 2026-09-23 · ไฟล์นี้คือ **ข้อกำหนด** ไม่ใช่สถานะ (สถานะอยู่ใน [STATUS](STATUS.md))
> รูปแบบ Skill ตาม [ADR-011](adr/0011-skill-format.md): Skill เป็น "ข้อมูล" ไม่ใช่โค้ด
> เกณฑ์ผ่านทุกข้อประกาศไว้ **ก่อนวัด** · ถ้าต้องแก้เกณฑ์ ให้เขียนวันที่และเหตุผลไว้ท้ายไฟล์

## Skill หนึ่งตัวประกอบด้วยอะไร

| ส่วน | ตัวอย่าง (สกิลแปล) | ทำไมต้องมี |
|---|---|---|
| ชื่อ + คำอธิบายสั้น | "แปลไทย ↔ อังกฤษ" | ตัวเลือก Skill ใช้คำอธิบายนี้ตัดสินว่าจะใช้สกิลไหน |
| ตัวอย่างคำขอ | "แปลประโยคนี้เป็นอังกฤษ", "translate this" | ใช้คัดสกิลก่อนถาม LLM และใช้เป็นชุดทดสอบ |
| คำสั่งถึงโมเดล (prompt) | สั้นที่สุดที่ทำงานได้ | prompt ยาว = รอนานก่อนคำแรก (BRIEF 5.4) |
| Action ที่อนุญาต | ไม่มี | สกิลเรียกได้เฉพาะ Action ใน allow-list (BRIEF 5.6) |
| สิทธิ์ที่ขอ | ไม่มี | แสดงให้ผู้ใช้เห็นก่อนติดตั้ง |
| ผู้ทำงานหลัก | LLM | บอกว่าใช้ LLM หรือโค้ดทำเอง |

**หลักการเลือก "ผู้ทำงานหลัก":** งานที่ต้องการความถูกต้องแน่นอน (วันเวลา การนับ การสั่งเครื่อง) ให้ **โค้ดทำเอง**
ใช้ LLM เฉพาะงานภาษาที่โค้ดทำไม่ได้ · โมเดลเล็กบน Pi ผิดง่ายและช้า จึงใช้ให้น้อยที่สุดเท่าที่จำเป็น

## การเลือกสกิล (ใช้ร่วมกันทุกตัว)

1. คำสั่งเครื่อง (สกิล 4) ตรวจก่อนด้วยตัวจับคู่แบบกำหนดแน่นอน — ตรงก็ทำเลย ไม่ผ่าน LLM
2. ที่เหลือ: คัดด้วยคำสำคัญ/ตัวอย่างให้เหลือไม่เกิน 3 สกิล แล้วให้ LLM เลือก 1 หรือ "ไม่ใช้สกิล" (BRIEF 5.8)
3. แสดงป้าย "ใช้ Skill: …" พร้อมเหตุผล ผู้ใช้เปลี่ยนหรือยกเลิกได้

**เกณฑ์ผ่าน (รวม):** ชุดคำขอภาษาไทย ≥ 100 ข้อ (รวมข้อที่ไม่ควรใช้สกิลใดเลย ≥ 20 ข้อ) → เลือกถูก top-1 ≥ **[ต้องกรอก]**% ต่อโมเดล
และใช้สกิลที่ต้องการสิทธิ์ที่ยังไม่อนุญาตโดยไม่ถาม = 0 ครั้ง

---

## 1. แปลไทย ↔ อังกฤษ

- **ทำงานด้วย:** LLM ตัวหลัก (ADR-007)
- **ขาเข้า:** ข้อความที่พิมพ์หรือพูด · **ขาออก:** คำแปล ตรวจทิศทางภาษาเอง (ไทย → อังกฤษ, อื่น ๆ → ไทย)
- **Action / สิทธิ์:** ไม่มี
- **ใช้ร่วมกับ:** สกิล 6 (ถ้าโมเดลดูภาพตอบเป็นอังกฤษ ใช้สกิลนี้แปลต่อ)
- **เกณฑ์ผ่าน:** ชุดประโยค 50 คู่ (ไทย→อังกฤษ 25, อังกฤษ→ไทย 25) คนไทย ≥ 2 คนให้คะแนน 1–5 → ค่าเฉลี่ย ≥ **[ต้องกรอก]** · เวลาถึงคำแรก วัดและรายงาน

## 2. จดโน้ตจากเสียง

- **ทำงานด้วย:** กดพูด → STT ภาษาไทย (ADR-005) → LLM สรุปเป็นข้อ ๆ → บันทึกเป็นไฟล์ในโฟลเดอร์ "โน้ต"
- **Action / สิทธิ์:** เขียนไฟล์ในโฟลเดอร์ `~/โน้ต/` เท่านั้น
- **ไม่เก็บเสียงดิบ** (BRIEF 5.5 ข้อ 6): เก็บแค่ข้อความที่ถอดได้และสรุป
- **ความเสี่ยง:** พูดยาวหลายนาที การถอดเสียงบน Pi อาจช้า → จำกัดความยาวต่อครั้งตามผลวัด
- **เกณฑ์ผ่าน:** CER ของการถอดเสียงตามเกณฑ์ BRIEF 5.5 · สรุปครบประเด็นสำคัญ (คนตรวจ 20 บันทึก) ≥ **[ต้องกรอก]**% · เวลาจากหยุดพูดถึงได้สรุป วัดและรายงาน

## 3. จดนัดหมายและเตือนความจำ

- **ทำงานด้วย:** **โค้ดแยก "อะไร / เมื่อไร" และแปลงวันเวลาเอง** (`aipc.skills.when`) สำหรับรูปแบบที่ประกาศว่ารองรับ · ประโยคที่ไม่รองรับ → บอกเหตุผลและขอให้พิมพ์ใหม่ · LLM จะช่วยเฉพาะประโยคยากภายหลัง ([การ์ด 0001](design/0001-reminder.md))
- **เหตุผล:** "พรุ่งนี้บ่ายสอง" / "วันศุกร์หน้า" ต้องแปลงเป็นวันที่จริงอย่างแน่นอน ห้ามให้ LLM คำนวณวันที่เอง
- **Action / สิทธิ์:** เขียนไฟล์นัดหมายของผู้ใช้ · แสดงการเตือนบนจอ
- **ยืนยันก่อนบันทึก:** แสดง "วันศุกร์ 25 ก.ย. 14:00 · ส่งรายงาน — ถูกไหม"
- **พึ่งพา:** นาฬิกาต้องถูกหลังไฟดับ → แบต RTC (BRIEF หัวข้อ 2)
- **เกณฑ์ผ่าน:** ชุดประโยค 50 แบบ (วันที่ตรง ๆ, คำสัมพัทธ์เช่น "พรุ่งนี้", "อีก 3 วัน", เวลาแบบไทยเช่น "บ่ายสอง" "สองทุ่ม") → 40 ข้อที่รองรับถูก **100%** · 10 ข้อยากต้องไม่บันทึกผิดเงียบ ๆ เลย · การเตือนตรงเวลา ±1 นาที (วัดบน Pi)
- **ผลล่าสุด (2026-09-23 วินโดวส์):** รองรับ 40/40 ถูก · ข้อยาก 10/10 ปฏิเสธพร้อมเหตุผล (ตีความได้ 0 ข้อ ผิดเงียบ 0 ข้อ) · ตัวจับเวลาทดสอบด้วยนาฬิกาปลอมเท่านั้น

## 4. สั่งงานเครื่อง (เปิดแอป เปิดเว็บ ปรับเสียง)

- **ทำงานด้วย:** **โค้ดทำเอง** — ตัวจับคู่คำสั่งแบบกำหนดแน่นอน (grammar + คำพ้อง) ไม่ผ่าน LLM (BRIEF 5.6 ข้อ 2)
- **Action:** `open_app`, `open_url` (รายการเว็บคงที่ เช่น YouTube, Gmail), `set_volume` · ทุกตัวอยู่ใน allow-list มีระดับความเสี่ยงกำกับ
- **ความมั่นใจต่ำ** → ถาม "หมายถึง … ใช่ไหม" ไม่ทำเอง · ชื่อแอปอังกฤษต้องมีคำเรียกแบบไทยด้วย ("ยูทูบ")
- **ห้ามเด็ดขาด:** shell, `shell=True`, URL ที่ AI ประกอบเองโดยไม่แสดงให้ผู้ใช้ยืนยัน
- **เกณฑ์ผ่าน (ตาม BRIEF 5.6):** ≥ 30 คำสั่ง × ≥ 5 วิธีพูด × ≥ 5 คน → ตีความถูก ≥ 95%, ทำสิ่งที่ไม่ได้ตั้งใจ ≤ 1%, ระดับสูง = 0 · ทดสอบ injection ผ่าน

## 5. ถามเครื่องว่าเป็นอะไร

- **ทำงานด้วย:** **โค้ดอ่านค่า** จาก `aipc.doctor` (ไฟตก ร้อน RAM พื้นที่ บริการ) → LLM อธิบายเป็นภาษาคนพร้อมวิธีแก้
- **ตัวอย่าง:** "ทำไมเครื่องช้า" → "ตอนนี้ร้อน 82°C และเคยถูกลดความเร็ว — ตรวจพัดลม"
- **กติกา:** LLM อธิบายได้เฉพาะค่าที่อ่านมาจริง · ค่าที่อ่านไม่ได้ต้องพูดว่า "ไม่รู้" ห้ามเดา · วิธีแก้ที่แตะไฟล์บูตให้เป็นคำแนะนำเท่านั้น
- **Action / สิทธิ์:** อ่านสถานะเครื่อง (อ่านอย่างเดียว)
- **เกณฑ์ผ่าน:** จำลองสถานะ 20 แบบ (ไฟตก, ร้อนเกิน, พื้นที่เต็ม, บริการล่ม, ปกติ ฯลฯ) → คำอธิบายตรงกับสาเหตุจริง ≥ **[ต้องกรอก]**% และพูดถึงค่าที่ไม่มีอยู่จริง (hallucination) = 0 ครั้ง

## 6. "นี่คืออะไร" (ถามภาพจากกล้อง)

- **ทำงานด้วย:** ผู้ใช้กดปุ่มถ่าย → ภาพ 1 ภาพ → โมเดลดูภาพได้ (VLM) บรรยาย → ถ้าตอบเป็นอังกฤษ ใช้สกิล 1 แปลเป็นไทย
- **ตัวเลือกโมเดล (ต้อง spike ก่อน — ROADMAP 0.11):**
  - **Gemma 3 4B** — ดูภาพได้ในตัว ถ้าใช้เป็น LLM ตัวหลักด้วย จะไม่ต้องโหลดโมเดลที่สอง (ประหยัด RAM) · ต้องตรวจว่ารุ่นที่ปรับภาษาไทย (Typhoon2.1-Gemma3-4B) ยังดูภาพได้ไหม
  - **SmolVLM** — เล็กมาก เร็วกว่า แต่น่าจะตอบภาษาไทยไม่ได้ → ต้องแปลต่อ
  - ทั้งสองตัวรันผ่าน llama.cpp ได้ (ต้องมีไฟล์ mmproj ของโมเดล)
  - **ยังไม่ได้ตรวจไลเซนส์ทั้งสองตัว** ต้องเปิดอ่านก่อนเลือก (ADR-014)
- **กล้อง (ADR-015):** กล้องเป็นของ visiond (BRIEF 5.2 ข้อ 2) สกิลนี้เปิดกล้องเองไม่ได้ → visiond ต้องมีคำสั่ง "ถ่าย 1 ภาพ" ที่
  ต้องกดปุ่มโดยผู้ใช้เท่านั้น, แสดงไฟกล้อง, ส่งภาพให้ VLM ผ่านหน่วยความจำ, **ไม่บันทึกภาพลงดิสก์**
- **ความเสี่ยงสูงสุดในชุดนี้:** ไม่รู้ว่า VLM บน Pi 5 เร็วพอไหม — ถ้าช้าเกินเกณฑ์ ให้รายงานตามจริงแล้วยกไปบทที่ 5
- **เกณฑ์ผ่าน:** ของใช้ในชีวิตประจำวัน 50 ชิ้น ถ่ายในแสงห้องปกติ → บอกได้ถูก ≥ **[ต้องกรอก, เสนอ 70]**% (คนตัดสิน) · เวลาจากกดถ่ายถึงคำตอบ median ≤ **[ต้องกรอก, เสนอ 20]** วิ บน Pi 5

## ลำดับทำ

1. สกิล 4 และ 5 (โค้ดทำงานหลัก ไม่ต้องรอผลเลือกโมเดล)
2. สกิล 1 และ 3 (ต้องมี LLM ตัวหลักก่อน — ADR-007)
3. สกิล 2 (ต้องมี STT — ADR-005)
4. สกิล 6 (ต้อง spike VLM และออกแบบกล้องร่วมกับ visiond)

ต่อจากนั้นจึงทำ "AI ช่วยสร้างสกิล" และ "แชร์สกิลเป็นไฟล์ลงลายเซ็น" ตามที่คุยไว้
